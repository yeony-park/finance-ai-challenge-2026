# 상품 상세 라우트 통합 (2026-09-05)

## 결정과 근거

- 한우와 부동산 검증 리포트 상세를 각각 `/cattle/products/{id}`, `/real-estate/products/{id}`로 옮겼다.
- 한돈과 미술품이 이미 사용하는 `/{category}/products/{id}` 규칙에 맞춰, 사용자가 카테고리에 따라 다른 URL 구조를 학습하지 않도록 했다.
- 카드·관심 공모·확인 질문은 자산 종류로 상세 경로를 만드는 단일 함수를 사용한다.
- 확인 질문의 `발행사 기록` 링크는 탭으로 전환 가능한 부모 섹션인 `이행 이력`을 가리키며, 신고서 정보나 발행사 기록이 없는 리포트에는 해당 실측 링크를 노출하지 않는다.

## 트레이드오프

- 기존 `/offers/{id}` 상세 경로는 별도 호환 리다이렉트 없이 제거했다. 오래된 북마크는 동작하지 않지만, 폐기한 `/offers` 경로를 라우팅 표면에 남기지 않는다.
- 한우와 부동산은 렌더러를 공유하되 정적 파라미터와 자산 종류 검사는 카테고리 라우트가 각각 소유한다.

## 검증 영향

- 한우 9건과 부동산 1건의 정적 파라미터 합집합이 공개 공모 ID 전체와 같은지 검사한다.
- 타 카테고리 ID와 미등록 ID가 404인지, 두 라우트 모두 `dynamicParams = false`인지 검사한다.
- 카드·관심 공모·확인 질문 URL과 질문 해시가 실제 리포트 탭에 대응하는지 검사한다.
- API 경로, 공모 ID, 검증 데이터 및 정정 감시 저장 키는 변경하지 않았다.

## 알려진 한계

- 관심 공모 화면의 서버 요약 대상은 기존과 같이 한우·부동산 공개 공모 레지스트리다. 한돈·미술품 관심 등록의 통합은 별도 레지스트리 작업이 필요하다.
- 삭제된 `/offers/{id}` 주소를 외부에서 직접 사용한 경우 새 카테고리 경로로 수동 이동해야 한다.
