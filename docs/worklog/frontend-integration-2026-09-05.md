# 프론트 통합과 화면 정리 (2026-09-05)

## 통합 브랜치 반영과 공통 화면

**결정과 근거** — 원격 HEAD를 조회해 기본 브랜치가 `integration`임을 확인했다. `feat/integration-front-develop`에서 `git pull --no-rebase --no-edit origin integration`으로 `a41bc1e`를 병합했다. 충돌 20건은 현재 공통 화면 구조와 원격의 데이터·근거 기능을 함께 유지하도록 해결했다. MunSu2001의 `3403e80` 등으로 들어온 부동산 시나리오 13건, 상품 근거 질문, AI 요약을 연결했다. `Su` 브랜치와 비교한 관련 화면·데이터 변경은 이미 통합 브랜치에 포함돼 있어 별도로 중복 이식하지 않았다.

카테고리 검색·상태 필터를 공통 화면에 배치하고 상세 경로를 `/{category}/products/{id}`로 모았다. 이전 `/offers/{id}`와 `/art?product=`는 새 경로로 이동한다. 한돈 API ID `pig-N`은 기존 상세 ID `round-N`에 연결한다. 부동산은 요약·조건·건물·수익/비용·운영 이력·근거의 6개 탭을 사용하며, 한우·한돈·미술품의 고유 분석 항목을 유지한다. 부동산 관심 등록이 저장 목록에 빠지던 부분도 연결했다.

**트레이드오프** — 모든 상품의 탭 이름까지 같게 만들면 자산별 분석 항목이 흐려진다. 목록·상세·탭 이동의 구조와 디자인 토큰을 공유하고 필요한 분석 탭은 자산별로 유지했다. 공통 문서의 `/offers/common/{category}/{product}`는 ID 충돌을 막는 namespace가 필요하므로 호환 경로로 남겼다.

**검증 영향** — 상세 링크·공개 승인 범위·탭별 데이터 보존·검색 필터·관심 목록 테스트를 갱신했다. 공개 승인을 받지 않은 자료는 기존처럼 노출하지 않는다. 원격의 API·근거 검색·AI 요약 검사도 함께 실행했다.

**알려진 한계** — 부동산 투자조건은 실제 판매 상품이 아닌 검토용 시나리오다. 관심 목록에서도 실제 공시 감시 대상으로 표시하지 않는다. 외부 키를 사용하는 라이브 재검증이나 유료 생성 호출은 이번 화면 검증에 포함하지 않았다.

## 스크롤·스타일·문구와 파일 정리

**결정과 근거** — 홈 히어로의 문서 좌표는 레이아웃이 바뀔 때 다시 재고, 스크롤에서는 저장한 좌표를 사용한다. 진행률이 같으면 계산과 CSS 갱신을 생략하고, 모션 축소 설정을 따른다. 검색 요청 교체·닫기·화면 종료 시 이전 요청과 전환 타이머를 취소한다. 컴포넌트의 숫자 글꼴 크기와 지도 색상은 `tokens.css` 변수로 모았다.

[im-not-ai](https://github.com/epoko77-ai/im-not-ai)의 사실 보존과 자연스러운 한국어 원칙을 참고했다. 미술품의 영문 테스트용 분석 설명은 화면에서만 한국어로 바꾸고 원본 수치·근거·AI 요약 입력은 보존한다. 원문 인용은 고쳐 쓰지 않는다.

삭제한 파일은 사용하지 않는 `HeroShards.tsx`와 전용 CSS, 기존 카탈로그와 중복되던 `components/art/SyntheticArtCatalog.tsx`와 전용 CSS, 삭제 상태였던 구형 `OfferTabs.tsx`·`report-catalog.ts`다. 중복 카탈로그의 AI 요약·근거 질문은 기존 미술품 상세에 옮긴 후 제거했다. API 명세, 디자인 시스템, 사용자 흐름, README, AGENTS 지침과 데이터 매니페스트를 갱신했다. `npm ci`에서 발견한 플랫폼별 선택 의존성 누락은 잠금 파일 재생성으로 해결했다.

**트레이드오프** — 스크롤 연출을 유지하면서 불필요한 측정과 갱신을 줄였다. 성능 향상률이나 FPS 수치는 측정하지 않았으므로 제시하지 않는다. 한국어 표시 변환은 현재 승인된 합성 데이터의 문장 형식에 한정되며, 새 형식의 문장은 원문으로 표시된다.

**검증 영향** — 전체 테스트 179파일, 2,425건 통과·30건 건너뜀. lint 오류 0건, 타입 검사와 프로덕션 빌드 통과. 빌드 사전 검사에서 부동산 파생 자료 13건과 AI 요약 34건의 최신 상태를 확인했다. 브라우저에서 홈 스크롤·구간 이동, 부동산 13건 목록·6개 상세 탭·근거 질문 응답·관심 등록/해제, 미술품 AI 요약과 분석 탭, 한돈 공시·질병 탭을 확인했다. 390px 부동산 화면에서 가로 넘침이 없음을 확인했다.

**알려진 한계** — 원본 자료 JS에서 기존 미사용 변수 경고 3건이 남아 있다. 로컬 검증 결과이며 GitHub의 `Verify` 실행 결과를 대신하지 않는다. 작업 전부터 수정돼 있던 한돈 파일 3개와 `Claude outputs/`는 이번 병합 커밋에서 제외한다.

## 첫 휠 입력이 사진 축소로 이어지도록 보완

**결정과 근거** — 첫 휠을 여러 번 내려야 사진이 작아진다는 피드백을 재현했다. 기존 720px 구간에서 120px를 내려도 사진 너비는 1,265px에서 약 1,210px로만 줄었다. 첫 하향 휠 입력은 520ms 동안 축소 완료 지점까지 이어 주고, 이후 휠은 일반 스크롤로 처리한다.

**트레이드오프** — 도입 구간에서만 하향 휠의 기본 이동을 대신한다. 상향 입력·터치·클릭·키보드 입력은 전환을 중단하며, 검색 화면과 모션 축소 설정에서는 개입하지 않는다.

**검증 영향** — 브라우저에서 20px 입력 한 번으로 스크롤 720px, 사진 너비 528px의 완료 상태에 도달했다. 연속 입력·상향 중단·검색 진입 시 정리·모션 축소·가로 휠과 확대 입력에 대한 회귀 검사 및 기존 홈 검사 18건을 통과했다. lint 오류 0건, 타입 검사·빌드 통과.

**알려진 한계** — 터치와 키보드 스크롤은 기존의 거리 기반 축소를 유지한다. 모션 축소 설정에서는 사진을 축소 완료 상태로 표시한다.

## 부동산 탭·카드 통일과 반복 문구 정리

**결정과 근거** — 부동산만 사용하던 상태 탭과 긴 텍스트 카드를 공통 `CategoryAnalysisStatusTabs`·`CategoryOfferCard`로 교체했다. 전체·청약 예정·진행 중·청약 종료 탭, 대표 이미지·관심 버튼·최소 투자금·주요 금액·상태·상세 링크를 다른 카테고리와 같은 구조로 표시한다. 목록에 반복하던 설명은 제거하고 세부 조건·검토 근거는 상세에서 확인하도록 했다.

**트레이드오프** — 부동산 거래 중·정산 완료는 공통 청약 종료 필터에 포함하고 카드의 상태 문구로 구분한다. 기존 `subscription-open` 필터 주소는 `open`, `listed-trading`·`settled`는 `closed`로 해석한다. 예정 상품은 현재 0건, 진행 중 2건, 청약 종료 11건이다.

**검증 영향** — 전체 화면에서 장식용 소제목 31곳과 카드의 중복 카테고리 표시를 제거했다. 사용하지 않게 된 부동산 전용 탭 파일과 CSS 선택자 58개도 정리했다. 시나리오 고지·수치·기준일·원문 연결은 유지한다. 필터·검색·공통 카드·관심 버튼을 포함한 전체 테스트 2,437건이 통과했고 30건은 기존 조건에 따라 건너뛰었다.

**알려진 한계** — 부동산 이미지는 개별 건물 사진이 아닌 공통 카테고리 대표 이미지다. 자료의 실제 건물 정보와 투자조건의 시나리오 구분은 상세에서 유지한다.

## AI 요약·Copilot 통일

**결정과 근거** — 네 카테고리의 상품 상세는 헤더 아래, 분석 탭 위에서 `ProductAiWorkspace`를 공유한다. AI 요약과 Copilot의 제목·테두리·색상·간격은 `AiPanel`로 통일했다. 부동산 폴더에 있던 공통 질문 구현을 `components/ai-assistant/EvidenceQuery.tsx`로 옮기고 사용하지 않는 기존 스타일을 제거했다.

**연동 범위** — 기존 요약 캐시와 상품별 질문 API를 유지한다. 요약의 빈 상태·로딩·오류를 제공하고, 질문은 `AskEvidence` 타입의 클라이언트 어댑터를 교체해 RAG에 연결할 수 있다. 상품 변경 시 이전 요청을 취소하고 입력·결과를 초기화한다. 팀원용 [연결 문서](../design/ai-ui-integration.md)와 서비스 API 문서를 갱신했다.

**표시 방식** — 요약 근거에는 원문 발췌·기준일·외부 출처를 남기고 내부 경로·ID는 표시하지 않는다. Copilot의 긴 인용은 ‘확인 근거’를 펼쳐 읽는다. 자료가 연결되지 않은 상품은 같은 카드 안에 빈 상태를 표시하며 질문 요청을 보내지 않는다. 부동산의 질문 전용 탭은 상단 Copilot으로 통합했다.

**검증 영향** — 전체 181파일에서 2,461건 통과·30건 건너뜀. 타입 검사·프로덕션 빌드 통과, lint 오류 0건·기존 원본 데이터 경고 3건. AI 요약 34건과 부동산 파생 자료 13건의 최신 상태를 확인했다. 인용 접기 변경 후 관련 38건도 통과했다. 브라우저에서 네 카테고리의 요약·질문 응답, 부동산·미술품 탭 전환 시 답변 유지, 한돈·미술품 390px 화면의 가로 넘침 없음을 확인했다.

**알려진 한계** — 미술품 과거 이력처럼 요약·검색 자료가 연결되지 않은 상품은 빈 상태다. 새 AI 모델이나 서버 생성 정책은 추가하지 않았으며, 실제 연결 작업은 문서에 정의한 기존 계약 또는 어댑터를 사용한다.

## 페이지 간격·정보 박스 점검

- AI 요약의 하단 마진·내부 패딩을 제거했다. 다음 섹션 시작 간격은 `--ds-content-gap`(24–32px)으로 정한다. 미술품 요약과 부동산 본문의 중첩 좌우 여백, 한돈 본문의 중복 상단 마진을 제거했다.
- `ProductFacts`로 네 카테고리 상세의 기본 정보 양식을 공유한다. 미술품 총 공모금액·최소 투자금도 회색 정보 박스의 첫 행에 배치한다. 이전 개별 헤더 정보·금액 CSS는 삭제했다.
- 부동산 목록의 추가 상단 패딩과 미술품 목록의 중복 하단 패딩을 제거했다. 홈의 일반 섹션·About·관심 공모·검증 방법·디자인 비교 페이지의 간격은 `--ds-page-section-gap`(32–48px)을 사용한다.
- 검증 방법 페이지 배경의 `100vw` 확장으로 생기던 가로 스크롤을 없앴다. 상품 이미지의 모바일 전환점(820px)과 비율(16:10), 긴 경로의 한 줄 말줄임을 맞췄다.
- 데스크톱 1280px와 모바일 390px에서 홈, 네 카테고리 목록, About, 검증 방법, 관심 공모, 네 카테고리 대표 상세, 부동산 정산 완료 상세, 미술품 과거 상세·작가·플랫폼, 카드 디자인 비교 등 17개 화면을 확인했다. 두 폭 모두 문서 전체 가로 넘침이 없다.
- 상세는 한우 9호 7개, 한돈 3호 7개, 부동산 01번 5개, 미술품 현재 상품 7개 탭을 전환해 본문과 요약 노출을 확인했다. 최소 공시 한우 1호의 요약 빈 후속 영역도 확인했다. 같은 템플릿을 쓰는 모든 상품을 개별로 열어본 것은 아니다.
- 전체 테스트 181파일·2,462건 통과, 30건 건너뜀. 타입 검사와 최종 프로덕션 빌드 통과. Lint 오류 0건, 기존 원본 데이터 경고 3건. HTTP 계약 변경 없이 디자인 시스템과 AI UI 연결 문서에 배치 기준을 갱신했다.

## 요약·분석 지표의 시각적 위계 보완

- 미술품 요약·분석 설명을 덮던 넓은 회색 배경을 제거했다. 요약 설명과 핵심 근거를 분리하고, 근거 제목(H4)·확인한 내용·보조 설명의 크기와 명도를 구분했다. 헤더와 중복되는 요약의 합성 배지는 제거하되 자료 구분과 본문 내용은 유지했다.
- 최근 경매 표본·낙찰률·목표 보유기간 등은 공통 `ProductMetric`을 사용한다. 제목은 H4(PC 18px, 390px 모바일 17px), 값은 H3, 회색 정보 박스는 R 12px이다. 현재·과거 미술품 상세와 작가·플랫폼 지표에 적용했다. 네 카테고리 헤더의 `ProductFacts`에도 같은 R값을 적용했다.
- 요약 아래 분석 항목은 제목·설명·화살표가 있는 행으로 구성하고 행 전체를 링크로 만들었다. 회색 카드 반복을 없애고 hover·키보드 포커스에 노란 강조를 사용한다. 기존 쿼리 탭 경로와 수치는 유지한다.
- PC와 390px 모바일에서 R값·H4 제목·회색 설명 배경 제거를 확인했다. 모바일 일곱 탭 모두 가로 넘침 0px. 작가 시장성·회수 가능성 행을 눌러 해당 분석 탭으로 이동하는 것을 확인했다. 관련 17개 테스트, 타입 검사, 변경 파일 lint, 프로덕션 빌드 통과. 문구를 반영한 상세 테스트 3개도 다시 통과했다.

## 검증 방법 페이지 디자인 통일

- 페이지 제목을 카테고리 목록과 같은 H2 크기·보통 굵기로 맞췄다. 큰 제목에 합쳐져 있던 질문은 보조 설명으로 분리했다. 섹션 제목은 H3, 항목 제목은 H4·굵게, 본문은 15px 공통 토큰을 사용한다.
- 전체 회색 배경과 반복되는 테두리 카드를 제거했다. 검증 과정은 PC 4열·태블릿 2열·모바일 1열로 배치하고 R 12px을 적용했다. 확인 항목은 노란 구분선으로, 판정 결과는 작은 상태 배지로 구분한다.
- 데이터 출처·작성 원칙·검증 한계는 같은 항목·설명 행을 공유한다. 모바일 가로 스크롤이 필요했던 출처 표를 설명 목록으로 바꿨다. 정정 통계는 `ProductMetric`을 재사용하고 이전 표·통계·헤더 전용 스타일을 제거했다.
- 검증 내용·판정·수치·출처와 8개 섹션의 기존 앵커를 유지했다. 탭 없이 문서를 순서대로 읽는 구조와 공모 목록 이동도 유지한다. API 계약 변경은 없다.
- 1280px PC와 390px 모바일에서 글자 크기·배경·행 배치·가로 넘침 없음을 확인했다. 관련 테스트 5개, 타입 검사, 변경 파일 lint, 프로덕션 빌드가 통과했다.

## 검증 방법 탭 복원과 기능별 커밋

- 후속 요청에 따라 검증 방법을 `공통 · 미술품 · 한우 · 한돈 · 부동산` 다섯 탭으로 구성했다. 공통 설명 8개는 첫 탭에서 순서대로 읽고, 각 섹션과 AI 설명·판정 묶음 사이에 구분선을 넣었다.
- 사용자 첨부 `jeomjeom-methodology.json`의 공통 설명 문구·판정·통계·출처를 현재 내용과 대조해 유지했다. JSON의 외부 폰트·CSS·메뉴·HTML 문서 전체는 가져오지 않았다. 현재 사이트의 공통 토큰과 React 컴포넌트를 사용한다.
- 네 카테고리의 기존 도식·설명·검증 범위를 다시 연결했다. `embedded` 양식은 중복 본문 여백과 대표 사진을 없애고 공통 H3/H4 크기와 섹션 구분선을 적용한다.
- 기존 공통 설명 해시와 카테고리 내부 바로가기는 해당 탭을 연다. 한글 해시 인코딩·잘못된 주소 처리를 검사하고, 방향키·Home·End 이동 및 활성 패널 접근성을 유지했다.
- PC·390px 모바일에서 다섯 탭과 도식·본문 표시를 확인했다. 모바일 모든 탭의 문서 가로 넘침은 0px이며, 공통 설명의 섹션 구분선 7개를 확인했다. 전체 테스트 181파일·2,464건 통과, 30건 건너뜀. 타입 검사·프로덕션 빌드 통과, lint 오류 0건·기존 원본 자료 경고 3건이다.
- 공통 디자인, AI 공통 패널, 홈 스크롤, About 팀원, 부동산 목록, 상품 상세, 축산 설명, 검증 방법으로 커밋을 나눈다. 기존에 수정돼 있던 한돈 질병 출처 변경과 참고 이미지는 작업 트리에 보존한다.
