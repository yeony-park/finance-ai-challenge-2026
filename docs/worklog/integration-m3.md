## M3 개시 — 여정 설계·프로파일 코어·디자인 시안 (2026-08-16)

**결정과 근거** — 오너가 "입문자를 위한 설계 방식과 기술 스택 고민이 생략된 것 아닌가"를
제기했다. 점검 결과 입문자 설계의 재료(IDI 발견·확인 질문 8가지·눈높이 2단·표현 경계)는
이미 있으나 이를 잇는 끝-끝 여정과 단계별 성공 기준이 문서화된 적이 없어,
`docs/planning/입문자-여정.md`(여정 5단계·온보딩 문답 3개·프로파일 명세·스택 평가)를
신설했다. 개인화는 **선언형**으로 정의 — 사용자가 밝힌 것만 반영하고(level·concern·
interests 3필드), UI는 프로파일의 순수 함수로 정렬·강조만 한다(숨김 금지). 근거는 04
라우팅 중립성(AI 주도 선별·우선 노출 금지)과 PRD의 "AI 주도 상품 라우팅" 사각 경고.
코드는 `src/components/site/profile.ts` — watchlist의 useSyncExternalStore 선례를
미러(파싱은 저장값 불신뢰, 차단 시 메모리 폴백). 카테고리 디자인은 한우 착지 재설계
시안(아티팩트, 저장소 외부)으로 선행 검증: 서류철 탭 내비, 층 선언 스탬프 카드, 시그니처
데이터 모듈(거세 경락가 33개월 실데이터 SVG), 사건·정정 타임라인, 확인 질문→리포트 챕터
다리, 카테고리 액센트 4색. 액센트는 dataviz 검증기로 실측 — 초안 2회 FAIL(3색이 회색으로
읽힘, 미술품↔부동산 ΔE 3.9로 색각이상 구분 불가) 후 확정: 한우 #8f3d1f · 돼지 #c2497c ·
미술품 #00879f · 부동산 #4653c9 (명도 대역·채도 하한·정상 분리도·표면 대비 전 항목 PASS,
색각이상 인접쌍 ΔE 7.7 = 텍스트 라벨 동반 시 허용 대역 — 카테고리는 항상 문자 병기이므로
구조적으로 충족).

**트레이드오프** — (a) 온보딩 UI·문안 구현을 이번에 하지 않고 여정 문서·시안에 대한 오너
반응 뒤로 미뤘다: 문안은 필터 감사·오너 리뷰 대상이라 선구현 시 재작업 위험이 컸다. 대신
방향 무관한 코어(프로파일 저장·정렬 함수)만 선구현. (b) 프로파일 필드를 3개로 제한(열람
이력 자동 수집 없음): 개인화 품질의 상한을 낮추는 대신 선언형 원칙·개인정보 최소화를
지켰다. (c) 액센트 채도를 검증기 통과선까지 올렸다: "종이톤에 녹는 저채도" 심미가 일부
양보됐다 — 회색으로 읽히는 색은 기능하지 않는다는 실측이 우선. (d) 시안을 저장소 밖
아티팩트로 뒀다: 팀 히스토리가 깨끗한 대신 시안 자체는 버전 관리 밖 — 확정 값은
tokens.css·design-system.md 반영 시점에 저장소로 들어온다.

**eval 영향** — 여정 5단계의 성공 기준 5문장이 S4 사용성 테스트 태스크의 뼈대로 신설됨.
프로파일 테스트 16건 신규(`profile.test.ts`) — 저장값 불신뢰 파싱, 정렬 순수성, **원소
보존(숨김 금지) 불변식**을 테스트로 고정. 액센트 팔레트는 검증기 실행 기록(2026-08-16,
surface #ffffff, adjacent)으로 회귀 기준 확보. 검증: 신규 스위트 16 통과, tsc·lint 클린
(빌드 무관 — 미참조 리프 모듈).

**알려진 한계** — 프로파일 store의 window 의존부(useSyncExternalStore·storage 이벤트)는
유닛 테스트 밖(watchlist과 동일한 공백). 온보딩 문안·개인화 상태 표시줄·레지스트리 파생
내비는 미구현 — 시안 확정 후 착수. 액센트의 soft/line 파생 톤은 시안에서 수작업 값이라
확정 시 명도 규칙으로 재도출 필요. 시안의 서체는 시스템 폰트 폴백이라 프로덕션 인상과
미세하게 다르다.
