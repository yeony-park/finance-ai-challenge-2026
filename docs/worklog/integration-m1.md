## 통합 브랜치 개설 — viowlet을 구조적 베이스로 (2026-08-15)

**결정과 근거** — `integration` 브랜치를 `origin/viowlet`에서 분기해 개설했다(worktree 분리, upstream 추적 해제 — 푸시 시점은 오너 결정). viowlet을 베이스로 택한 근거: ① viowlet은 main 계열과 git 히스토리가 무관(unrelated histories)해 어느 방향이든 "머지"가 아니라 "이식"이며, 이식 비용이 비대칭 — 검증 엔진(~2.4만 LOC + 데이터 24MB + 테스트 442 단언 + 배포·보안·cron 설정)을 옮기는 것보다 타 브랜치 자산(대부분 데이터 파일 + 페이지 컴포넌트)을 가져오는 쪽이 압도적으로 싸다. ② 제출 요건(URL 무중단)을 이미 충족 중인 유일한 계보다. 4관점 리뷰를 거친 PRD v0.2의 결정을 계승한다.

**트레이드오프** — 대안 (a) main 베이스 재구성: 팀 중립적이지만 엔진 전체 이식 비용과 회귀 리스크가 크다. (b) 제로베이스 신규 앱: 가장 깨끗하지만 검증된 인프라를 전부 재구축해야 한다. viowlet 베이스의 지불 비용: 타 팀원에게 "한 사람의 브랜치가 기준이 됐다"로 읽힐 팀 정치적 부담 — 완화책으로 자산 보존 매핑(`docs/spec/07-asset-map.md` 예정)으로 모든 브랜치 자산의 행선지를 명시하고, 카테고리 소유권은 기존 담당을 유지한다. main의 골격 자산(디자인 시스템 문서·AssetPage 계약 사상)은 명세에 흡수한다.

**eval 영향** — "기존 442 테스트 단언 무회귀"가 M1 전체의 베이스라인 게이트가 된다(M1은 기존 파일 무수정·순수 추가 원칙). 설치 직후 lint/typecheck/vitest 실측을 이 로그에 기록한다.

**알려진 한계** — 이 결정은 팀 4인의 사후 합의를 전제로 한다(PRD OQ "팀 합의" 미해결 — v1-draft 상태로만 커밋하고 푸시 보류). 또한 viowlet의 `.env` 비밀값은 워크트리에 없으므로 라이브 모드 검증은 이 단계에서 불가 — fake 모드 완결성(키 없이 전체 파이프라인 작동)에 의존한다.

## 공통 명세 7편 + 계약 타입·한우 실증 (2026-08-15)

**결정과 근거** — 명세를 문서(`docs/spec/00~07`)와 타입(`src/lib/verify/contract/`)의 이중 표현으로 작성하고 "문서와 타입이 다르면 타입을 따르고 문서를 정정한다"로 우선순위를 고정했다. 계보에 세 벌 있던 어휘는 경쟁이 아니라 층위 차이로 해소: 판정 3값(표면 고정) / 화면 5상태(pig-research 계보 승격) / 엔진 검증가능성 6값(화면 노출 금지). 5상태는 (검증가능성×판정×현재성)의 프로젝션 함수 `projectEvidenceStatus()` 하나로만 산출하며, 우선순위는 mismatch > stale > 나머지 — 위험 신호(불일치)를 신선도 표시가 가리지 않게 하기 위함. `AssetKind`·`ClaimKind` 유니온 확장은 기존 파일 수정이므로 M1에서 금지 — `CategoryId` 신설 + `engineAssetKind` 선택 바인딩 + `proposedClaimKinds` 문자열 선언으로 우회하고 엔진 등록은 M2+ 일괄로 미뤘다. 한우 실증 디스크립터가 기존 축(어댑터 2종·claim kinds 6종·3층 지원)을 무손실 수용함을 테스트로 증명. 실측: `npx tsc --noEmit` 0오류, 신규 계약 테스트 12/12, eslint 클린, 기존 495 테스트 무회귀.

**트레이드오프** — (a) verifiable+판정 전 상태를 `review`로 접었다: "아직 안 한 것"과 "교차 충돌로 강등된 것"이 화면에서 같은 상태가 된다 — 화면 단순성을 위해 수용, 구분이 필요한 화면은 리포트 원천값(verifiability)을 참조. (b) `proposedClaimKinds`가 문자열이라 오타를 타입이 못 잡는다 — M2 엔진 등록 시 해소되는 일시 부채. (c) 문서당 200줄 상한을 지키려 예시 코드 대신 실파일 참조를 썼다 — 파일 이동 시 링크 부패 위험.

**eval 영향** — 계약 테스트 12건이 신규 측정 지점: 프로젝션 전수성(6값×판정 3값 조합 무예외), 코퍼스 등록 정합(어댑터 sourceId ⊆ 스파인 등록 출처), 층 선언 완전성(3층 전부+근거 서술). PRD [계약] 필수 8요소는 02(어휘)·03(evidence)·04(표현·고지)·05(마스킹·라이선스·개인정보·신선도)에 전건 매핑 — 커버리지 재검증은 리뷰 게이트가 수행.

**알려진 한계** — 신선도 기준의 카테고리별 구체 수치 미정(`[팀 결정 대기]`). `isStale` 산정 로직(as_of 비교)은 M1 범위 밖 — 프로젝션은 입력으로만 받는다. 계약이 정의한 페이지 슬롯의 실제 셸 구현은 M2. 명세 리뷰(규제·일관성·착수 실용성) 통과 전까지 v1-draft.

## 명세 리뷰 3관점 실행 + 전건 반영 (2026-08-15)

**결정과 근거** — v1-draft에 3관점 리뷰를 실행했다: ①규제·정책(고지 문안을 출력 필터 정규식에 실대조하는 기계 검증 포함) ②문서-코드-엔진 정합성 ③착수 드라이런 — 돼지 담당자 시점으로 명세만 읽고 실제 디스크립터 초안 작성을 시도해 수용 기준("명세만 읽고 착수 가능")을 실증. 결과 CRITICAL 0 / HIGH 6(+드라이런 BLOCKER 1) / MEDIUM 12 / LOW 11, 전건 반영. 핵심 반영: (a) **BLOCKER — 코퍼스 등록 모순**: 신규 출처는 담당자가 등록할 수 없는데(기존 파일 무수정 원칙) 등록 없이는 인용 불가였다 → `proposedSources` 신설로 claim kind와 동일한 "선언→오너 M2+ 일괄 반영" 문형으로 비대칭 해소, 기존 id 재사용 조건(`amendsExisting`)·신호등 기록 위치(`license` 필드)도 계약 편입. (b) **고지 문안 1이 자체 출력 필터에 차단됨** (리뷰어가 정규식 실대조로 증명 — "투자권유…가 아니며" 꼬리를 필터 부정 예외가 인식 못 함) → 문안 재작성("투자를 권유하지 않으며…"), `contract/notices.ts`로 단일 진실화, 필터 통과를 `notices.test.ts`로 회귀 고정, "신규 문안은 필터 테스트 선통과" 절차 명문화. (c) 실명 예외 자기모순("자연인 일체 불허" vs 작가명 허용) → "예외 목록 외" 문형 정정 + `allowedPublicNames` 계약 필드 신설(익명화 게이트가 참조할 기계 allowlist) + 작가명 외부 AI 전송 불가 기본값. (d) 표현 규칙 신설분의 집행 공백(시작 촉구·집계 점수·신뢰 주어가 현행 필터 전부 통과함을 기계 확인) → 규칙별 집행 방식 열 신설(필터 확장=M2 오너 / 레드팀 / 표본 감사), verdict-summary 허용 형태(건수 나열만, 비율·게이지 금지) 계약화. (e) CDN URL "보존 무방" 모호 → 로컬 원천 한정·공개 산출물 제거/비렌더 격리·원문 링크=상품 페이지 URL 명문화. (f) 02 review 행 열거가 코드 4케이스보다 부족 → `verifiable` 포함 정정(타입 우선 원칙 적용례). 그 외: 어댑터 `status`(planned/implemented) 신설로 "계획 선언" 표현 가능화, engineAssetKind 의미 정의, 테스트 확장 방법(카테고리별 새 파일), DART 공통 축 관례 명문화, "10분 가이드"→사전 읽기 목록+반나절 현실화, 어휘 충돌 금지 원칙(unsupported 라벨 "검증 경로 없음"으로 분리), stale 라벨 "현재성 재확인", 00 결정 대기 표에 누락 마커 8행 보강, 이의제기 기본값(접수 확인 2영업일·1차 회신 7영업일)·검토 중 표시·정보주체 창구 신설.

**트레이드오프** — 집계 점수 금지·시작 촉구 금지의 완전한 기계 집행(필터 패턴 확장·공개 리포트 스키마 린트)은 기존 파일 무수정 원칙과 충돌해 M2 오너 작업으로 이월 — 그때까지 집행은 오너 리뷰+표본 감사이며 이 한계를 04에 명시했다. `allowedPublicNames`는 필드만 신설, 게이트(mask.ts) 연동은 M2 — 그 사이 art 실명 자산은 라이선스 Yellow 게이트(공개 화면 금지)가 이중 방어선이다. 드라이런의 "기계 그린 ≠ 의미 정합" 문제(소 전용 서술의 id를 돼지가 재사용해도 테스트 통과)는 amendsExisting 선언 의무로 완화했으나 최종 방어는 오너 리뷰다.

**eval 영향** — 계약 테스트 12→18건: 고지 문안 필터 통과 회귀(`notices.test.ts` — 문안 수정 시 자동 검출), 출처 배선 정합(`unknownSourceIds` = ∅), 층 출처 규칙(`layerSourcesSatisfied`), 어댑터 구현 상태 검사 추가. 드라이런 자체가 재사용 가능한 검증 방법으로 확립됨(다음 담당자 온보딩 시 반복 가능).

**알려진 한계** — 문서 프로파일 `ColumnKey`의 소 개체 명세표 전용성은 M2 확장 결함으로 예고됨(pig 신고서 표는 두수·자돈 조건 구조라 현행 프로파일이 못 담음) — pig 착수 시 프로파일 일반화 필요. 드라이런이 작성한 pig 디스크립터 초안은 참고용으로만 존재(담당자 본인 확정 전 커밋하지 않음 — 역할 분담 원칙).

## 빌드 실패 재발 — Google Fonts 메타데이터 404 → next 16.3.1 (2026-08-15)

**결정과 근거** — M1 최종 검증의 `npm run build`가 폰트 모듈 로드에서 실패했다. 실측: 네트워크 정상, fonts.gstatic.com이 next/font 메타데이터가 가리키는 noto_sans_kr v39 파일 URL에 404 응답 — Google 측 폰트 파일 회전으로 인한 빌드타임 메타데이터 부패로, fa247cd(16.2.12→16.3.0 "Google Fonts 메타데이터 갱신")와 동형의 재발이다. 제 변경(문서+미참조 신규 모듈)과 무관한 베이스라인 고장. 선언 범위 `^16.3.0` 안에 있는 16.3.1로 갱신해 해소(치유법도 전례와 동일). 재검증: build 완주(정적/SSG/동적 라우트 산출), 테스트 513 통과 유지, lint 클린.

**트레이드오프** — "기존 파일 무수정" 원칙의 예외 1건: `package.json`(범위 표기 ^16.3.0→^16.3.1)·`package-lock.json`. 방치 시 팀 전원이 새 빌드·배포 불가(제출 URL 유지 요건과 직결)라 예외가 정당하다고 판단, 예외 범위를 이 2파일로 한정하고 별도 커밋으로 분리한다.

**eval 영향** — 의존성 패치라 지표 변화 없음. 단 "빌드 가능"이 외부 폰트 CDN 상태에 의존함이 재확인됨 — 제출 동결 전 재배포 리허설 필요성의 실측 근거.

**알려진 한계** — next/font/google 의존이 남는 한 동형 재발 가능. 근본 해결(폰트 셀프호스팅)은 M2+ 검토로 이월. eslint-config-next 16.2.12는 기존부터 next와 불일치였으나 lint 정상이라 미수정.
