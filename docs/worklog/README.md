# 작업 로그(worklog) 규약

> AI(Claude Code) 협업 작업의 수정 내역을 상세 기록하는 문서. "무엇을 만들었나"는
> git 커밋 메시지가 담당하므로, 여기에는 **"왜 그렇게 결정했고, 무엇을 포기했고,
> 그래서 무엇을 검증할 수 있게 됐나"** 를 남긴다. curation-gate 프로젝트의
> worklog 규약을 이식했다.

## 적용 범위

- 기록 시작: **2026-08-15**. 그 이전 구간(S0~S3.5, 2026-08-08~15)의 1차 기록은
  git 커밋 메시지와 `docs/planning/페이즈-계획.md`의 게이트 판정이다.
  소급 재작성은 하지 않는다 — 사후 복기는 당시의 트레이드오프를 미화한다.
- 8/15 당일 작업분은 세션 기억이 유효한 범위에서 소급 기록했다(`s3-5.md`).

## 파일 규칙

- 스프린트당 1파일: `docs/worklog/s<n>.md` (n = 페이즈 계획 v4의 스프린트 번호.
  S3.5와 그 후속은 `s3-5.md`)
- 구현과 **병행 기록** — 마감 때 몰아서 복기하지 않는다
- 항목 단위로 append. 기존 항목 수정 시 정정 표기(~~취소선~~ + 사유)
- 설계 결정의 규모가 크면 council 평결(`docs/planning/council-*.md`) 또는
  별도 결정 문서로 승격하고 worklog에는 포인터만 남긴다

## 항목 필수 섹션

```markdown
## <항목 제목> (YYYY-MM-DD, 커밋 <hash>)

**결정과 근거** — 무엇을 어떻게 하기로 했고, 왜 그런가.
근거가 실측이면 실측 방법·결과를 포함한다.

**트레이드오프** — 고려한 대안 / 채택 이유 / 지불한 비용.
"비용 없음"은 대개 거짓 — 미룬 것·좁힌 것·복잡해진 것을 적는다.

**검증 영향** — 이 결정이 만드는(또는 없애는) 측정·검증 지점.
테스트, 골드셋 F1, 레드팀, 익명화 스캔, 회귀 스냅샷이 소비한다.

**알려진 한계** — 이 결정으로 못 잡게 된 것, 잔여 부채.
```

- 해당 없는 섹션은 "해당 없음"으로 명시(생략 금지 — 생략은 "안 적은 것"과
  "없는 것"을 구분 못 하게 한다)

## 이 프로젝트 고유 규칙

- **데이터 익명화 관련 결정은 반드시 기록** — 마스킹 규칙 변경, 공개 산출물
  경로 변경, 스캔 게이트 수정은 전부 worklog 대상이다
- **판정 규칙 변경은 실측 근거 필수** — 성별 수→거세 재분류처럼 도메인 상식을
  판정에 반영할 때는 오탐/정탐 수치를 병기한다
- **사고 기록도 남긴다** — 재발 방지 조치와 함께 (예: 주석 스윕의 CSS 파괴,
  fake verify의 data/public 오염)
