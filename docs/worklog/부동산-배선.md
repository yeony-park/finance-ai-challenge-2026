# 부동산 배선 — 건축물대장 표제부 축 개통 (2026-08-22)

건축HUB 어댑터(017eae6, 미배선)를 검증 파이프라인·계약·화면에 연결. 판정 규칙 변경 포함.

## 결정과 근거

- **소재지 claim의 검증가능성 승격**: `real_estate_address`를 `structurally_impossible` →
  `verifiable`로 변경. 기존 사유("실거래 신고가 법정동까지만 공개돼 구조적으로 불가")는
  표제부 어댑터 등장으로 거짓이 됨 — 이제 판정 여부는 추출이 아니라 판정 단계에서
  수집본 유무로 결정된다.
- **판정 규칙 (judge/real-estate)**: 표제부 수집본 없음 → "수집본이 없어 …(대조 불가)" /
  수집본 있으나 지번 미확인 → "수집이 부분적일 수 있어 판정하지 않습니다(대조 불가)"
  (부재를 불일치로 단정하지 않음 — 근거 0건 무판정 원칙) / 지번 확인 → "일치" + 근거는
  대장 사실(주용도·연면적·사용승인일·구조)만 나열, **주소·건물명은 근거 문장에 넣지 않는다**
  (마스킹 이중 안전).
- **픽스처 격리 가드 (pipeline)**: 라이브 실거래 실행에 픽스처 표제부가 섞이는 경로 차단 —
  register는 `name==="cache"`(실수집본)이거나 전체가 fake 모드일 때만 판정에 사용. fake
  사용 시 리포트 노트에 명기.
- **계약**: `contract/real-estate.ts` 신설 — 실재성 partial(층·호 소유 구조는 공개 대장
  확인 불가 명시), 가격 supported(RTMS), 이행 partial(DART 미접수 공모). 스파인 코퍼스에
  `molit-bldrgst-title` 등록. `/real-estate` 착지 descriptor 배선(층별 지원 선언 첫 표시).
- **지번 스코프 수집**: 어댑터에 `bun`/`ji`(4자리 패딩) 추가 — 법정동 전체 1,000행 한도를
  피해 대상 필지만 수집. 수집 CLI `reference:building` 신설 (rtms-collect-cli 미러).
- **실키 프로브 실측**: 서초동 1678-4 수집 시도 → HTTP 403 · returnReasonCode=30.
  **키는 유효하나 건축HUB 활용신청이 별도로 필요** (RTMS 승인과 무관함이 확정).
  실패 캐시는 status=failed로 커밋(키 마스킹 확인, 히트 0건) — 프로브 기록 보존.
- 라이브 리포트 재생성: 소재지가 낡은 "구조적 불가" 대신 "수집본 없음(대조 불가)"로,
  기초자료 limits·뷰모델 문장도 표제부 축 기준으로 갱신.

## 트레이드오프

- 표제부 부재를 "원장 불일치"로 판정하지 않음 — 수집이 부분적일 수 있어(1페이지 한도,
  신주소 전환·합필 가능성) 부재≠부존재. 민감도(놓침)를 감수하고 특이도(오탐 0)를 택함.
- 실재성 층을 supported가 아닌 **partial**로 선언 — 표제부는 건물 단위까지만 확인하고
  층·호 단위 소유 구조는 공개 대장에 없다. 과대 표기 방지 테스트로 고정.
- 지번 스코프 수집은 필지 단위 파일을 만들므로 법정동 전체 조회보다 파일 수가 늘 수 있음
  — 오퍼 단위 검증에는 충분, 지역 통계 용도가 아님.
