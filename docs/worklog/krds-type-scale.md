# KRDS 타이포 스케일 이식 (2026-08-19)

> 2차(컴포넌트 계층) 이식 기록은 문서 하단 "2차: 컴포넌트 계층" 섹션 참조.

## 결정과 근거

- GDWEB 관공서 부문 수상작 60건을 스캔해 레퍼런스로 **디지털 정부서비스 UI/UX 가이드라인
  (KRDS, GOLD PRIZE, 現 www.krds.go.kr)** 을 선정.
- 근거: (1) 후보군 중 최고 등급, (2) "예쁜 사이트"가 아니라 수치로 검증 가능한 표준
  (본문 17px 이상, 행간 150% 이상, heading 19/24/32/40, display ≤60)이라 이식이 재현
  가능, (3) 본 서비스가 국가 공공 원장을 대조하는 서비스이므로 정부 디지털 서비스의
  디자인 언어를 따르는 것이 신뢰 서사와 일치, (4) 색·레이아웃을 강제하지 않는 체계라
  기존 웜 화이트+옐로 액센트 캐릭터를 그대로 보존 가능.
- 차선 후보: 고용24(WINNER, KRDS 적용 대형 포털), 국가정신건강정보포털(WINNER,
  일러스트 기반 — 기존 에디토리얼 캐릭터와 충돌), 축산물품질평가원(BRONZE, 범용 기관형).
- 이식 범위: `src/styles/tokens.css` 타입 스케일·행간만 변경. 색상 토큰·간격·컴포넌트
  구조 무변경. font-size 선언 217곳 중 214곳이 토큰 참조라 토큰 교체만으로 전면 전파.

## 트레이드오프

- 본문 15px→17px(+13%)로 밀도 감소 — 카드 본문이 2줄→3줄로 늘어나는 지점 존재.
  가독성(대상 사용자: 조각투자 입문자)을 밀도보다 우선.
- display 상한 68px→60px(KRDS display-large PC 기준) — 히어로 임팩트 소폭 감소.
- SVG 차트 내부 텍스트 3곳(11px/10.5px, category.module.css)은 viewBox 좌표계
  종속이라 의도적으로 미변경.

## eval 영향

- 판정·마스킹·공개 경로 로직 무관 — vitest 55파일 891통과, `next build` 통과.
- 시각 검증: dev 서버에서 `/`·`/offers`·`/cattle`·`/methodology`·`/offers/livestock-1`
  를 1440px·375px 전후 스크린샷 대조. 양 폭 모두 가로 오버플로 0건.

## 알려진 한계

- 토큰 1차 이식만 수행. KRDS의 컴포넌트 계층(터치 타깃 44px, 헤더 구조, 브레드크럼 등)은
  미적용 — 후속 작업 후보.
- 스크린샷 검증은 대표 5화면 한정. `/pig`·`/art`·`/real-estate`·나머지 리포트는
  동일 토큰 파생이라 낮은 위험으로 판단했으나 전수 확인은 아님.

# 2차: 컴포넌트 계층 (2026-08-19)

## 결정과 근거

- KRDS 공식 코드(github.com/KRDS-uiux/krds-uiux `_button.scss` + `krds_tokens.css`)에서
  버튼 높이 실측: xsmall 32 / small 40 / medium 48 / large 56 / xlarge 64px.
- 신규 토큰: `--ds-tap-min 44px`(최소 터치 타깃), `--ds-control-h-sm/md/lg 40/48/56px`,
  헤더 60→64px(KRDS height-9).
- 적용: 헤더 내비 링크(44 타깃), 온보딩·히어로 칩 40, 검색·온보딩 완료·상태 액션·리플레이
  버튼 48, 리포트 레벨 토글·챕터 필·관심 등록 토글 40, `<summary>` 토글류는 마커(▶) 보존을
  위해 flex 대신 padding으로 44 확보.
- 부수 수정: `/cattle` 모바일 375px 가로 오버플로 56px(프로덕션에도 존재하던 기존 버그) —
  원인은 `.layerTable`의 `.layerName{white-space:nowrap}`. 640px 이하에서 어절 단위
  줄바꿈 허용으로 해결.

## 트레이드오프

- 인라인 텍스트 링크(`.offerLink` "리포트 열기 →" 등)는 44px 미적용 — 액센트 밑줄이 텍스트에서
  분리되는 시각 부작용이 있고, 카드 전체가 이미 클릭 영역이라 WCAG 인라인 예외로 처리.
- 칩 높이 상승으로 온보딩 모달 세로 길이 소폭 증가(85dvh 스크롤 내 흡수).

## eval 영향

- vitest 55파일 891통과, `next build` 통과. 모바일 375px 8개 화면(`/`·`/offers`·4개 카테고리
  착지·리포트·방법론) 가로 오버플로 전수 0건 계측.

## 알려진 한계

- SVG 차트 내부 인터랙션(가격 차트 크로스헤어)과 표 내부 셀 버튼(`.cell`)은 좌표계·밀도 제약으로
  이번 라운드 제외. KRDS 헤더 구조(브레드크럼·유틸 영역)도 미이식 — 규모 대비 효익 낮다고 판단.

# 3차: 카드 섹션 균형 회복 + 엣지 케이스 (2026-08-19)

## 결정과 근거

- 17px 상향 후 오너 피드백: 카드 섹션 내 UI 불균형. 계측 결과 3가지 실체 —
  (1) landing `.offerCard`가 grid+`align-content:start`라 본문 줄 수 차이만큼 하단
  액션(관심 등록·리포트 열기) 위치가 카드마다 어긋남, (2) `.watchRow`에서 상태문이
  길면(부동산 A "정정 접수 여부 미확인…") 토글 배치가 형제 카드와 달라짐,
  (3) category `.tileRow`가 `align-items:flex-end`라 캡션 줄 수가 다른 "대조 불가"
  블록 전체가 내려앉음.
- 수정: `.offerCard` flex column 전환 + `.offerMeta{margin-top:auto}`로 푸터 클러스터
  하단 고정, `.watchStatus{flex:1 1 10rem}`·`.watchToggle{margin-left:auto}`로 줄바꿈
  시에도 토글 우측 고정, `.tileRow` 상단 정렬, category 카드는 `OfferWatchControl`에
  `className` 프롭 신설 + `.offerCardWatch{margin-top:auto}`로 동일 처리.

## 트레이드오프

- 하단 고정으로 짧은 카드에는 본문과 푸터 사이 여백이 생김 — 행 단위 정렬 일관성을
  카드 개별 밀도보다 우선(표준 카드 그리드 관행).
- `.offerCard > div` 셀렉터 같은 구조 의존 대신 프롭 전달을 택해 TSX 1곳 수정 비용 수용.

## eval 영향

- 판정·데이터 경로 무관. vitest 891통과, `next build` 통과.
- 엣지 케이스 스위트(DOM 주입)로 검증: 긴 공모명(3줄 랩), tally 5자리(12,345),
  긴 정정 상태문(3줄 랩 + 토글 우측 유지), 관심 등록됨 상태(플래그 뱃지 추가·액센트
  버튼), 320px 초협폭(오버플로 0), tileRow 3블록 상단 정렬.

## 알려진 한계

- 엣지 주입은 DOM 조작 기반 — 실데이터 경로(view-model)의 극단값 렌더는 미검증.
- tally 0값 칩의 시맨틱 색상(0인데 판정색 표시)은 판정 어휘 규칙 영역이라 미변경 —
  변경하려면 view-model tone 정책 결정 필요.
