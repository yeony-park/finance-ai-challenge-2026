# 표현 규칙·고정 고지 (Expression Rules)

> **상태: v1-draft (팀 리뷰 요청)** · 집행 장치: `src/lib/spine/guardrail/output-filter.ts` + 표본 감사 + 계약 테스트 · 고지 문안의 단일 진실: `src/lib/verify/contract/notices.ts` (필터 통과가 테스트로 고정됨) · 근거: PRD v0.2 (금소법 §22 — 판매업자 아닌 자의 금융상품 광고 금지, 추천·비교는 '중개' 판단 가능)

## 대원칙

이 서비스는 **교육·정보 제공형**이다. 특정 상품의 청약을 유인하는 순간(추천·가입 유도) 등록 없이 불가한 영역에 들어간다. 모든 표면 — 입문자용 친화적 화면·챗 응답 포함 — 이 예외 없이 아래 규칙을 따른다. **차단기는 측정기가 아니다**: 필터는 게이트일 뿐, 준수 여부의 측정은 표본 감사·레드팀·리뷰가 담당한다.

## 차단 계열 (출력 필터 기존 9계열 계승)

`valuation-assertion`(적정/저평가) · `price-prediction`(오른다) · `investment-solicitation`(청약하세요/추천) · `safety-assertion`(안전합니다) · `fraud-assertion`(사기/속였다) · `materiality-grade`(중대성 등급) · `definitive-verdict`(확정/100%) · `guaranteed-return`(수익 보장) · `impersonation`/`system-prompt-leak`(사칭/카나리). 부정형 고지문은 통과하나, **필터의 부정형 예외는 특정 꼬리 문형만 인식하므로 신규 문안은 반드시 필터 테스트 선통과 후 확정한다** (`contract/__tests__/notices.test.ts`가 그 게이트다 — 실제로 초안 문안 1이 필터에 차단되어 재작성된 이력 있음).

## 추가 규칙 (v1 신설) — 규칙별 집행 방식 명시

| 규칙 | 내용 | 집행 방식 |
|---|---|---|
| 집계 점수 금지 | 판정·체크리스트의 상품 단위 집계(점수·통과율·배지·서열·게이지) 표시 금지 — 집계는 사실상 등급. `custom` 슬롯 포함 | 오너 리뷰(필수) + 필터 패턴 확장(M2 오너) + 표본 감사 |
| verdict-summary 허용 형태 | 판정값별 **건수 나열**("일치 8 · 원장 불일치 1 · 대조 불가 3")까지 허용. 비율·백분율·단일 합성값·시각 게이지 금지 (참고: 가격 층의 시장 위치 백분위는 판정 집계가 아니라 시장 통계이므로 허용) | 계약 문서 + 오너 리뷰 |
| 시작 촉구 금지 | "지금 시작하세요" 류 참여 촉구 금지. 목표 서술은 "시작 여부와 무관하게, 확인 후 결정" | 필터 패턴 확장(M2 오너) + 표본 감사 |
| 신뢰 표현 주어 제한 | "믿을 수 있다" 계열의 주어는 **서비스 방법론** 한정. 상품·발행사 주어 금지 | 표본 감사 (정규식 부적합) |
| 자체 조사 격리 | 발행사·플랫폼 자체 설문·조사 수치는 사용자 대면 콘텐츠 사용 금지 (근거 문서 인용 시 "자체 조사" 명시) | 표본 감사 + 콘텐츠 리뷰 |
| 근거 없는 시세·인과 금지 | 시세 생성, "질병 때문에 하락" 류 인과 단정 금지 — 시점 병렬 제시까지만 | 레드팀 시나리오 + 표본 감사 |
| 감정·법률 대체 금지 | 공식 감정평가·진위 판정·등기·법률 검토 대체 인상 금지 (미술품 특히) | 고정 고지 3·4 + 콘텐츠 리뷰 |
| 검증 범위 한정 | "검증"은 항상 "공시-공공원장 대조"로 한정해 사용 | 고정 고지 3 + 표본 감사 |

## 라우팅 중립성 (AI 상품 안내)

1. 상품 라우팅은 **사용자가 명시적으로 지정한** 카테고리·상품에 한정한다. 지정의 범위는 **같은 대화 세션 내 유지**된다(이전 턴에 지정한 상품은 이후 턴에서 재언급 가능).
2. 카테고리만 지정하고 상품 미지정 시: 검증 데이터 보유 상품 **전수**를 **공시 접수일순**(중립 정렬)으로 제시하고, 선정 기준(검증 가능 데이터 존재 여부) 고지를 동반한다. AI 주도의 선별·우선 노출·비교 제시 금지.
3. 예시 질문·추천 질문은 교육·확인 절차 수준으로 제한 — 특정 상품·청약 지시 문안 금지.
4. "어떤 상품이 나은가" 질문에는 **판단 기준 교육**으로 응답하고 상품을 지목하지 않는다.

## 예금자보호 서술 규칙 (3요소 동시 제시)

예금자보호를 언급하는 모든 콘텐츠는 3요소를 함께 제시한다 (하나만 말하면 반쪽 진실). 표준 문장: `contract/notices.ts`의 `DEPOSIT_PROTECTION_NOTICE` (필터 통과 고정):

1. 조각투자 증권은 금융투자상품으로 **예금자보호 대상이 아니다** (2단 논거로 서술 — "어떤 보호도 없다"로 확장 단정하지 않는다. '보호 없음' 인상은 요소 3이 담당).
2. 증권사 예치 현금(투자자예탁금)만 1인 1억 원 한도 보호 (2025-09-01 시행). ※ 조각투자 플랫폼의 예치금 은행 별도 예치·신탁(요소 3)과 혼동 금지.
3. 보호장치는 도산 시 반환·관리 장치이지 **손실 보전이 아니다**.

각 요소에 별도 공식 출처 부착 (출처: `docs/planning/research-2026-08-15.md` BOX 3).

단일 진실: `src/lib/verify/contract/notices.ts`의 `FIXED_NOTICES` 5문안 — 문서에 문안을 중복 기재하지 않는다(문서-코드 불일치 방지). 필터 통과는 `notices.test.ts`로 고정. 신규·수정 문안은 테스트 선통과 후 반영.

## 발행사 이의제기 채널

- "원장 불일치" 등 판정이 공개되는 상품의 발행사가 정정을 요청할 수 있는 접수 경로를 방법론 페이지에 고지한다.
- 기본값 `[팀 결정 대기]`: 접수 확인 통지 2영업일, 1차 회신 7영업일, 접수 주소는 팀 공용 이메일.
- 접수 시: 해당 판정에 **"이의제기 검토 중" 표시**를 부착 → 근거 재확인 → 판정 유지/정정 → 처리 결과를 리포트 이력으로 남긴다 (은폐 없이 정정 이력으로 투명화).
- 개인 정보주체(자연인)의 정정·삭제 요청 창구는 `05-data-policy.md` §1이 규정한다.
