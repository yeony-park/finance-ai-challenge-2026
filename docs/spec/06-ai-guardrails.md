# AI 가드레일 (AI Guardrails)

> **상태: v1-draft (팀 리뷰 요청)** · 집행 장치: `src/lib/spine/` (README에 파이프라인·코퍼스·필터 상세) · 근거: PRD v0.2, 규제 경계 리뷰 H-2·H-6·H-7

## 1. 스파인 파이프라인 계승 (전 AI 표면 의무)

새로 생기는 모든 AI 표면(메인 대화형 검색 포함)은 스파인 전체 경로를 통과한다 — 출력 필터만 떼어 쓰는 것 금지:

```
요청 → 레이트리밋 → 입력 스크리닝(인젝션·권유 요구·단정 요구·마스킹 해제·개인정보 조회)
     → LLM(출처 계약 JSON) → 출처 강제(등록 코퍼스 밖 인용 → abstain)
     → 출력 필터(04-expression-rules 계열) → 응답
```

- 응답 유니언 `answer | abstain | blocked | pending_action | rate_limited` 계승.
- 기존 계보가 자유 대화형 챗을 범위 밖으로 뒀던 결정은 **본 명세로 대체**된다 — 단, 되살리는 조건이 이 문서 전체다. `/api/chat` 류 라우트 신설 시 레드팀 통과가 선행 조건.
- 새 카테고리의 출처는 코퍼스(`spine/rag/corpus.ts`) 등록분만 인용 가능하다. 담당자는 `proposedSources`로 선언만 하고, **등록·서술 보강은 M2+에서 오너가 일괄 반영**한다 (`01-category-contract.md` §2).

### 대화 라우트 출시 게이트 (2026-08-16 council 확정)

`/api/chat` 류 공개 대화 표면은 아래 4게이트 **전부** 통과 전에는 공개하지 않는다 — 기준은 날짜가 아니라 게이트다:

1. **다턴 레드팀 통과** — §6의 대화 맥락 공격(다턴 유도·맥락 주입) 시나리오 셋 신설·버전 표기 포함.
2. **전역 요청·비용 한도** — 서버리스 인스턴스 메모리는 인스턴스별 근사만 가능하므로, 전역 카운터 저장소(KV 1개)로 일일 예산·요청 한도를 강제한다. 한도 도달 시 정적 안내로 강등.
3. **배포 외부 킬스위치** — 수동 CLI 배포 구조에서 심사 기간 중 재배포 없이 차단할 수 있어야 한다. 차단 플래그는 배포 아티팩트 밖(전역 카운터와 같은 저장소)에 둔다.
4. **강등 리허설** — LLM 실패·한도 도달·킬스위치 각 경로에서 정적 스캐폴드(§4)로의 회귀를 실측으로 확인한다. 폴백 전환 자체가 두 번째 장애가 되지 않아야 한다.

정적 스캐폴드는 챗 공개 후에도 제거하지 않는다 — §4 열화 모드의 영구 폴백이다.

## 2. AI 응답 4유형 (대화형 안내의 전 응답 분류)

| 유형 | 내용 | 근거 데이터 |
|---|---|---|
| ① 입문 교육 | 조각투자 구조·라이프사이클·보호장치·수익 구조 (04의 예금자보호 3요소 규칙 준수) | 출처 부착 교육 콘텐츠 (사전 작성) |
| ② 라우팅 | 사용자가 명시 지정한 카테고리·상품으로 안내 (04의 중립성 3원칙) | 카테고리 디스크립터 |
| ③ 검증 사실 인용 | 확인 현황·확인 항목 체크리스트·미확인 항목의 확인 질문 변환. 근거 없으면 "대조 불가" | **사전 생성 리포트 캐시만** |
| ④ 범위 밖 거절 | 타 금융상품·세무·법률·예측 요구 → 표준 거절 + 공식 채널 안내 (abstain 경로) | 코퍼스 officialChannels |

- 모든 사실 문장에 출처·기준일 부착. 수치 문장은 AI 생성 태그 불가 (기존 눈높이 서술 규칙 계승: 문장 출처 태그 `fact | issuer_claim | calc | ai`, 수치 문장 `ai` 금지).
- 체크리스트 응답에는 "확인 절차 안내이며 투자판단이 아님" 고지 동반.

## 3. 캐시 경계 (결정 8의 정밀화)

- **검증 데이터·인용 사실**: 사전 생성 캐시(`data/public/`)에서만 읽는다. AI가 라이브 원장·외부 API를 대화 중 호출하지 않는다.
- **AI 추론 호출**: 별도 경계로 관리 — 요청 한도(레이트리밋)·비용 상한·타임아웃. 인용은 캐시 출처로 한정되므로 추론이 실패해도 사실이 오염되지 않는다.
- 눈높이 서술(easy/pro)은 사전 생성·캐시 후 서빙을 기본으로 한다 (기존 narrative 캐시 계승). 실시간 생성이 필요한 표면은 출력 필터 + 재생성 1회 루프 계승.

## 4. 열화 모드 (제약 조건 — 미충족 시 결격 위험)

AI 제공자 장애·쿼터 소진 시에도 다음은 **AI 없이** 동작해야 한다:

- 4카테고리 분기·카테고리 착지 페이지·검증 리포트 열람 (정적 경로)
- 예시 질문 → 확인 항목 안내의 정적 스캐폴딩 (사전 작성 콘텐츠)
- AI 응답 불가 사실의 정직 표기 (조용한 실패 금지 — `mode` 표기 관례 계승)

공개 대화 표면의 남용 방지(요청 한도·비용 상한·실패 폴백)는 URL 무중단 제출 요건의 전제다.

## 5. 추출 교차검증 (계승 불변식)

- LLM 추출은 규칙 파서와 독립 실행 후 교차 확인: agreed만 완전 신뢰, 충돌 → `cross_check_conflict` 강등, LLM 단독 → `llm_only` 강등. **LLM 단독 추출은 절대 판정에 이르지 못한다.** 강등 = 판정 미산출 — 판정 층 표면 어휘로는 "대조 불가", 화면 상태로는 `02`의 프로젝션에 따라 "추가 대조"로 표시된다.
- 근거 0건 판정 금지는 타입 수준 강제(`createJudgement`) — 우회 금지.

## 6. 레드팀 (상시 게이트)

- 기존 24 시나리오(1~4세대 프레임: 인젝션·권유 유도·단정 요구·마스킹 해제·PII·판정 조작·출처 탈락·코퍼스 밖·도구 남용·인코딩 스머글 + 양성 대조군) 통과 유지.
- 대화형 표면 신설 시 시나리오 셋에 대화 맥락 공격(다턴 유도·맥락 주입)을 추가하고 **시나리오 셋을 버전 관리**한다 — "통과율 100%"는 항상 "어떤 셋의" 100%인지와 함께 보고.
- 외부 문서(공시 원문·수집 데이터)는 항상 비신뢰 입력으로 다룬다 — 문서 내 지시문은 데이터일 뿐 명령이 아니다. yeonjeong 계보의 프롬프트 인젝션 픽스처(6표면) 편입 검토는 `07-asset-map.md`.
