## 0. 무엇이 이미 있었고, 무엇이 비어 있었나

**이미 결정돼 있는 것 — 이 문서는 재발명하지 않는다.**

| 재료 | 위치 | 내용 |
|---|---|---|
| 입문자 문제 정의 | IDI 2026-08-15 ★★ | 입문자는 정보가 아니라 **판단 기준 자체가 없다** → 확인 항목 스캐폴딩 + 항목별 엔진 실측으로 답한다 |
| 전환 2대 기준 | IDI | 수익 구조 명확성 · 판매 주체 신뢰성 |
| 판단 기준의 실물 | `content/checklist.ts` | 확인 질문 8가지 — 전 항목 공적 출처 부착 |
| 눈높이 2단 | narrative easy/pro | 같은 사실의 서술 깊이 2단계 |
| 멘탈모델 교정 재료 | `content/home.ts` INTRO_CARDS | 청약 진입·매각 지연·예금자보호 3요소 |
| 표현·규제 경계 | spec 04·06 | 라우팅 중립성, 집계·시작 촉구 금지, AI 4유형, 캐시 경계, 열화 모드 |

**비어 있던 것 — 이 문서가 채우는 것.**

1. 재료들을 잇는 **끝-끝 여정**: 첫 방문자가 어떤 순서로 무엇을 겪고, 각 단계에서 무엇을 얻는가.
2. 단계별 **성공 기준**: S4 외부 사용성 테스트가 검증할 문장.
3. 여정을 받치는 **기술 선택**: 무엇을 새로 들이고, 무엇을 들이지 않는가.

## 1. 설계 원칙 (상위 결정의 계승)

- **개인화는 선언형이다.** 사용자가 밝힌 것만 반영한다. 행동 추적·취향 추론·상품 추천 없음
  (04 라우팅 중립성 — AI 주도 선별·우선 노출 금지의 화면 측 대응).
- **UI = f(페이지 명세, 프로파일).** 페이지별 슬롯 구조는 고정하고, 프로파일이 바꾸는 것은
  슬롯의 내용·순서·서술 깊이뿐이다. **정렬·강조까지만, 숨김 금지** — 전 카테고리·전 공모는
  항상 접근 가능하다.
- **기본 상태가 심사 대상이다.** 프로파일이 비어 있는 화면이 그 자체로 완결적이어야 한다.
  개인화는 진행형 향상이다.
- **AI 없이 성립한다.** 여정의 전 단계가 정적 콘텐츠로 완주 가능해야 한다(06 열화 모드).
  AI 대화는 같은 여정의 대화형 표피이지, 여정의 전제가 아니다.
- **여정의 목적지는 청약이 아니라 "확인을 마친 상태"다.** 시작 촉구 금지(04)와 일관 —
  "시작 여부와 무관하게, 확인 후 결정".
- **개인화 상태는 투명하다.** 현재 적용 중인 프로파일("관심: 한우 · 눈높이: 쉬움")을 화면에
  상시 표시하고, 초기화를 항상 제공한다.

## 2. 여정 5단계

| # | 단계 | 입문자의 질문 | 화면·기능 | 프로파일 | 성공 기준 (S4 태스크 후보) | 현재 상태 |
|---|---|---|---|---|---|---|
| 1 | 도착 | "여기 뭐 하는 곳이지?" | 홈 히어로 + 예시 질문 칩 | 없음 (기본 상태) | 첫 화면에서 10초 내 첫 상호작용 발생 | 구현됨 (M2) |
| 2 | 기준 형성 | "뭘 확인해야 할지 모르겠다" | 온보딩 문답 3개 → **"나의 확인 목록"** | level·concern·interests 생성 | 2분 내 자기 확인 목록을 만든다 | **신규 — M3 핵심** |
| 3 | 개념 학습 | "주식이랑 뭐가 다르지?" | 입문 카드 (눈높이·걱정 반영 정렬) | level·concern 반영 | 예금자보호 3요소를 자기 말로 재진술한다 | 부분 (카드 있음, 정렬 없음) |
| 4 | 검증 열람 | "이 공모, 공시대로인가?" | 카테고리 착지 → 리포트. **확인 질문 → 리포트 챕터 다리** | interests 반영 | 체크리스트 항목에서 해당 리포트 근거까지 3클릭 내 도달 | **갭 — 다리 없음** |
| 5 | 재방문 | "그 뒤로 바뀐 건 없나?" | 관심 공모의 정정 감시 결과를 홈에 표면화 | watchlist 반영 | 재방문 시 정정 유무를 첫 화면에서 인지한다 | 부분 (감시는 있음, 홈 표면화 없음) |

여정에서 가장 값싼 고효율 갭이 4단계의 "다리"다: 확인 질문 8가지의 각 항목에 "이 공모에서
확인하기" 링크를 붙여 리포트 챕터 앵커(`ReportChapterNav` 기존 앵커)로 연결하면, 스캐폴딩
(기준)과 실측(근거)이 화면에서 이어진다 — IDI 구도("확인 항목 + 항목별 엔진 실측")의 완성이다.

## 3. 온보딩 문답 설계 (2단계 상세)

원칙: **문항 3개 고정, 전부 건너뛰기 가능, 답마다 즉시 보상**(화면이 눈앞에서 바뀐다),
전 문안은 `content/` 모듈 + 출력 필터 감사 테스트를 거친다.

| # | 질문 | 선택지 | 프로파일 반영 | 즉시 보상 |
|---|---|---|---|---|
| Q1 | 조각투자, 얼마나 익숙하세요? | 처음 들어요 / 들어는 봤어요 / 해 봤어요 | level: easy / easy / pro | 눈높이 적용 표시 — 이후 서술 깊이가 바뀜 |
| Q2 | 가장 마음에 걸리는 게 뭐예요? | 실물이 진짜 있는지 / 돈이 어떻게 돌아오는지 / 문제 생기면 보호되는지 / 산 다음 언제 팔 수 있는지 | concern: asset-existence / return-structure / protection-scope / exit-structure | 해당 확인 질문이 목록 맨 위로 — "그 걱정은 확인 질문으로 답할 수 있어요" |
| Q3 | 어떤 자산이 궁금하세요? | 4카테고리 다중 선택 (+건너뛰기) | interests | 카테고리 정렬·강조 반영 |

- 종착 화면: **"나의 확인 목록"** — 확인 질문 8가지가 concern 우선으로 재정렬된 상태 +
  `CHECKLIST_NOTICE`("확인 절차 안내이며 투자판단이 아닙니다") 고지 동반.
- concern 선택지는 확인 질문 id를 그대로 쓴다 (`checklist.ts`의 asset-existence 등) —
  정렬 규칙이 별도 매핑 없이 성립한다.
- **챗 승격(2단계 이후)**: 같은 3문답을 대화형으로. AI는 `pending_action`으로 프로파일 변경을
  제안만 하고 사용자가 확정한다. `/api/chat` 신설 조건은 06 §1 그대로(스파인 전 경로 +
  다턴 레드팀 + 한도·폴백) — 칩 온보딩이 곧 열화 모드 폴백이 된다.

## 4. 프로파일 명세 (2026-08-16 오너 결정: 로컬 저장, 계정 없음)

```
BeginnerProfile v1
  version: 1
  level:     "easy" | "pro" | null
  concern:   "asset-existence" | "return-structure" | "protection-scope" | "exit-structure" | null
  interests: 카테고리 id 배열 (선택 순서 유지)
```

- 저장: `localStorage["jeomjeom.profile.v1"]`. 파싱은 저장값을 신뢰하지 않는 좁히기
  (watchlist 선례). 관심 공모(watchlist)는 기존 키를 유지하고 프로파일에 흡수하지 않는다.
- **비수집 결정**: 열람 이력을 자동 기록하지 않는다 — 선언형 원칙. 수집하는 것은 사용자가
  버튼·문답으로 직접 밝힌 3필드뿐이다.
- 파생은 순수 함수로만: `orderChecklist(concern)`·`orderCategories(interests)` —
  입력 배열의 원소를 제거하지 않는다(숨김 금지를 테스트로 고정).

## 5. 기술 스택 평가

**결론: 재플랫폼 불요.** 현 스택(Next.js 16 App Router + 사전 생성 캐시 + vitest +
Playwright + Vercel)이 여정 요구를 전부 감당한다. 판단 기준은 "입문자 여정에 무엇이
필요한가"이지 스택의 새로움이 아니다.

**들이지 않는 것 (이유 병기):**

| 후보 | 판정 | 이유 |
|---|---|---|
| 상태 라이브러리 (Zustand 등) | 불채택 | 프로파일은 저빈도 소상태 — watchlist의 `useSyncExternalStore` 패턴 재사용으로 충분. 의존성 0 유지 |
| 차트 라이브러리 (recharts/d3) | 불채택 | 시그니처 데이터 모듈은 소수·맞춤형 — RSC 수제 SVG가 번들 비용 0, 토큰 완전 제어. 게이지·비율 금지(04) 제약을 라이브러리 기본값이 침범하기 쉬움 |
| Vercel AI SDK / 스트리밍 챗 | 불채택 | 스파인 구조상 출력 필터가 **완성된 응답**을 본 뒤 노출한다 — 토큰 스트리밍과 양립 불가. 06 §7 모델 접근 단일화 유지, 스파인 클라이언트 확장으로 간다 |
| DB · 계정 · 서버 프로파일 | 불채택 | 심사 요건에 불필요, 개인정보 최소화(05)와 정합 |

**챗 착수 시점에 결정할 것 1건**: 공개 대화 표면의 전역 레이트리밋·비용 상한 카운터 저장소.
서버리스 인스턴스 메모리는 인스턴스별 근사만 가능 — 전역 한도가 필요하면 외부 KV(Upstash 류)
1개가 최소 추가분이다. 챗 없는 1단계에서는 불필요하므로 지금 결정하지 않는다.

## 6. 비범위

행동 추적, 추천 엔진, 계정, 푸시 알림, 상품 간 비교 표시, "당신에게 맞는 상품" 계열 문안
(participation-push 확장 대상). 카테고리·공모의 개인화 숨김.
