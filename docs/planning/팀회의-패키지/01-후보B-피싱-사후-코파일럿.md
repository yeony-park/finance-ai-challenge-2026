# 후보 B — 보이스피싱 '사후 골든타임' 대응 코파일럿

> council 4/4 지참 확정. 단 차별화 각 없이는 "동일 주제 참가작 중 1등만 생존"하는 레인.

## 문제 (한 줄)
피해 연 1조원·건당 5,300만원 시대에 탐지 앱은 6종+ 있고 **신고·초동 지급정지 연결은 112 통합신고대응센터(2023-10~, 경찰청+금감원+KISA+통신3사 합동)가 이미 원스톱화했다.** 그러나 **신고 "이후" 피해자가 수 주간 스스로 챙겨야 하는 절차 — 사건사고사실확인원 발급 → 3영업일 내 금융사 서면 피해구제 신청 → 2개월 채권소멸 공고 추적 → 환급 — 를 관리해주는 도구는 없다.** (2026-07-31 검증: fsc.go.kr/no010101/80830, korea.kr 148930266)

## 타깃·채널 (기획서 3번 대응)
- 기본형: 피해(의심) 당사자와 **가족**(대리 대응자), 모바일 웹
- **변형 B×시니어**: 피해자의 53%가 50대 이상 — 큰 글씨·음성 안내·가족 공유 모드 (E 후보 흡수)
- **변형 B×외국인**: 다국어 피싱 대응 부재 (A 후보와 결합)
- → 회의에서 타깃 변형 하나를 고르면 예시 주제 군중과 갈라섬 (차별화 최저비용)

## 서비스 컨셉
의심 문자/통화 내용 붙여넣기 또는 대화형 문진 → ①사기 유형 분류(기관사칭·대출빙자·딥보이스 등) ②상황 판정(송금 전/직후/악성앱 설치) ③**상황별 체크리스트를 실행 단위로 안내** — 지급정지 연락처 원탭, 피해구제신청서 초안 자동 작성, 증거 보전 가이드, 3영업일·2개월 등 이후 일정 타임라인 추적.

## 생성형 AI 역할 (기획서 5번 대응)
유형 분류(few-shot) / 상황 문진 대화 / 공개 절차·사례 RAG 기반 **출처 표시** 안내 / 신청서 초안 생성(사용자 확인 후 확정 — human-in-the-loop).

## 검증된 데이터 (data-first) — API 키 불필요, 전부 공개 문서
- 금감원 보이스피싱지킴이: 사기 시나리오·실제 음성·피해 사례 (fss.or.kr)
- 보이스피싱 통합신고대응센터 절차 (counterscam112.go.kr), 112/1332 체계
- 전기통신금융사기 피해방지 특별법상 피해구제 절차·서식 (법령정보센터)
- 은행별 지급정지 콜센터 연락처 (각행 공개)
- KISA 피싱 URL 목록 (data.go.kr, 선택)

## 하네스 스케치
서브에이전트: 분류기 / 절차 가이드(RAG) / 서류 작성 / 타임라인 관리 + 신뢰 스파인(04) 전체 적용. 안전 규칙: 긴급 상황 판정 시 **"지금 112부터"를 항상 최상단에** (앱이 신고를 대체하지 않음 — 보조수단성 원칙).

## 승산
금보원·정책 어젠다 정면(ASAP, 10대 트렌드) / 공백 실재 (스트림 2·3 교차 확인) / 데이터 완전 공개 / 구현 난도 하 → 완성도 극대화 가능.

## 결정적 리스크 (council)
1. **예시 문구와 동일 → 참가작 몰림.** 타깃 변형 + 실행형 기능(서류 생성·타임라인)으로 "안내 챗봇"들과 갈라서야 함.
2. **정적 플로우차트화** — 절차 안내의 본질상 생성형 AI가 장식으로 전락하기 쉬움 (Skeptic). 문진·서류 생성·개인화가 AI의 존재 이유여야.
3. **오안내 = 실피해 확대** — 심사자가 반드시 찌를 지점. 출처 강제 + "확실하지 않으면 1332 연결"로 방어.
4. ~~전제 재검증 필요~~ → **검증 완료 (2026-07-31)**: 112 통합센터가 '신고·초동 조치'는 원스톱화함. 따라서 이 서비스의 각은 "신고 안내"가 아니라 **"신고 이후 수 주간의 서류·기한·환급 절차 관리"**로 확정. 포지셔닝 필수: 112를 대체하는 게 아니라 **112 신고를 첫 단계로 안내하고 그 이후를 관리**하는 보조 도구 (보조수단성 원칙과도 정합).
