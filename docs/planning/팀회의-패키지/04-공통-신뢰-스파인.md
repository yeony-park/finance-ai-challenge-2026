# 신뢰 스파인 (Trust Spine) — 주제 무관 공통 모듈

> **✅ 구현 착수됨 (2026-07-31)**: `src/lib/spine/` — 테스트 26개 통과, 레드팀 9/9 통과(`docs/redteam/report.md`), 프로덕션 빌드·E2E 검증 완료. 상세: `src/lib/spine/README.md`

> council 만장일치: 후보 C(AI 보안)는 단독 주제로는 사망, **모든 후보에 내장되는 공통 모듈로 전환.**
> "진짜 결정은 무엇을 고르나가 아니라 C를 어디에 붙이나다" (Pragmatist).
> 어느 주제를 골라도 이 모듈이 ①기획서 '기존 앱 대비 차별성'의 공통 답 ②금보원 어젠다(에이전트 보안·레드팀) 가점 ③심사자 인젝션 공격 방어를 담당한다.
> **주제 확정 전에 개발 착수 가능** (주제 독립적).

## 왜 이게 무기인가
- 심사기관(금융보안원)은 AI 레드팀을 직접 운영하며 "금융권 AI가 3·4세대 공격(RAG 오염·도구 조작)에 취약하다"는 보고서를 냈다 → **심사자는 어떤 주제든 인젝션을 찔러볼 것** (Critic)
- 2026-06-22 금융분야 AI 가이드라인 시행 직후 — 7원칙(보조수단성 등)을 실구현한 참가작은 드물 것 → 선점 효과
- 팀 리더의 하네스 엔지니어링(스킬 기반 서브에이전트) 우승 경험이 그대로 재사용되는 슬롯

## 구성 요소

### 1. 출처 강제 RAG (halluci-방어)
- 모든 사실성 답변에 근거 문서·원문 링크 병기, 근거 없으면 "확인 불가 — 공식 채널 안내"로 폴백
- 세 후보 모두 "틀리면 사람이 다치는 정보"(지급정지 절차·비자 요건·보험금) — 상관된 단일 실패 모드를 한 번의 설계로 방어 (Critic)

### 2. 인젝션 가드레일
- 입력 분류(악의 프롬프트 탐지) → 시스템 프롬프트 방어 → **도구 권한 최소화**(에이전트별 최소 스코프, 금보원 '에이전트 권한 검증' 어젠다 직접 대응)
- 출력 필터: 범위 밖 주제(투자 권유 등) 거절

### 3. Human-in-the-loop (가이드라인 보조수단성 원칙)
- 실행성 행동(서류 확정, 외부 연결)은 반드시 사용자 확인 단계를 거침
- UI에 "AI는 보조수단이며 최종 확인은 ○○"를 명시 — 가이드라인 7원칙 매핑표를 기획서 부록으로

### 4. 자체 레드팀 리포트 (차별화 킬러)
- 제출 전 자체 공격 시나리오 N개(인젝션·탈옥·오정보 유도·도구 남용) 테스트 → **결과 리포트를 기획서 자유 항목(7번)에 동봉**
- "저희는 이렇게 공격해봤고 이렇게 막았습니다" — 금보원 심사위원에게 보내는 직통 신호

### 5. 무중단 운영 (9/7~9/11 다운 = 결격)
- 배포: Vercel (서버리스, 콜드스타트 완화 설정) + 헬스체크·알림
- **심사자 동시 접속 대비**: LLM API 크레딧 예산 산정, 레이트리밋(남용 방지 + 크레딧 소진 방지), 캐싱
- 제출 전 부하 테스트 + 5일 모니터링 당번
