공시는 제출에서 끝나지만,
투자는 제출 이후에 일어난다

발행사가 증권신고서에 공시한 주장을 국가 공공 데이터와 자동 대조하고, 제출 이후의 변화를 지속 재검증하는 독립 검증 레이어. 확인 불가능했던 공시 검증을 청약 전 3초~5분으로 단축하고, 문서가 바뀌면 다시 검증해 알린다.

제1항 — 배경

공시가 이제 막 전수로 생겨나는 시장

팩트조각투자는 4년간 규제 샌드박스 특례로 운영됐다. 공시는 플랫폼 자체 채널에 흩어져 있었고, 그 채널에는 무결성 보장이 없었으며, 플랫폼이 사라지면 공시 채널도 함께 사라졌다 — 2026년에만 샌드박스 사업자 6곳 중 2곳(카사·펀블)이 인가 미취득으로 폐업했고, 카사는 2026-08-10 서비스를 종료했다.

팩트2026-07-28 대통령령 제36543호로 조각투자 증권신고서 제출이 전면 의무화됐다(소액공모 특례에서 조각투자증권만 배제). 이제 모든 공모의 주장이 전자공시(DART)라는 불변 원장에 쌓이기 시작한다 — 한번 접수된 문서는 교체할 수 없고, 정정은 새 문서로만 가능하다. 장외거래소 2개사 예비인가(2026-02), 토큰증권법 시행(2027-02)이 뒤따른다. 근거 · law.go.kr 자본시장법 시행령 개정이력 · 금융위 2026-02-13

추론시장은 작다(유통 4사 2024년 연 거래 145억 원). 그러나 공시 의무화 다음에는 그 진위를 검증하는 계층이 별도 산업으로 분화한다 — EU에서 지속가능성 공시 의무화(CSRD) 이후 제3자 검증 시장이 평가 시장보다 빠르게 성장한 선례가 있다. 검증 인프라를 세울 수 있게 된 최초의 시점이 지금이다.

제2항 — 문제

공시는 제출에서 끝난다 — 대조도, 감시도 없다

팩트대조 공백. 공시된 주장(개체 이력번호·공모가· 자금용도)이 사실인지 확인하려면 수십 페이지 비정형 문서를 읽고 공공 데이터를 수작업으로 대조해야 하며, 그 비용이 투자금을 초과한다. 이를 대신하는 제3자는 국내 0곳(혁신금융 1,112건 중 제3자 검증 지정 0건), 비유동 실물자산 기준으로는 해외에도 확인되지 않는다.

팩트감시 공백. 신고서는 제출 후에도 계속 변한다. 정정 시 "정정 전후 대비표"가 법정 서식으로 붙지만, 발행인이 지정한 항목만 수록된다 — 실제 정정신고서에 발행인이 직접 명시한다: "제2부 발행인에 관한 사항에는 정정사항을 본문의 색깔 표시 없이 반영하였으며, 정오표를 별도로 기재하지 않았습니다"(요약정보 동일). DART에는 버전 비교 기능이 없고, 공시 밖 사실(가축 원장·실거래가)의 변화는 애초에 정정 의무 대상이 아니다. 근거 · DART 투게더아트 정정신고서 원문 직접 열람 (rcpNo 20260512000391)

팩트실사용자 전수조사(4개 자산군, 앱리뷰·커뮤니티·언론)에서 확인된 최강 실증이 정확히 이 지점이다: 청약 때 있던 '매입확약' 문구가 청약 종료 후 정정공시 없이 사라진 것을 투자자가 우연히 발견했고(비즈한국 단독 보도, 2024-11 — 샌드박스기 자체 공시 채널), 정산 지연 공지를 "앱을 뒤져보다 우연히 발견"했다(ZDNet 2022). 두 번 모두 '우연히'다 — 도구가 없기 때문이다.

추론병목이 공백을 만든다. 정정을 확인하려면 접수될 때마다 전문을 다시 열어 수십 항목을 눈으로 재대조해야 한다 — 공모당 평균 2.4회다. 이 확인 비용을 감수하는 소수에게 정정 확인은 병목이고, 대다수에게는 확인하지 않는 것이 합리적 선택이 되어 공백이 된다. 그래서 이 제품의 초점은 확인 비용의 붕괴다 — 사용자의 일을 "정정마다 전문 재독·재대조"에서 "알림 한 건 확인"으로 줄여, 병목을 없애는 방식으로 공백을 메운다.

제3항 — 발단

손으로 직접 해봤더니, 일상의 문제였다

실측 ① — 첫 대조에서 불일치가 나왔다

청약을 앞둔 한우 투자계약증권(청약 8/27 개시)의 신고서에 기재된 개체 37두를 국가 축산물 이력 원장과 실호출로 대조했다. 결과 — 36두는 전 항목 일치, 1두는 소유권 이전 기록 없이 다른 농장 소재로 기록. 서비스를 만들기 전 첫 수작업 대조에서 실제 불일치가 발견됐다. 원인(등록 지연·오기 등)은 단정하지 않는다 — 그러나 "확인해볼 가치"는 실증됐다.

근거 · data/snapshots/2026-08-10-bankcow9-37head-trace.json (스냅샷 보존)

실측 ② — 정정은 예외가 아니라 관행이었다

전자공시 API로 투자계약증권 공시 전수(2023~2026)를 집계했다. 98건 중 정정이 64건(65%), 공모당 평균 2.4회. 표본 11건의 대비표를 판독한 결과 정정 내용의 다수가 공모가격 결정 방법·기초자산 가격 산정 근거·투자위험 등 판단 직결 사항이었고, 금융감독원 요구에 의한 정정도 포함돼 있었다. 한 발행사는 작품 가격 산정 근거를 2주 새 세 번 고쳤다. 공시는 "한 번 읽고 끝나는 문서"가 아니라 계속 변하는 살아있는 문서인데, 그 변화를 지켜보는 눈이 시장에 없다.

제4항 — 해결

보존 → 대조 → 감시 → 알림, 공시의 생애주기를 지키는 검증 레이어

제품 결정이 제품은 일회성 검증 리포트 발급기가 아니라 공시의 생애주기 전체를 다루는 검증 레이어다. 심사자와 투자자가 보는 것은 "특정 시점의 검증"이 아니라 "지금 이 순간까지 유효한 검증"이다.

  • 보존 — 모든 공시 버전을 스냅샷으로 저장한다. 발행사·플랫폼이 사라져도 검증 기록은 남는다.
  • 대조 — 주장을 3층위로 검증한다: ① 실재 확인(개체·자산 ↔ 국가 원장) ② 가격 위치(공모가 ↔ 시장 실거래 분포) ③ 이행 이력(발행사 트랙레코드 — 예상 vs 실제, 손실 포함).
  • 감시(정정 재검증) — 정정신고서가 접수되면 같은 검증 엔진을 다시 실행한다. 알림에는 사실 2가지만 담는다: 변경된 항목의 나열, 그리고 재검증 결과 판정의 유지/변동. 중요·안 중요의 등급은 매기지 않는다 — 단정 금지 원칙의 확장이다. 발행인이 대비표에 올리지 않은 변경도 전체 문서 비교로 잡는다. 사람이 하면 몇 시간인 버전 대조·사실 재확인이 알림 한 건 확인으로 준다 — 없애는 것은 기계적 확인 비용이지 판단이 아니다.
  • 알림 + 리플레이 — 관심 공모의 변동을 알리고, 과거의 발견 과정을 스냅샷 diff로 재생한다. 심사 기간 중 실제 변동이 없어도 기능을 증명할 수 있다.

제품 결정AI의 역할 경계 — AI는 비정형 신고서에서 검증 가능한 주장을 추출하고, 검증 가능성을 판별하고, 눈높이 서술을 작성한다(4종 태깅: [확인된 사실]/[발행사 주장]/[계산]/[AI 해석]). 판정 자체는 결정론적 대조가 수행한다. 추출은 규칙 파서와 교차검증하며 불일치 필드는 확인 불가로 강등 — 환각이 판정에 닿지 않는 구조.

제5항 — 핵심 사용자

청약을 검토 중이지만 신고서를 검증할 수단이 없는 개인 투자자

  • 주 사용자 — 조각투자 공모 청약 검토 투자자. 트리거는 신규 공모 공고·청약 개시, 채널은 웹. 이용 목적은 탐색·기초 검토 비용 절감. 출처 · 2026-08-10 인뎁스 인터뷰
  • 차기(로드맵) — 보유 중 투자자의 자산 변동 추적.
  • 대상 아님 — 투자 추천을 원하는 사용자(판정만 제공, 권유·자문 없음), B2B/B2G(확장 항목 서술만 — 최종 인수 주체는 금융기관 리스크·컴플라이언스 부서).

제6항 — 범위와 비범위

MVP가 하는 것과 하지 않는 것

포함 범위 (MVP)

1 · 검증 리포트 2축 — 한우 투자계약증권 라이브 검증(청약 8/27~9/10이 심사 접속 기간 9/7~11과 겹침) + 부동산 수익증권 사후 검증(예상값·실제값 분리 표기).
2 · 3초 판정 첫 화면 — 판정 집계 → 개체 카드 → 상세 → 근거 원문의 단계 공개. 접속 즉시 불일치 사례로 드릴다운되는 동선.
3 · 눈높이 서술 2프리셋 — 초보/숙련 토글, 사전 생성·캐싱, 자유 입력 없음.
4 · 정정 재검증 + 관심 공모 알림 — 위 제4항의 감시 기능. 리플레이 포함.
5 · 익명화 기본 — 발행사명·이력번호·지역 마스킹. 실명 전환은 팀 결정 전까지 없음.

포함하지 않는 범위

자유 대화형 챗봇 / 상품 추천·자문·적정성 단정 / 정정의 중대성 등급(A~D류) 부여 — 사실 대조에서 평가로 넘어가는 선을 넘지 않는다 / 미술품·항공기 엔진 자산군(공개 대조 데이터 미확보 — 로드맵) / 자연어 검색·상품 등급(로드맵) / 플랫폼 웹 크롤링(공시 API만 사용).

범위 결정 근거 · 자문 평결 4회(필요성·방향성·기획서 항목·정정 재검증) + 재구조화안 통합 검토. 최종 합의는 팀 회의에서.

제7항 — 핵심 사용자 흐름

접속→ 공모 선택→ 3초 판정 (36 일치 · 1 미확인)→ 개체 카드 · 근거 원문 병치→ 사용자가 직접 판단→ 관심 등록 · 정정 시 재검증 알림

제품 결정서비스는 판단을 대신하지 않는다. 판정은 일치/원장에서 확인되지 않음/확인 불가 3값뿐이고, 근거 없는 판정은 코드 수준에서 생성이 차단되며, 자료 부족은 부정 판정의 사유가 아니다. 모든 판정에 원문 위치와 조회 시각이 붙는다.
