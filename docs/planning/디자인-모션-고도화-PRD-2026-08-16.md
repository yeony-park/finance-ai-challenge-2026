# 디자인·모션 고도화 PRD (2026-08-16)

> 오너 요청: "kbstarreit.com처럼 애니메이션·사진 배경 수준의 디자인 — 단, 완전 모방이 아니라
> 현재 디자인을 발전시키는 방향". 레퍼런스 실측 분석 → 기술 스택 판정 → 단계별 구현 플랜.
> 근거 스킬: frontend-design-direction(방향 선택·안티패턴), motion-ui(모션 시스템 규율).

## 1. 레퍼런스 실측 — kbstarreit.com (2026-08-16 헤드리스 브라우저 캡처)

**구성**: ① 풀블리드 영상/사진 히어로(로비·건물 실사진, 백색 타이포 오버레이, Scroll 큐,
회전 원형 배지) ② KEY FACTS — 큰 숫자 스탯 타일 8개(옐로 아이콘) ③ 자산 쇼케이스 —
에디토리얼 분할 레이아웃 + 대형 건물 사진 + 배경 스케치 라인아트 워터마크.

**기술 스택 실측**: jQuery + AOS(스크롤 리빌) + `<video>` 1개 + 이미지 32장. 캔버스·3D 없음.
→ **기술적으로는 구식**. 우리 스택(motion/react = Framer Motion 계열, RSC SVG)이 이미 우위.
필요한 것은 라이브러리가 아니라 **연출의 적용 범위**다.

**팔레트**: 흑백 회색 + KB 옐로 악센트 — **JeomJeom의 종이+노랑 체계와 구조 동일**.
레퍼런스가 우리 정체성과 충돌하지 않고, 오히려 "노랑 악센트 + 중립 베이스 + 큰 숫자"
문법이 이식 가능함을 확인.

## 2. 방향 — "데이터와 기록물이 우리의 사진이다"

정체성 교체 금지(council 판정 선례: 시안 v1의 죄 = 다름이 아니라 교체). 종이 문서 톤·노랑
형광펜·판정 3색·mono 메타 체계는 유지하고, KB가 사진·영상으로 채우는 자리를 우리는
**실데이터 도판과 검증 기록물 일러스트**로 채운다.

| KB 요소 | 모방 대신 이식 |
|---|---|
| 실사진·영상 히어로 | **불채택** — 라이선스·익명화 게이트(발행사·농장 식별) 충돌, 기록물 미학과 이질. 대체: 대조 일러스트(공시 문서 ↔ 원장 문서 + 형광펜 하이라이트) 라인아트를 draw-in 애니메이션으로 |
| Scroll 큐·풀하이트 히어로 | 채택 — 히어로를 뷰포트 높이로 확장, mono SCROLL 큐 |
| AOS 스크롤 리빌 | 채택 — 기보유 `Reveal`(whileInView·reduced-motion·hydration 가드)을 리포트 한정에서 전 표면으로 확장 |
| KEY FACTS 큰 숫자 | 채택 — 기존 판정 타일에 **카운트업**(뷰포트 진입 시 0→실값). 최종값 동일·게이지 아님 → 04 집계·판단 유도 경계 비침범 |
| 배경 스케치 워터마크 | 조건부 — 종이 질감·기록물 모티프 대형 라인아트(P4, 오너 반응 후) |
| 회전 배지·장식 모션 | 불채택 — motion-ui 원칙(장식 목적 모션 제거) |

## 3. 기술 스택 판정 — **신규 의존성 0**

| 후보 | 판정 | 근거 |
|---|---|---|
| motion/react (보유) | **유지·확장** | useScroll/useTransform(패럴랙스)·whileInView·카운트업까지 전부 커버. 이미 MotionProvider(LazyMotion)·감속 가드 구축됨 |
| GSAP/ScrollTrigger | 불채택 | motion/react와 스케줄러 중복, 번들 +30kb, 프로젝트 의존성 0 원칙 |
| AOS | 불채택 | Reveal이 상위 호환(hydration·reduced-motion 처리 내장) |
| Lottie/three.js | 불채택 | 용도 없음(장식), 번들 비용 |
| 사진·영상 에셋 | 불채택 | §2. 스톡 사진은 anti-pattern("stock-like atmospheric media") + 라이선스 |
| CSS 스크롤 연동(animation-timeline) | 보류 | 브라우저 지원 불균일 — motion/react로 충분 |

**성능·접근성 게이트**(전 Phase 공통): CLS 0 · transform/opacity만 애니메이션 ·
reduced-motion 전면 폴백(기존 useReducedMotionSafe/CSS 미디어) · LCP<2.5s 유지 ·
landing JS 예산 내(신규 라이브러리 0이므로 위험 낮음) · 실서버 스크린샷 QA(320/768/1280).

## 4. 구현 플랜

- **P1 홈 히어로 개편**: 풀하이트(≈88dvh) 히어로, 우측 대조 일러스트(문서 2장 + 형광펜
  하이라이트 + 대조 화살표 + 검증 스탬프, SVG stroke draw-in ~1.5s, 1회), 콘텐츠 스태거
  인, 하단 SCROLL 큐. 모바일은 일러스트 축소/숨김.
- **P2 스크롤 리빌 전면화**: Reveal을 홈 밴드(로드맵 스텝 스태거 포함)·카테고리 착지
  슬롯에 적용. 스태거 ≤0.06s/항목.
- **P3 숫자 카운트업**: `CountUp` 컴포넌트(SSR=최종값 렌더→뷰포트 진입 시 1회 카운트,
  reduced-motion=정적) — 착지 판정 타일 3개 적용.
- **P4 질감·워터마크** *(오너 반응 후)*: 종이 그레인, 섹션 배경 대형 기록물 라인아트,
  히어로 패럴랙스(useScroll). 경락가 차트의 배경 장식화는 **보류**(가격 인상 규제 검토
  선행 — 기존 결정).
- **P5 마이크로 인터랙션 정리** *(오너 반응 후)*: 카드 호버 리프트 일관화, 리포트 챕터
  내비 현재 위치 표시, 다이얼로그 AnimatePresence 전환.

이번 회차 구현: **P1+P2+P3**. P4·P5는 라이브 반응 후.

## 5. 비범위·규제 메모

- 판정 3색의 장식 사용 금지(모션에서도) — 카운트업 숫자 색은 기존 tone 클래스 그대로.
- 카운트업은 최종값을 바꾸지 않는 연출(집계 점수·게이지 아님) — 표본 감사 무영향.
- 일러스트는 실존 문서·발행사를 특정하지 않는 추상 기록물(익명화 게이트 무관).
- 모든 신규 모션은 "상태 전달·주의 유도·공간 연속성" 중 하나에 복무 — 아니면 제거
  (motion-ui 최종 규칙).
