# IDI 지식 활성화 인터뷰 로그 — 공모전 주제 선정 (2026-07-31)

목적: 리서치(후보 A~E) 완료 상태에서 사용자의 경험·관심·강점을 활성화해 팀 회의에 가져갈 주제안을 준비.

## 0. 씨앗 선언 (verbatim)

> "아까 봤던 AI 보안 쪽도 좋은 거 같아. 외국인 금융정착도 좋은 거 같은데 이건 잘 모르겠어. 너가 후보로 가져온 주제들 다 좋은데 나는 데이터가 확실하고, 구할 수 있는 거라면 어떤 것이든 사실 좋아. 그래서 수상을 목표로 하는 주제 중에 골라보는 게 좋을 것 같긴 한데, 아직은 팀원들과 회의 전이고 그 전에 아이디어들을 가져가는 거라서 다양하게 다뤄봐도 좋을 것 같아."

해석 메모:
- 끌림: AI 보안(C) > 외국인 금융정착(A, 확신 없음)
- 선택 기준: **데이터 확보 확실성** + **수상 가능성**
- 상황: 팀 회의 전 → 단일 확정이 아니라 **복수 아이디어 준비**가 목표

## 1. 자유 회상 — ① 아는 것

Q: 본인·팀에 대해 아는 것을 순서 없이 전부 (전공, 스택, AI 경험, 금융·보안 접점, 팀 구성, 시간)

A (verbatim 요약):
- 응용통계학과 전공
- 희망 진로: AI 엔지니어 + DBA & DevOps
- **올리브영 코파톤 공모전 올리브영 트랙 1위 수상** (최근)
- MLOps K-digital 과정 수료
- 시간: 많이 쓸 수 있음
- 팀: 본인 포함 4명 (대회 최대 인원)
- 자신 있는 것: **LLM/AI로 뭔가 만드는 것**

미언급 (2단계 단서 후보): 팀원 각각의 역량/역할, 금융·보안 도메인 접점 유무, 웹 프론트/배포 경험

Q(당연해서 안 말한 것): 올리브영 코파톤에서 뭘 만들어 이겼는지, 역할은?

A: **"웰니스 기획전 자동화 MVP 시스템 — '올리브베러'. 하네스 엔지니어를 평가하는 대회였던 것 같아."**
→ ★ 해석: AI 에이전트/하네스 엔지니어링으로 자동화 MVP를 만들어 우승한 이력. 이번 대회의 "작동하는 MVP 완성도" 심사축과 정확히 같은 역량. 차별화 후보.

## 2. 단서 회상 — ② 잠자던 기억

Q [cue:사람] 팀원 3명 각각 뭘 하는 사람이고 뭘 잘하나?

A:
- 팀원1: **금융 도메인 현직자** [cue:사람]
- 팀원2: 머신러닝 엔지니어에 가까움 [cue:사람]
- 팀원3: 모름 (팀 회의 때 파악 필요)
- 본인 포함 3명이 같은 MLOps 부트캠프 출신

Q [cue:사람-심화] 금융 현직자는 어느 업권·무슨 업무?

A: **은행**이라는 것만 앎. 개발자인지 여부 등 업무는 모름. [팀 회의 확인 항목]

Q [cue:경험] 보이스피싱·금융사기 접점? 외국인 지인?

A:
- 전화 걸고 **내 목소리만 듣고 끊는 곳** 경험 (→ 보이스 수집/변조 수법 인지) [cue:경험]
- 요즘 **목소리 변조(딥보이스)** 쓰는 것 인지 [cue:경험]
- **공기업 사칭** 사례 인지 [cue:경험]
- **구매 발주서에 대학 이름 넣은 위조** 사례 목격 (문서 위조형 사기) [cue:경험]
- 본인은 모르는 번호 안 받아서 직접 피해 없음
- 외국인 지인: 언급 없음 → 외국인 도메인 개인 접점 부재로 해석 (씨앗의 "잘 모르겠어"와 일치)

## 3. 에피소드 파고들기 — ③ 암묵지

### 에피소드 1: 올리브베러 1위의 결정 요인

Q: 그때 뭘 어떻게 만들었고, 무엇이 1위를 갈랐나?

A: "**하네스 엔지니어링이랑 내 도메인 지식**이 갈랐다고 생각해. 기존에 **올리브영 크루로 일하고 있었거든.** 그리고 **다양한 스킬로 서브 에이전트들을 호출한 게 AI native에서 높은 점수**를 받은 듯."

★ 추출된 암묵 규칙: **"현장 도메인 지식 × AI 네이티브 하네스(스킬 기반 멀티 서브에이전트) = 우승 공식."**
→ 이번 대회 적용: 도메인 지식 슬롯은 본인이 아니라 **은행 현직자 팀원**이 채워야 함. 하네스·멀티에이전트 설계는 본인의 재현 가능한 강점.

### 에피소드 2: "AI 보안이 좋아 보인다"의 실체

Q: 그 생각이 든 순간은? 만들 그림이 떠올랐나, 아니면 멋있어 보여서였나?

A: "네 리서치 요약을 읽다가였어. 뭐 사실 멋있어 보이기도 했고."

→ 판정: **경험·비전에 뿌리내리지 않은 심미적 끌림.** 만들 그림 없음. C 후보는 "하고 싶은 것"이라기보다 "리서치가 좋다고 해서 좋아 보이는 것". 단, 본인의 하네스 엔지니어링 역량이 가드레일·인젝션 방어와 기술적으로 인접하다는 사실은 본인이 언급하지 않음 (연결 인식 없음).

### 에피소드 3: "데이터 확실성 1순위"의 근원

Q: 데이터 때문에 프로젝트가 막혔던 구체적 기억은?

A: "**어떤 프로젝트든 그럴싸한 계획 가지고 데이터를 찾으면 항상 데이터가 없었어. 그래서 차라리 데이터를 먼저 확보하고 주제를 구상하는 게 어떨까 싶어서.**"

★ 추출된 암묵 규칙: **"계획→데이터 순서는 반복 실패했다. 데이터 확보→주제 구상이 옳은 순서다" (data-first 원칙).**
→ 적용: 팀 회의에 가져갈 아이디어는 각각 **검증된 데이터·API 목록을 붙인 형태**여야 함 (스트림 4 카탈로그가 그 역할). 데이터 없는 아이디어는 아예 상정하지 않음.

## 4. 미지 영역 — ④ 모르는 것

### 알고 있는 미지 (known unknowns, 본인 진술)

- **금융 도메인 전반**: "어떻게 흘러가는지, 화두가 무엇인지 아예 모르겠다. 파고들 지점이 생기면 파고들 수는 있는데, 뭘 파야 할지 모르겠다." → 타깃이 정해지면 깊이 팔 수 있는 유형. 필요한 건 '지점 지정'.
- **심사 배점**: 모름 (리서치로도 미공개 확인 — 공식 기준은 "주제 적합성, 부적격 여부" 수준).

### 가설 제시 결과 (unknown unknowns 탐침)

| 가설 | 반응 | 판정 |
|---|---|---|
| 1. 모델 성능 대회가 아니라 서비스 완성도 대회 | "맞는 것 같아" | ①로 승격 |
| 2. 하네스 강점은 어떤 주제든 보안 어필로 변환 가능 | "맞아. **금융 쪽이라 설명 가능한 형태라면 어필 가능**하지 않을까" | ①로 승격 + 본인 확장: **설명가능성(explainability) 각도** |
| 3. 은행 현직자 팀원이 최고의 주제 광맥 | "맞아. 그 사람이 가져오는 지식을 나중에 듣고 판단하면 될 것 같아" | ①로 승격 + 전략 확정: 회의에서 청취 후 판단 |
| 4. 개인 금융데이터 연동 전제 아이디어는 사망 | "맞아" | ①로 승격 |
| 5. 발표 인력 공백 리스크 | **"나 발표 잘해"** | 반례로 기각 — 발표는 본인 담당 가능 (새 ① 지식) |

# Knowledge Activation Map — 2026 금융 AI Challenge 주제 선정 (2026-07-31)

### 씨앗 (verbatim)
"AI 보안 쪽도 좋은 것 같고, 외국인 금융정착도 좋은 것 같은데 잘 모르겠어. 데이터가 확실하고 구할 수 있는 거라면 뭐든 좋아. 수상을 목표로 고르되, 팀 회의 전이라 다양하게 다뤄봐도 좋을 것 같아."

### ① 아는 것 (활성 지식)
- 응용통계 전공, AI 엔지니어·DBA/DevOps 지향, MLOps K-digital 수료
- LLM/AI로 만드는 것에 자신 있음. **발표 잘함**
- 팀 4명: 본인 + 은행 현직자 + ML 엔지니어 + 미상 (3명이 같은 MLOps 부트캠프)
- [승격] 이 대회는 서비스 완성도 대회다 / 하네스 강점은 전 주제에서 보안·설명가능성 어필로 변환된다 / 현직자 팀원이 주제 광맥이다 / 개인 금융데이터 연동 아이디어는 불가하다

### ② 단서로 깨운 것
- ★ **올리브영 코파톤 1위 = '올리브베러'(웰니스 기획전 자동화 MVP), 스킬 기반 서브에이전트 다수 호출로 AI native 고득점** [cue:당연함-질문]
- 보이스 수집 전화·딥보이스·공기업 사칭·발주서 위조 등 최신 사기 수법 인지 [cue:경험]
- 외국인 도메인 개인 접점 없음 (씨앗의 "잘 모르겠어"와 일치) [cue:경험]

### ③ 에피소드에서 추출한 암묵 규칙
- ★ **"현장 도메인 지식 × AI 네이티브 하네스 = 우승 공식"** (에피소드: 올리브베러 — 크루 경험이 도메인 슬롯, 서브에이전트 하네스가 기술 슬롯)
- ★ **"데이터 먼저, 주제는 그다음" (data-first)** (에피소드: 계획 먼저 세우면 데이터가 항상 없었음)
- "AI 보안 끌림"은 심미적 끌림 — 만들 그림 없음. 가설 2 수용으로 해소: 보안은 주제가 아니라 **모든 주제에 얹는 설계 원칙**으로 전환

### ④ 모르는 것 + 처분
- 은행 실무 내부 페인포인트 → **팀 회의에서 현직자 청취** (회의가 리서치 수단)
- 팀원3 역량 / 현직자의 구체 업무 → **팀 회의 확인**
- 심사 세부 배점 → **선언된 가정**: "MVP 완성도 + 주제 적합성 + 차별성 중심" / 대회 게시판 공지·문의 정기 확인 (시간박스: 주 1회 10분)
- 모의(합성) 데이터 시연의 규정상 허용 여부 → **선언된 가정**: 허용으로 가정하되 대회 게시판에서 확인 시도

### 기획 인계 (planning handoff)
**문제 재정의 (before → after)**
- Before: "수상 가능하고 데이터 확실한 주제를 골라서 다양하게 팀 회의에 가져가고 싶다."
- After: **"주제를 '고르는' 게 아니라, 데이터 출처가 검증된 후보 3~4개를 [검증된 데이터·API + 현직자에게 물을 질문 + 하네스·가드레일 설계 스케치]가 붙은 원페이저 패키지로 만들어 회의에 가져간다. 최종 확정은 현직자의 도메인 지식을 들은 뒤. 어떤 주제가 되든 '스킬 기반 멀티에이전트 + 보이는 가드레일 + 설명가능성'을 공통 무기로 쓴다."**

**가정 목록 (구현 중 깨지면 갱신)**
1. 심사 배점 = MVP 완성도·적합성·차별성 중심 (비공개라 가정)
2. 합성/모의 데이터 시연 허용 (게시판 확인 예정)
3. 은행 현직자 팀원의 도메인 지식이 실전 수준 (회의에서 검증)
4. 팀원3이 최소 1개 역할(프론트/디자인/QA) 커버 가능 (회의에서 검증)
