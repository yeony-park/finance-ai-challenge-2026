# 2026 금융 AI Challenge — 종합 리서치 보고서

> 작성일 2026-07-31. 4개 리서치 스트림(정책·주제·수상작·데이터)과 대회 양식 분석을 종합.
> 상세 근거: [stream1 정책·규제](stream1-정책-규제-보안동향.md) · [stream2 주제 딥다이브](stream2-주제별-딥다이브.md) · [stream3 수상작·지형](stream3-수상작-핀테크지형.md) · [stream4 데이터·API](stream4-공개데이터-API.md) · [양식 분석](../competition/양식-분석.md)

## 1. 이 대회의 본질

- **"아이디어 → 모델 → 실서비스"로 진화해온 금융보안원 대회 계보의 2026년판.** 2025년 대상팀의 결정적 차별점이 '시범서비스 실제 구현'이었고, 2026년은 아예 MVP 제출을 의무화했다. **작동하는 데모의 완성도가 제1 심사축.**
- 심사자는 **금융보안원**(보안 기관) + 내부 비공개 심사위원단. 금보원의 2026년 3대 어젠다: ①AI 에이전트 보안(권한 통제·4세대 공격 방어) ②AI 레드팀 ③보이스피싱 공조 대응.
- 기획서 양식이 요구하는 것: **생성형 AI 활용 방안(필수)**, **뾰족한 타깃 고객+채널 선택 이유**, **기존 금융 앱 대비 차별성**. 기능명세서는 심사자가 직접 URL 테스트하는 절차(테스트 계정·샘플 입력·예상 결과)까지 요구.
- 수상 패턴(2024~2026 금융권 대회 공통): **좁은 타깃 × 흩어진 정보의 AI 통합 × 포용금융/보안 어젠다 정렬 × 완성도.** "전 국민 대상 만능 서비스"는 수상 명단에 없다.
- 참가 규모 참고: 2025년 951팀 1,249명(역대 최대). 2026년 현재 참가 440명. 본선은 11팀 내외만 진출 → **상위 ~2.5% 싸움.**

## 2. 승리 공식 (리서치 종합)

1. **좁고 실재하는 페인포인트 하나를 끝까지** — 넓고 어설픈 기능 나열이 아니라, 한 시나리오를 E2E로 완성한 MVP.
2. **생성형 AI가 '장식'이 아니라 '해결의 핵심'** — 기획서 5번 항목을 채우려면 LLM이 비정형 정보(공고문·약관·절차·대화)를 구조화·해석·개인화하는 역할이어야 함. 단순 챗봇 UI는 전 공동개최사가 이미 출시해 차별화 불가.
3. **compliance-by-design** — 2026-06-22 시행된 금융분야 AI 가이드라인 7대 원칙(특히 보조수단성 human-in-the-loop, 보안성)을 설계에 명시 반영. 시행 직후라 실구현 사례가 드물어 선점 효과. 금보원 심사 관점에 정확히 부합.
4. **흩어진 공개 정보의 통합이 안전한 데이터 전략** — 개인 실데이터(마이데이터·오픈뱅킹)는 접근 불가. 공공 API(금융상품한눈에, 서금원, bizinfo, K-Startup, ECOS 등)+공개 문서 RAG+필요시 합성 데이터가 현실적 조합.
5. **심사자 5분 체험 최적화** — 로그인 장벽 없는 데모 모드, 준비된 샘플 시나리오, 9/7~9/11 무중단 배포(Vercel 등).
6. **도메인 리얼리티 보강** — 상위권에 현직 금융사 직원팀 다수. 일반 팀은 실제 절차·규제·통계 인용의 정확성으로 격차를 메워야 함.

## 4. 후보 주제 방향 (우선순위)

### A. 외국인 금융 정착 AI Agent (예시 주제 2) — 균형 최상
- **근거**: 체류 외국인 ~280만 명, 계좌 보유 ~70%. 은행 앱(SOL Global 등)은 자사 상품 안내에 갇혀 있고, **비자 유형별 가능/불가·신용 형성·피싱 대응까지 아우르는 중립 창구 부재**. 스트림 3에서 "혁신금융 트렌드에 언급만 되는 단계"로 확인된 흰 공간. 포용금융 코드 + 은행 공동개최사의 실제 관심사(외국인 고객 유치 경쟁 중).
- **데이터**: 전부 공개 정보(제도·상품·절차) → RAG + 금융상품한눈에 API. 제약 없음.
- **시연 효과**: 다국어 데모 자체가 강렬. 심사자가 바로 체험 가능.
- **변형**: 외국인×피싱 보호 결합(외국인은 피싱에 더 취약하고 다국어 대응 부재) — 금보원 어젠다까지 연결.
- **리스크**: 예시 주제라 경쟁 존재. 다국어 품질 검증 필요.

### B. 보이스피싱 '사후 골든타임' 대응 코파일럿 (예시 주제 3의 좁히기) — 어젠다 정면
- **근거**: 피해 연 1조 원 돌파, 정책 최우선 과제. 탐지 앱은 6종+ 있지만 **"당한 직후 뭘 해야 하나"(지급정지 순서·기기 격리·증거 보전·피해구제 신청)를 안내하는 도구는 공백** — 스트림 2·3 모두 동일 결론.
- **데이터**: 절차·서식·연락처 전부 공개. 사기 시나리오는 금감원 공개 사례+생성으로 확보.
- **리스크**: **공모전 예시 문구와 동일해 참가작 몰림 예상.** '탐지'가 아닌 '대응·회복'으로 확실히 좁히고, human-in-the-loop 설계로 프리미엄을 얹어야 함.

### C. 금융권 AI 보안 대응 비서 / 가드레일 (예시 주제 7) — 참신성·주최 관심 최상
- **근거**: 금보원 AI 레드팀 보고서가 3·4세대 공격(RAG 오염·도구 조작) 취약을 자인, 2026년 레드팀 전담조직 신설. 현장용 '도구'는 초기 단계 = 공백. 프롬프트 인젝션 가드레일 프록시, 대화형 대응 비서, 자동 레드티밍 시뮬레이터 등.
- **데이터**: 공격·방어 데이터 자체 생성 가능 → 외부 의존 zero.
- **리스크**: B2B 서사라 "금융 현안 해결" 체감 전달이 어렵고, 기획서의 '금융 고객·채널' 프레임과 결이 덜 맞음. 주최 기관이 가장 잘 아는 영역이라 어설프면 역효과. 기술 난도도 상대적으로 높음.

### D. 보험 특화 서비스 (예시 밖 흰 공간) — 경쟁 밀도 최저
- **근거**: 생보협회·KB증권이 2026년 신규 공동개최. 보험업 AI 활용은 가능 업무 83개 중 8개뿐(여백 최대). 보험 사각지대 진단, 청구 절차 내비게이션, 약관 해석 등. 참가작 풀에서 희소할 것.
- **데이터**: 표준약관(FINE)·상품 공시 공개. 청구 절차 공개 정보.
- **리스크**: 예시 주제 밖(허용은 됨). 보험 도메인 지식 필요.

### E. 시니어 음성 금융 도우미 (예시 주제 5의 좁히기)
- **근거**: 고령층 디지털 역량 57%, 점포·ATM 급감. 은행 '고령자 모드'는 글씨 확대 수준. 음성 대화형 단계별 안내는 미개척. TECH4GOOD 최우수 2팀 모두 사회적 가치형이라는 수상 정서와 부합.
- **리스크**: 음성 UX 품질 확보 난도. '청년+고령+장애인' 다 담으면 실패 — 한 계층만.

### 탈락: 소상공인 매칭(1) — 2025 대상 재탕+레드오션(각도 바꾸면 재고 가능) / 벤처 성장성 평가(4)·보험사기 탐지(6) — 라벨 데이터 부재로 5주 내 설득력 불가.

## 5. 다음 단계 (IDI 연결)

리서치로 "시장이 원하는 것"은 파악됨. IDI(지식 활성화 인터뷰)에서 확인할 것은 "우리가 잘할 수 있는 것":

1. 후보 A~E 중 사용자의 경험·관심이 실제로 닿아 있는 도메인 (외국인 지인? 보안 배경? 보험 경험? 시니어 가족?)
2. 팀 구성 계획 (1인 vs 팀빌딩, 디자인·발표 역량 포함 여부)
3. 기술 스택 강점 (다국어 처리, 음성, 웹 풀스택 등 — 후보별 요구 역량이 다름)
4. 주당 투입 가능 시간 (5주 × 시간 = MVP 스코프 상한)
5. LLM API 예산 (데모 기간 무중단 서빙 비용 포함)

이후: 주제 확정 → 기획서 골격 → MVP 스코프 → 구현 (권장 배분: 기획 1주 / 구현 3주 / 배포·검증·문서 1주).
