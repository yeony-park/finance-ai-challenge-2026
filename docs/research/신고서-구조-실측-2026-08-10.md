## 판정 1 — 상위 구조는 표준화되어 있다

3사 목차가 사실상 동일하다 (요약정보 → 제1부 모집·매출 → 투자위험요소 → 자금의 사용목적 → 제2부 발행인 …). 금감원 서식 기준이 실제로 지켜지고 있다. **"발행사마다 양식이 제각각"은 사실이 아니며 기획서에 쓰지 않는다.** 섹션 단위 분할은 규칙 파서로 가능하다.

## 판정 2 — 핵심 데이터는 표(TABLE) 안에 있고 기계가 읽을 수 있다

뱅카우 9호: **학산 1~37호 개체별 이력번호·취득가액이 정형 TABLE로 전수 기재.**
9자리 이력번호 37종 확인 (예: 학산 1호 = 212786152, 취득가 4,574,865원).

⚠️ **어댑터 실무 발견**: 기재된 이력번호는 **9자리**. 전국 소 이력번호 체계는 12자리(002 프리픽스)이므로 축산물이력제 API 조회 시 **포맷 변환(002 + 9자리) 검증 필요** — 서비스키 발급 후 첫 호출 테스트에서 확인할 것.

## 판정 3 — 그러나 "검증 가능한 claim"의 종류·형태는 문서마다 다르다

| | 뱅카우 (소) | 데이터젠 (돼지) | 투게더아트 (미술품) |
|---|---|---|---|
| 개체 식별 | 이력번호 표 (37두 전수) | **"이력번호는 표시되지 않으며 도축 단계에서 부여"** — 집합물(월 500두 입식) 관리 방식을 산문 서술 | 작품·작가 정보, 감정 관련은 주석(주1~주5) 산문에 분산 |
| ① 실재성 검증 | ✅ 이력번호 대조 가능 | ❌ **개체 대조 구조적 불가** → ③ 이행 검증만 (기존 계획과 일치) | △ 감정서·전시 이력 — 공공 API 대조 불가 |
| 표 스키마 | 취득가액·사료비·사육관리비 표 3종 | 두수·중량 위주 | 비용 명세 + 주석 산문 |

**같은 '축산'이라도 소와 돼지는 검증 가능 층위가 다르다.** 어떤 주장이 검증 가능한 claim인지, 그것이 표에 있는지 산문에 있는지를 판별하는 것 자체가 문서 이해 문제다.

## 결론 — LLM의 역할 재정의 (기획서 5번 서술용)

- ~~"발행사마다 양식이 달라 LLM이 필수"~~ → **부정확. 폐기.**
- 정확한 논거: **뼈대는 표준이지만, 검증의 알맹이는 발행사·자산군마다 다른 표 스키마와 산문에 흩어져 있다.** "돼지는 이력번호가 없다"는 문장을 읽고 실재성 검증 불가로 라우팅하는 판단은 규칙으로 안 된다.
- 추출 전략: **하이브리드** — 섹션 분할·정형 표는 규칙 파서, claim 식별·산문 추출·검증 가능성 판별은 LLM. 규칙과 LLM이 서로 교차검증하는 구조가 추출 신뢰도 논거가 된다.

## Phase 1 반영 사항

1. 신고서 파서: 섹션 분할은 규칙 기반으로 확정 (실측 근거 확보)
2. 축산물이력제 어댑터: **9자리→12자리 이력번호 포맷 변환 검증** 추가
3. 데이터젠(돼지)은 ① 실재성 대상에서 명시 제외, ③ 공시 이행 검증 전용 유지
4. claim 스키마에 "검증 가능성 판별" 필드 추가 (검증 가능 / 대조 데이터 없음 / 구조적 불가)
