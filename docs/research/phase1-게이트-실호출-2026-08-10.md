## 어댑터 구현 계약 (Phase 1 코드 반영 사항)

1. **존재 판정은 `infoType=1` 아이템 유무로** — `resultCode=00`은 미존재 번호에도 반환됨 (빈 `<items/>`). resultCode 판정 시 전량 통과 오탐.
2. **이력제 API는 serviceKey를 검증하지 않음** (실측: 엉터리 키도 정상 응답). 키 회귀 테스트는 키를 검증하는 경락가 API에 걸 것.
3. `items`는 `infoType`(1 개체 / 2 사육지 / 3 도축 / 5 백신 / 7 검사) 혼합 평면 배열 — infoType 분기 후 타입별 매핑. 정적 스키마 파싱 금지.
4. 선택 필드(`lsdYmd` 등)는 빈 값이 아니라 **태그 부재** — `findtext()` + 기본값.
5. 사육지 이력은 미정렬 — `regYmd` 정렬 후 최종 레코드 = 현 사육지, `infoType=1`의 `farmNo`와 교차 검증.
6. 날짜 대조는 윈도 판정 (신고서 취득시기 ~ +30일 내 양수등록) — 36두 전부 취득시기와 양수등록일(7/30 일괄)이 최대 16일 어긋남. 완전일치 판정은 전량 오탐.
7. 가격 대조는 ±2% 밴드, 농장 대조는 `farmNo` 완전일치 + 대표자명/주소 부분일치 이중 확인.
8. 이력번호 정규화(9자리 → `002` prefix)는 어댑터 진입점에서 강제. 응답 `cattleNo`는 `410002`+9자리 15자리.
9. 두 API 모두 **http 평문** — 클라이언트 HTTPS 강제 옵션 해제 필요. 서비스키 이중 URL 인코딩 금지.
10. 경락가 일 1,000건 — 월 단위 집계 캐싱, 동일 기간·조건 재호출 금지 (응답에 파라미터 에코백 있어 캐시 키 재구성 가능).
