## 1. 제품 정의

DAKER는 조각투자 상품을 단순 나열하는 서비스가 아니다. 공모가격이 주변 또는 유사 거래와 비교해 설명 가능한지, 실물과 권리관계가 독립 자료로 확인되는지, 사업자가 과거 공시와 청산 약속을 이행했는지를 원문 근거로 보여주는 실사 대시보드다.

제품이 답해야 하는 질문은 다음과 같다.

- 지금 신규 매수 또는 청약이 가능한 상품인가?
- 공모금액과 실제 취득금액은 얼마인가?
- 부동산의 토지·연면적 단가는 주변 거래와 얼마나 차이 나는가?
- 비교 대상으로 쓸 만한 거래가 충분한가?
- 건물의 주소·면적·준공일과 소유·권리관계를 독립 자료로 확인했는가?
- 미술품 작가에게 실제 경매 트랙레코드가 있는가?
- 동일 작품 또는 유사 작품의 낙찰가와 공모가격은 얼마나 차이 나는가?
- 발행사가 운용·배당·매각·청산 약속을 실제로 이행한 사례가 있는가?
- 근거가 부족하거나 오래된 경우 투자 판단을 멈춰야 하는가?

## 2. 문제 정의

[확인된 문제]

- 상품 페이지에는 공모 설명과 운영사 자료가 있지만 소비자가 주변 실거래, 작가 경매 이력, 사업자 청산 이력을 각각 찾아 대조해야 한다.
- 부동산은 토지면적과 연면적 중 어떤 기준을 사용하느냐에 따라 가격 신호가 달라질 수 있다.
- 미술품은 작가명이 같아도 작품 연도·크기·재료·진위·소장이력(provenance)·경매 lot이 다르면 직접 가격 비교가 어렵다.
- 공시 자료가 존재해도 현재 거래 가능 상태, 외부감사 여부, 자료 기준일이 분리되지 않으면 최신 사실로 오인하기 쉽다.

## 3. 목표와 비목표

### 목표

- 공식 원문, 검증 저장본, 계산 결과를 화면에서 구분한다.
- 모든 핵심 수치에 출처 URL과 기준일을 연결한다.
- 표본 수, 현재성, 작품 식별 신뢰도를 반영해 가격·위험 경고를 계산한다.
- 외부 데이터 호출이 실패하면 검증된 저장본으로 안전하게 전환한다.
- 상품·지역 설정을 바꿔 다른 SOU 부동산 상품에도 재사용할 수 있게 한다.

### 비목표

- 개인별 매수·매도 추천
- 목표 수익률 또는 원금 보장 약속
- 공식 감정평가나 법률상 권리검증 대체
- 근거가 부족한 추정 시세 생성
- 음악 저작권 조각투자 분석

## 7. 비교·판정 규칙

### 7.1 부동산 비교 규칙

1. 해제 거래가 있으면 원행과 해제행을 모두 제거한다.
2. 지분 거래를 제외한다.
3. 동일 날짜·금액·면적의 주용도 중복행은 하나의 거래로 병합한다.
4. 넓은 표본은 같은 법정동, 일반건축물 전부 거래, 토지면적 0.5~2배, 연면적 0.25~4배를 사용한다.
5. 엄격 표본은 넓은 조건에 더해 건축HUB 용도·VWorld 용도지역 확인, 연면적 0.5~2배를 요구한다. 다중 필지 PNU가 하나라도 확인되지 않으면 엄격 비교를 차단한다.
6. 엄격 표본 0~4건이면 `자료 부족·가격 적정성 판정 보류`다.
7. 엄격 표본 5~9건은 표본 강도 `낮음`, 10건 이상은 `중간`이다.
8. 토지와 연면적 기준의 20% 경고 신호가 다르면 판정을 보류한다.
9. 넓은 표본은 방향 확인용이며 최종 가격 판정에 쓰지 않는다.

### 7.2 미술품 비교 규칙

1. 작가, 연도, 재료, 크기, 작품명, 소장이력(provenance)·경매 lot을 분리해 확인한다.
2. 동일 작품 근거가 있어도 식별번호가 없으면 신뢰도를 낮춘다.
3. 유사작 중앙값은 같은 통화끼리만 계산한다.
4. 환율 기준일이 없으면 KRW와 USD를 합산하지 않는다.
5. 취득가와 발행비 합계가 공모가와 일치하는지는 비용 연결 검증일 뿐 가격 적정성 검증이 아니다.
6. 보유·처분 확인일이 180일을 넘으면 현재 상태 재확인을 요구한다.
7. 다른 작품 한 건만으로 저평가·고평가를 확정하지 않는다.

## 8. 핵심 화면 요구사항

### 상품 목록

- 자산 유형, 상품명, 현재 상태를 표시한다.
- 상품명, 주소, 작가명, DART 접수번호 검색을 지원한다.
- 검색 결과가 바뀌면 상세와 사업자 이력도 같은 상품으로 바뀌어야 한다.

### 부동산 상세

- 주소, 토지·연면적의 ㎡와 평, 공모·취득가를 표시한다.
- 감정가, 임대료, 미납, 순이익, 배당 원데이터를 저장한다. 연환산 수치는 2026-08-10 IDI 결정에 따라 원데이터에 보존하고 UI에는 표시하지 않는다.
- 실존·소유·권리 독립 확인 상태를 별도 경고로 표시한다.
- RTMS 실시간 표본과 5년 저장본을 섞지 않고 별도 표로 표시한다.
- 표본 수, 중위값, 단가 차이, 판정 보류 이유를 표시한다.

### 미술품 상세

- 작가, 작품명, 연도, 재료, 크기를 표시한다.
- 낙찰가·취득가·발행비·공모가의 연결을 표시한다.
- 작가 출품·낙찰·낙찰률·낙찰총액을 표시한다.
- 비교작별 날짜·크기·경매사·통화·원문 링크를 표시한다.
- 동일 작품 신뢰도와 다른 작품 비교 한계를 표시한다.

### 사업자 이력

- 발행·처분·청산 사례를 기준일과 함께 표시한다.
- 감사의견, 손실, 자본, 준비금을 표시한다.
- 준비금이 원금보장이 아니라는 경고를 표시한다.
- 각 사업자의 원문 링크를 표시한다.

### 플랫폼 트랙레코드·적합성 테스트

- 메인, 검색 결과, 적합성 테스트 자료를 각각 `index.html`, `search.html`, `suitability.html`로 분리한다.
- 아트앤가이드, 아트투게더, TESSA를 출처별로 분리하고 저장 건수·검증 시점을 표시한다.
- 기본 상품 8건과 플랫폼 자체 게시 저장본 338건을 합친 346건을 하나의 검색 인덱스로 연결한다.
- 검색어·자산 분류·상태 조건이 없으면 등록 자료 카드와 페이지 이동을 표시하지 않는다. 검색 뒤에는 일치 레코드만 큰 카드로 표시한다.
- 작가명, 작품명, 상태, 식별자를 검색하고 출처별 상태 filter와 12건 단위 페이지 이동을 제공한다.
- 선택 레코드의 정규화 필드와 개인정보 제거 원값 JSON을 모두 확인할 수 있어야 한다.
- 아트앤가이드 `EXPECTED_TRANSFER`의 `soldMoney : 0`은 0원 매각으로 표시하지 않는다.
- 아트투게더 금액 필드는 currency code가 없고 timestamp에는 timezone offset이 없으므로 통화·시간대를 임의로 붙이지 않는다.
- TESSA의 공시 기재 수익률과 `[DAKER 계산]` 단순 세전 정산수익률을 분리하고, 게시판 등록시각의 timezone을 임의로 붙이지 않는다.
- 적합성 테스트 10문항과 각 2개 선택지, 현재 client 정답 위치를 읽기 전용으로 표시한다. radio, 제출 button, 완료 API 호출은 만들지 않는다.
- 회원 이름·연락처·주소·계좌·세션·개인 답안·개인 만기일, 작가의 상세 인물 프로필은 저장·표시하지 않는다.
- 플랫폼 자체 게시값이며 외부 거래 원자료·법률 정답을 독립 검증하지 않았다는 경고를 화면에 고정 표시한다.

## 9. 시스템 요구사항

- Python 표준 라이브러리만 사용한다.
- 서버는 `127.0.0.1:8000`에만 bind한다.
- `/api/catalog`가 상품·사업자·출처 상태를 하나의 JSON으로 반환한다.
- `/api/track-records/artnguide`, `/api/research/weshareart`, `/api/track-records/tessa`가 검증 저장본만 반환한다.
- `/api/catalog.api_status.products[상품 ID]`가 상품별 API 상태를 반환한다. 한 상품의 실패가 다른 상품의 상태를 바꾸지 않아야 한다.
- SOU·RTMS·건축HUB·VWorld 성공 결과는 상품·필지별 24시간 cache에 둔다.
- `data/sou_property_configs.json`은 상품 ID·SOU ID·PNU·법정동·RTMS 지역을 검증한다. 중복 ID/PNU, PNU와 필지코드 불일치, 상품 누락은 시작 시 거부한다.
- 외부 응답은 허용 호스트(host)·HTTPS·최종 경로(path)·응답 크기·스키마(schema)·날짜·숫자 범위를 검증한다.
- RTMS는 CP949와 CSV header를 검증하고 손상 행을 가격 계산에 사용하지 않는다.
- 외부 호출이나 schema 검증 실패 시 API 전체를 실패시키지 않고 저장본을 반환한다.
- 정적 서버는 고정 allowlist의 HTML·CSS·JavaScript·검증 JSON만 제공한다. `/live`는 13개 파일과 `js`, `data` 디렉터리만 허용한다.
- API 응답에는 `no-store`, CSP, `nosniff`를 적용한다.

## 10. 성공 기준

- 캡처에 있던 fixture 안내·데모 표본 영역이 없어야 한다.
- 부동산과 미술품 상세에서 단순 나열이 아닌 계산 결과와 경고가 보여야 한다.
- 모든 핵심 숫자에 원문 링크와 기준일이 있어야 한다.
- 실시간 값과 저장본을 사용자가 구분할 수 있어야 한다.
- 표본 부족·거래 중단·현재성 만료·식별 불충분 상태에서는 매수 판단을 내리지 않아야 한다.
- SOU, 상업·업무용 RTMS, 토지 RTMS, 건축HUB, VWorld NED, OpenDART 원문을 secret-safe smoke test로 확인해야 한다.
- 데이터 검증, JavaScript 계산 테스트, Python 회귀 테스트가 통과해야 한다.
- 데스크톱과 390px 모바일에서 문서 전체 가로 넘침이 없어야 한다.
- 세 출처의 트랙레코드·공시 합계 338건과 적합성 테스트 10문항이 저장본에서 누락 없이 로드돼야 한다.
- 트랙레코드 출처·상태 filter, 검색, 페이지 이동, 상세 원값 펼치기가 데스크톱과 390px 모바일에서 작동해야 한다.
- 회원·세션·개인 답안·개인 만기일 값과 UTM 추적 매개변수가 source JSON·`/live`·화면에 없어야 한다.
