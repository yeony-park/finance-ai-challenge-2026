# 제품 목표와 팀 범위

## 한 문장 목표

우리는 미술품·부동산·가축(한우·돼지) STO의 공시와 실물·시장 근거를 연결해, 금융소비자가 확인된 사실과 남은 위험을 구분하도록 돕는 AI 플랫폼을 만든다.

제품명은 **JeomJeom**이다.

## 문제 정의

STO 상품 정보는 공시, 발행사 자료, 실물 이력, 공공 데이터, 가격 지표에 흩어져 있다. 사용자는 다음을 직접 찾아 대조해야 한다.

- 공시에 적힌 기초자산이 외부 근거의 대상과 같은가?
- 금액, 수량, 상태, 기준일이 서로 일치하는가?
- 공모 설명과 독립 근거가 충돌하거나 누락된 부분은 무엇인가?
- 지금 판단하기에 근거가 충분한가, 아니면 확인을 멈춰야 하는가?

## AI의 역할

AI는 투자 결론을 대신 내리지 않는다.

1. 공시와 문서에서 사실 필드를 구조화한다.
2. 식별자와 기준일을 이용해 외부 근거를 연결한다.
3. 일치, 불일치, 누락, 현재성 만료를 분류한다.
4. 근거가 연결된 쉬운 설명을 만든다.
5. 미확인 항목을 발행사 또는 운영사에 물어볼 질문으로 바꾼다.
6. 사용자가 수정할 수 있는 검토 노트를 만든다.

## 공통 evidence 최소 구조

자산별 데이터 모델이 정해질 때도 다음 필드는 유지한다.

| 필드 | 의미 |
| --- | --- |
| `claim` | 검토할 공시·상품 주장 |
| `value` / `unit` | 원문 사실값과 단위 |
| `source_url` | 원문 또는 공식 출처 |
| `as_of` | 사실의 원문 기준일 |
| `fetched_at` | 시스템 수집 시각 |
| `subject_id` | 상품·건물·개체·작품 식별자 |
| `status` | 확인, 대조 필요, 미확인, 현재성 만료 |
| `method` | 원문 파싱, 수기 정규화, 계산 등 취득 방식 |
| `limitations` | 이 근거로 판단할 수 없는 범위 |

## 자산별 초기 검토 질문

### 부동산

- 공모가, 취득가, 발행비가 분리되어 있는가?
- 건축물 주소, 용도, 토지·연면적, 사용승인일이 일치하는가?
- 비교거래는 법정동·용도·면적 조건을 충분히 만족하는가?
- 등기·소유권·근저당·신탁관계가 독립 근거로 확인됐는가?

### 한우

- 공시의 개체 식별자와 이력 근거가 같은 대상을 가리키는가?
- 사육, 위탁, 보험 증빙의 발급기관과 기준일이 확인되는가?
- 수량, 상태, 비용, 정산 조건에 불일치가 있는가?
- 가격 근거의 축종, 등급, 지역, 시점 조건이 맞는가?

### 돼지

- 질병 발생일, 축종, 시군구가 상품 농장과 직접 연결되는가?
- 이동제한 또는 도축물량의 공식 근거가 있는가?
- 사건 전후 가격 데이터의 품목, 단위, 기간이 일관적인가?
- 같은 기간의 가격 변화를 질병의 인과 효과로 과장하고 있지 않은가?

### 미술품

- 작가, 작품명, 연도, 재료, 크기와 증권 식별자가 일치하는가?
- 감정서, condition report, provenance의 식별번호와 발급기관이 공개됐는가?
- 현재 소유, 보관, 보험 상태의 확인일이 최신인가?
- 확인되지 않은 내용을 추정하지 않고 다음 질문으로 전환하는가?

## 제품 경계

### 제공

- 공시·공식 데이터 구조화와 원문 연결
- 근거 간 대조와 불일치·누락 탐지
- 기준일과 현재성 경고
- 쉬운 설명, 확인 질문, 개인 검토 노트

### 제공하지 않음

- 개인화된 매수·매도 추천
- 수익률·가격 예측 또는 원금 보장
- 공식 감정평가, 진위 판정, 등기·법률 검토 대체
- 근거 없는 시세와 인과관계 생성
- 이용조건을 확인하지 않은 사이트의 자동수집

## 참고 자료 상태

- `yeonjeong` 브랜치의 미술품 검토 자료를 참고했으나, Copilot 명칭과 대화형 UI는 돼지 페이지에만 사용한다.
- 부동산 Notion 링크는 2026-08-10 현재 연결된 Notion 워크스페이스에서 `NOT_FOUND`로 반환되어 상세 내용을 확인하지 못했다.
- Downloads의 `공시대조검증 기획서.html`은 macOS 폴더 접근 권한 때문에 읽지 못했다.
- 따라서 현재 부동산·한우 화면은 교체 가능한 초기 정보 구조이며, 원문 접근 후 상세 요구사항을 보강해야 한다.
