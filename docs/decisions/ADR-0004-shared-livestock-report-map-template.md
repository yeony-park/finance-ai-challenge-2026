# ADR-0004: 축산 리포트 공통 지도 템플릿과 지연 로딩

- **Status:** Superseded
- **Decision date:** 2026-09-01
- **Supersedes:** None
- **Superseded by:** [ADR-0005](./ADR-0005-kakao-only-livestock-map-rendering.md)

## Context

한우와 한돈의 검증 화면에는 공고와 관련된 질병 현황을 보여 주는 지도가 반복해서 필요하다. 한우 공고들은 같은 최신 질병 데이터 지도를 공유하면서 공고별 관련 지역과 기준일만 달라질 수 있고, 카테고리마다 지도 주변에 덧붙일 안내·근거·추가 필드도 다를 수 있다.

기존 구현은 한우 화면이 한돈 이름과 스타일을 가진 지도 컴포넌트를 직접 재사용했고, 섹션별 제목·본문 폭·간격을 각 컴포넌트가 따로 관리했다. 또한 상세 탭은 선택된 패널만 DOM에 보이지만 서버 컴포넌트 데이터와 RSC payload는 페이지 진입 시 함께 준비되므로, 지도처럼 무거운 클라이언트 코드와 데이터에 별도의 지연 로딩 경계가 필요했다.

## Decision

축산 검증 화면에 공통 `ReportSectionFrame`과 `DiseaseMapFrame`을 둔다. 공통 프레임이 제목 크기, 설명, 본문 폭, 여백과 추가 콘텐츠 위치를 정하고, 카테고리 전용 내용은 명명된 `additionalContent` 슬롯과 자식 콘텐츠로 주입한다.

질병 지도는 `LazyLivestockDiseaseMap`이라는 공통 진입점을 사용한다. 고정 높이 로딩 프레임을 먼저 표시하고, 지도 영역이 뷰포트에 가까워질 때 축산 지도 클라이언트 번들 및 `/api/livestock-disease-map?species=cattle|pig` 데이터를 로드한다. API는 축종별 공통 최신 데이터셋을 반환하며, 한우 리포트에서는 공고 지역과 신고서 기준일을 지도 표현 단계에서 강조·필터링한다.

현재 해시 기반 리포트 탭 구조는 유지한다. 지도 이외 서버 섹션의 진정한 탭별 데이터 지연 로딩은 별도 라우트 세그먼트 설계가 필요한 후속 작업으로 남긴다.

### Decision basis

- **User-confirmed:** 한우·한돈 모든 리포트에 질병 지도를 넣고, 한우에서 공유하는 업데이트 지도를 재사용 가능한 템플릿처럼 만든다.
- **User-confirmed:** 카드 상세는 탭이 분리되어 있으므로 지연 로딩해도 된다.
- **User-confirmed:** 카테고리별 추가 항목은 달라도 큰 틀의 폰트 크기와 구성을 동일하게 유지한다.
- **Inferred:** 빈 공간은 완전히 비우기보다 고정 높이 로딩 상태를 보여 주는 편이 레이아웃 이동을 막고 로딩 중임을 명확히 한다.
- **Inferred:** 현재 정적 생성과 해시 탭 계약을 깨지 않는 최소 변경으로 우선 지도 번들과 데이터만 뷰포트 기반 지연 로딩한다.

## Alternatives considered

| Alternative | Benefits | Costs / risks | Why not selected |
| --- | --- | --- | --- |
| 한우·한돈별 지도 컴포넌트를 각각 유지 | 카테고리별 수정이 자유로움 | 레이아웃·로딩·오류 처리·지도 SDK 코드가 중복되고 디자인이 쉽게 어긋남 | 사용자가 공통 템플릿을 요청함 |
| 지도 데이터를 모든 페이지의 서버 props에 포함 | 초기 구현이 단순하고 별도 API가 없음 | 미선택 탭에도 전체 데이터와 직렬화 비용이 포함되고 공유 최신 데이터의 캐시 경계가 불명확함 | 지도 영역 진입 시 필요한 데이터만 요청하도록 분리함 |
| 모든 상세 탭을 즉시 라우트 세그먼트로 전환 | 서버 데이터까지 탭별로 완전 지연 로딩 가능 | URL·정적 파라미터·내비게이션·테스트 계약이 크게 바뀌며 현재 요청보다 범위가 큼 | 우선 공통 프레임과 가장 무거운 지도 경계를 해결함 |
| 카테고리별 추가 필드를 공통 스키마에 모두 고정 | 렌더러 하나로 단순화 가능 | 카테고리 고유 정보가 빈 필드나 조건문으로 누적됨 | 공통 외곽과 명명된 확장 슬롯을 분리함 |

## Rationale

지도 외곽, 로딩 상태, 데이터 계약을 공유하면 한우와 한돈의 화면 밀도와 상호작용을 한 곳에서 맞출 수 있다. 축종은 API 파라미터로만 나누고 공고별 맥락은 표현 단계에서 적용하므로, 같은 최신 지도 데이터셋을 여러 리포트가 중복 보유하지 않는다.

동시에 카테고리 고유 항목을 슬롯으로 열어 두면 공통 틀을 복제하지 않고 필요한 정보만 추가할 수 있다. 뷰포트 기반 로딩은 현재 해시 탭 구조를 유지하면서 초기 페이지에 지도 SDK, 지도 렌더러와 질병 데이터가 포함되는 비용을 줄이는 가장 작은 변경이다.

## Consequences

### Positive

- 한우·한돈 질병 지도가 동일한 제목, 여백, 로딩·오류·빈 상태와 접근성 계약을 사용한다.
- 축종별 최신 질병 데이터가 하나의 캐시 가능한 API 경계에서 제공된다.
- 지도 코드와 데이터는 사용자가 해당 영역에 가까워질 때만 로드된다.
- 카테고리별 안내, 출처와 추가 필드를 공통 레이아웃을 복제하지 않고 추가할 수 있다.
- Kakao 지도 키가 없는 환경에서도 같은 프레임 안에 SVG 대체 지도를 제공한다.

### Negative / tradeoffs

- 한돈은 아직 별도 `/offers/pig-*` 리포트 라우트가 없어 기존 긴 상세 화면 안에서 공통 지도 프레임만 사용한다.
- 현재 해시 탭 구조에서는 지도 외 서버 데이터가 여전히 최초 RSC payload에 포함된다.
- `IntersectionObserver` 경계와 동적 import가 추가되어 지도 로딩 상태가 하나 더 생긴다.
- 공통 스타일 변경이 한우와 한돈 양쪽에 동시에 영향을 준다.

## Guardrails

- 공통 프레임은 시각적 계약만 소유하고 카테고리별 데이터 해석을 포함하지 않는다.
- 축종별 API 파라미터는 `cattle`과 `pig`만 허용하며, 불명확하거나 중복된 값은 `400`으로 거절한다.
- 공개 지도 응답에는 정책상 허용된 질병명·발생일·축종·시도·시군구·대표 좌표만 포함하고, 내부 식별자·발생 두수·출처 URL·농가 식별 정보는 노출하지 않는다.
- 지도 응답은 스냅샷 기준일과 ETag를 제공하고 브라우저·공유 캐시의 fresh 기간을 5분으로 제한한다.
- 지도 로딩 중에는 고정된 최소 높이와 `aria-busy` 상태를 유지한다.
- 공고별 날짜·지역 필터는 공유 원본 데이터를 변형하지 않고 표현 단계에서 적용한다.
- 카테고리 전용 콘텐츠는 `additionalContent` 슬롯을 사용하고 공통 프레임 CSS를 복제하지 않는다.
- 다른 서버 탭의 지연 로딩은 URL 및 정적 생성 계약을 함께 설계하기 전 임시 클라이언트 fetch로 우회하지 않는다.

## Validation

- 한우 리포트의 질병 탭을 열기 전에는 지도 컴포넌트가 마운트되지 않고, 탭 선택 후 공통 로딩 프레임을 거쳐 지도와 통계가 표시되어야 한다.
- 한돈 상세 페이지에서는 질병 영역 근처로 스크롤하기 전 지도 컴포넌트가 마운트되지 않아야 한다.
- 한우 응답은 구제역·럼피스킨병, 한돈 응답은 아프리카돼지열병·구제역 데이터를 반환해야 한다.
- 잘못된 축종 파라미터는 캐시되지 않는 `400` 응답을 반환해야 한다.
- Kakao 키가 없는 로컬 환경에서도 SVG 대체 지도와 범례가 화면 폭을 넘지 않아야 한다.
- 공통 리포트 프레임을 사용하는 기존 요약·신고서·정정·이행·실재성 섹션의 테스트가 유지되어야 한다.
- lint, TypeScript 검사, 전체 테스트와 Next.js build가 모두 성공해야 한다.

## Revisit triggers

- 한돈 공고가 `/offers/pig-*` 검증 리포트와 공통 탭 내비게이션으로 전환될 때.
- 지도 외 상세 섹션도 실제 데이터 요청 비용 때문에 탭별 서버 지연 로딩이 필요해질 때.
- 질병 데이터가 정적 스냅샷이 아닌 외부 실시간 소스로 바뀔 때.
- 한우·한돈 이외 축종 또는 서로 다른 지도 투영·레이어가 필요해질 때.
- 최신 전국 현황과 공고 당시 맥락을 동시에 겹쳐 보여 주는 별도 시각 계층이 필요해질 때.
