# 디자인 방향 — 약관 위험조건 검증 데모 UI

> 2026-08-08. frontend-design-direction 프레임 + 레퍼런스 리서치 2트랙(핀테크 신뢰 UI 12건 · 문서 어노테이션 UI 17건) 종합.
> 적용 대상: `src/app/page.tsx` 데모 UI의 다음 이터레이션.

## 1. 디자인 방향 (스킬 5문항)

| 항목 | 결정 |
|---|---|
| **Purpose** | 약관 문서 위에 검증 결과를 얹어 보여주는 도구. 첫 화면이 곧 제품(3탭 → 스캔 결과) — 마케팅 히어로 없음 |
| **Audience** | 1차: 심사위원(금융보안원·금융권, 5분 체험) — 정확성·근거 검증 동선이 최우선. 2차: 금융 초보자·시니어 — 쉬운 말 병기·큰 활자 |
| **Tone** | **문서적(documentary) + 절제된 신뢰**. 화려함 대신 공시 자료의 권위 + 리걸테크의 정밀함. 놀이 요소 없음 |
| **Memorable detail** | **"조항 카드" 시그니처** — 세리프 약관 원문 + 노란 하이라이트 + 우측 근거 주석의 좌우 분할 카드 (8/2 검토서 HTML의 히어로 데모를 제품 UI로 승격) |
| **Constraints** | Next.js + Tailwind 4, 모바일 웹 우선(심사 요건), 색각 접근성(등급 3중 코딩), fake 모드 데모 안정성, 신뢰 스파인 고지 문구 상시 |

## 2. 디자인 언어 (내부 레퍼런스 = 8/2 주제검토서 HTML)

검토서가 이미 팀이 승인한 시각 언어를 갖고 있다 — 그대로 토큰화한다:

```css
--paper: #F4F5F2;      /* 배경 — 종이 */
--card: #FFFFFF;
--ink: #1C2431;        /* 본문 */
--ink-soft: #5A6472;
--line: #DBDED6;
--hl: #FFE14D;         /* 하이라이트 — 편차 구절 전용 */
--danger: #B93A32;     /* 경고 */
--caution: #B97A1E;    /* 주의 (신규 — 명도 분리) */
--ok: #2F7A5B;         /* 정상/참고 */
--serif: 'Noto Serif KR';   /* 약관 원문 전용 */
--sans: 'Noto Sans KR';     /* UI 크롬 */
--mono: 'IBM Plex Mono';    /* 조항 번호·메타·출처 */
```

**서체 3층위 규칙** (양 트랙 공통 결론): 약관 원문 = 세리프(문서성) / UI·판정 = 산세리프 / 조항 번호·페이지·메타 = 모노. 세 층위가 서체만으로 구분되면 "문서 위에 시스템이 얹혀 있다"는 레이어가 생긴다. 세리프 대안: [마루 부리](https://noonnu.cc/en/font_page/487)(화면 최적화, OFL).

## 3. 화면 구조 결정 (레퍼런스 → 적용)

### 결과 화면 위계 — "종합 1 + 조항 N" ([ToS;DR](https://tosdr.org/en) 구조)
1. 상단: 상품명 + **종합 요약 스트립**(경고 n · 주의 n · 참고 n + 스캔 커버리지) — 뱅크샐러드식 "요약 → 카드 → 근거" 3단 드릴다운
2. 본문: 조항 카드 리스트(등급순) — 카드 = 한 줄 결론 → 펼치면 근거·diff·원문
3. "이 약관에서 표준과 일치하는 조항" 섹션 병기 — 위험만 나열하지 않기 ([CoverageCheck](https://www.insurance.com/coverage-check-insurance-policy-analyzer/)의 균형 리포트 인상)

### 조항 카드 (시그니처)
- 좌: 세리프 원문 + `--hl` 하이라이트 / 우(모바일: 하단): 등급 배지 + 근거 카드 — 검토서 히어로 데모 레이아웃
- 근거 카드 구성: 법령 조문 + 유형 라벨 + 심결례 연결 ([앨리비](https://allibee.ai/) 근거 구성) + **"원문 조항 보기" 토글 = Audit Trail** ([Smashing — AI Transparency](https://www.smashingmagazine.com/2026/05/practical-interface-patterns-ai-transparency/))
- **양방향 연동**: 하이라이트 클릭 ↔ 근거 카드 포커스 ([Hypothesis](https://web.hypothes.is/help/overview-of-the-hypothesis-system/) 패턴). 데스크톱 우측 마진, 모바일 바텀시트

### 표준약관 대비 — 신구조문대비표 문법 (핵심 발견)
- "표준약관 vs 이 상품" diff는 **법조계 표준인 신구조문대비표**(좌=표준, 우=상품, 차이 밑줄) 포맷으로 — 심사위원·은행 현직자에게 익숙한 시각 문법이라 도메인 신뢰감을 그대로 얻는다 ([law.go.kr 대비표](https://www.law.go.kr/LSW/lsInfoP.do?lsiSeq=168084&viewCls=lsOldAndNew&chrClsCd=010102&lsId=003666))
- word-diff(문장 단위, 거터 없음 — Linear식 절제), 데스크톱 split / 모바일 unified 토글 ([GitHub split diffs](https://github.blog/2014-09-03-introducing-split-diffs/))

### 등급 배지 — 3중 코딩
- 색 + 문자 + 명도: 경고(적·"경고"·진함) / 주의(황갈·"주의"·중간) / 참고(회청·"참고"·연함) — 색각 접근성 ([Snyk 배지](https://docs.snyk.io/manage-risk/prioritize-issues-for-fixing/severity-levels) + [Rubrik colorblind](https://medium.com/rubrik-design/adapting-user-interfaces-for-colorblind-users-from-theory-to-practice-e020ce92d082))
- **등급 산정 기준 범례를 UI에 노출**(툴팁/시트): "경고 = 표준 편차 + 법 유형, 2계열 근거" — 심사 질문 "등급 기준이 뭐냐" 방어 (SonarQube 정의문 패턴 + [토스 — 당연함의 함정](https://toss.tech/article/thinking-user-perspective))

### 신뢰 신호
- AI 라벨: 결과 카드 단위 인라인 "AI 분석" pill — 전면 경고 블록 금지 ([Shape of AI — Disclosure](https://www.shapeof.ai/patterns/disclosure))
- 면책 고지 2단: 푸터 상주 1줄 + 경고 등급 카드에만 인라인 보강
- **쉬운 말 + 법정 용어 병기** — 토스식 과단순화는 금융권 심사에서 역효과(미수거래→외상 제재 사례, [DI Today](https://ditoday.com/미수거래는-외상-옵션투자는-홀짝-게임토스의/)). 일상어 요약과 원문 표현을 항상 페어로
- 출처 표기: 모노 서체 고정 포맷 "출처: 금감원 시행세칙 별표15 (2025.10.28 시행)" — 파인의 기관 명시 관행만 차용, 포털식 링크 나열은 배제

### 심사 UX 디테일
- 조항별 "검토됨" 체크 + 상단 진행률 (GitHub PR Viewed 패턴) — "N조 중 M조 확인" 시연 효과
- 아코디언 열림 시 조항 번호+배지 sticky 유지 ([NN/g Mobile Accordions](https://www.nngroup.com/articles/mobile-accordions/))
- 약관 원문 타이포: 16~18px, 행간 1.7+, 행폭 ~38자(모바일)

## 4. 안티패턴 (이 프로젝트에서 금지)

- 보라 그라데이션·장식 블롭·거대 히어로 카피 (스킬 공통 + 금융 도메인 부적합)
- 카드 안의 카드 중첩 — 근거는 카드가 아니라 "주석 행"으로
- 등급 색 외의 유채색 사용 — 색은 의미로만 (양 트랙 공통 원칙)
- 점수 게이미피케이션(신용점수형 원형 게이지) — 등급은 판정이 아닌 "가능성 표시"라는 표현 원칙과 충돌
- 전면 AI 경고 배너 — 신뢰를 오히려 깎음
