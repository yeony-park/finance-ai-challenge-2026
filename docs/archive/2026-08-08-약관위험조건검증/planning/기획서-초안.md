# 기획서 초안 v1 — 금융문서 위험조건 검증 (첨부1 양식 매핑)

> 2026-08-07 작성. 주제 검토서(8/2) + 검증 리서치(Stream 5~8) 반영.
> 각 항목은 `docs/competition/양식-분석.md`의 첨부1 필수 항목에 대응. hwpx 양식 전사 시 이 문서를 원고로 사용.
> ⚠️ 표시는 검증 리서치로 **수정·보강된 지점** — 검토서 원문을 그대로 옮기지 말 것.

## 1. 서비스 명칭 (팀 결정 필요)

후보: **약관레이더** / **폴리시가드** / **깨알약관** — 팀 회의에서 확정. 직관성 기준(양식 요구)으로 "무엇을 해주는지"가 이름에서 읽혀야 함.

## 2. 아이디어 핵심내용 요약 (개조식)

- 보험약관을 업로드하지 않아도, 보험사·상품명 선택 3탭으로 약관을 자동 로드해 전수 분석
- 수수료·해지·면책·원금손실 등 핵심 조건을 스키마 기반 전수 추출 — 질문해야 답하는 챗봇이 아닌 능동 스캔 도구
- 금감원 표준약관(시행세칙 별표15) 대비 diff로 소비자에게 불리하게 변형된 조항 탐지 ⚠️(기준선 출처: 공정위 아님 — Stream 5)
- 약관규제법 6~14조 무효 유형 분류 + 공정위 심결례·금감원 분쟁조정 사례 RAG로 "근거 n건" 제시
- 참고→주의→경고 단계형 등급. "독소조항" 단정 없이 근거 기반 가능성 표시 (CLAUDETTE "potentially unfair" 원칙)
- 모든 판정에 원문 페이지·문장 연결. 자체 레드팀 리포트 동봉

## 3. 문제 정의 및 제안 배경

**문제**: 보험약관·투자설명서의 정보 비대칭 → 불완전판매·분쟁. 소비자는 계약 전 알릴 의무, 면책, 해지 조건 같은 결정적 조항을 읽지 못한 채 서명.

**수요 근거 (정량)** ⚠️Stream 6:
- 시그널플래너 AI 상담 분기 5,000건 중 **36.6%가 "보장범위·청구 가능 여부"** 질문 ([헤럴드경제 2026-07-05](https://biz.heraldcorp.com/article/10798200)) — 약관 이해 수요 실재
- 금감원이 2025년 보험약관 소비자 중심 전면 개편(어려운 용어 교체, AI 챗봇 보조) 추진 — **규제기관도 인정한 현안**. 단 이는 공급자 측 표시 개선이며, 이미 체결된 구계약 약관과 소비자 측 검증 도구는 여전히 공백

**타깃 고객·채널 (양식 3번 필수 — 구체 명시)**:
- 주 타깃: **보험 가입 전 검토 단계의 금융 초보자(사회초년생) + 보유 계약을 재점검하려는 시니어**
- 채널: **모바일 웹**(설치 없는 URL 접근 — 심사 요건과 일치). 시니어를 위한 쉬운 말 변환·큰 글씨 모드
- 선정 이유: 공시실에서 약관을 찾는 것 자체가 시니어·초보자에게 최대 장벽(Stream 7 — 공시실 검색이 사실상 표준 경로이나 정식 상품명 매칭이 어려움) → 자동 로드가 이 마찰을 정조준

## 4. 서비스 컨셉 및 차별성

**컨셉**: 질문에 답하는 챗봇이 아니라, 문서 전체를 정해진 필드로 전수 추출·자동 검사하는 **검증 레이어**. 흐름: 상품 선택(또는 업로드) → OCR·구조 인식 → 필드 추출 → 위험조항 분류 → 불리 조항 판별·등급화 → 불일치 탐지 → 비교표 → 원문 연결.

**차별성 서술 원칙** ⚠️Stream 6 — "국내 유일" 류 표현 금지(또박·카카오페이 보험진단·미국 도구가 반례로 제시될 수 있음). 대신 **교집합의 구체성**으로:

> "금융약관 특화 × 조항 단위 전수 검증 × 법적 근거(약관규제법 유형+심결례) 제시"를 모두 갖춘 서비스는 부재. 각 축의 인접 서비스: 또박(일반 계약서 독소조항, 금융 특화 아님) · 카카오페이 보험진단(약관 학습 챗봇, 조항 인용 없음) · 은행연합회×업스테이지(기관 내부용) · 미국 CoverageCheck류(한국 법제 아님)

**기존 금융 앱 대비 비교표 (축을 나눠 정면 비교)** ⚠️Stream 7:

| 축 | 카카오페이 보험진단 | 보닥·시그널플래너 등 | 본 서비스 |
|---|---|---|---|
| 연동 편의성 | ◎ (마이데이터 제로 입력) | ○ | △ → **3탭 자동 로드로 보완** |
| 약관 조항 근거 제시 | ✗ (학습 재료일 뿐, 인용 UX 없음) | ✗ | **◎ 조항 원문+출처 연결** |
| 중립성 | ✗ (진단=판매 주체 그룹, GA·자회사 손보) | ✗ (설계사 연결 수익) | **◎ 판매 없음, 분석만** |
| 구계약(판매중지 상품) 약관 | ✗ | ✗ | **◎ 공시실 판매중지 상품 포함** |
| 불리 조항 판별·등급 | ✗ | ✗ | **◎ 법 유형+심결례 근거** |

**"대형 플랫폼이 따라 하면?" 방어 논리**: 판매 채널(카카오페이·GA 앱)은 자사 유통 상품의 불리조항을 표시할 유인이 구조적으로 없음. 마이데이터에는 약관 원문이 없어(API 규격 확인, Stream 7) 이 영역에선 플랫폼의 연동 우위가 이전되지 않음.

**"왜 아무도 안 했나" 선제 답변** ⚠️Stream 6: (a) 소비자 지불의사 낮음(DoNotPay 실패·FTC 제재, InsureScan 건당 2,900원) → 공모전 MVP는 무관, B2B 확장으로 수익화, (b) 오답 시 법적 리스크 → 근거 기반 등급 표현+신뢰 스파인으로 통제, (c) 플랫폼 흡수 우려 → 중립성이 구조적 해자.

## 5. 활용 데이터 및 생성형 AI 모델 적용 방안

**데이터 (전부 검증 완료, Stream 5·8)**:

| 데이터 | 용도 | 검증 상태 |
|---|---|---|
| AI Hub 580 「법률/규정 텍스트 분석 데이터」 | 불리조항 분류기 학습 | 약관 1만+건·43개 분야 유·불리/위법성 라벨 확인. **보험·카드·은행 약관 포함**. 내국인 승인제 — 즉시 신청 필요. 학습·서비스 활용은 출처 표기 조건부 허용 ⚠️펀드 약관 미확인 → 보험 단일 영역 근거 |
| 금감원 시행세칙 **별표15 표준약관** | diff 기준선 | law.go.kr에서 HWP/PDF 무료, 연혁 추적 가능(구계약 버전 매칭) ⚠️검토서의 "공정위 표준약관" 서술은 오류 — 반드시 수정 |
| 공정위 결정문 (data.go.kr/15103301) | 심결례 RAG | 실존 확인, 2008년~ PDF — 파싱 파이프라인 필요 |
| 금감원 분쟁조정 사례 | 조항→실제 분쟁 연결 | fss.or.kr 통합검색 |
| 보험사 상품공시실 약관 | **분석(추론) 입력 전용** | 삼성화재 정적 PDF·robots Allow 확인. 법적 검토 완료(Stream 8): 수칙 준수 저위험. **학습에는 미사용**(TDM 회색지대 회피) |

**생성형 AI 역할 (양식 5번 필수)**:
1. LLM 필드 추출 — 비정형 약관에서 수수료·면책·해지 조건을 스키마로 구조화
2. 근거 연결형 RAG — 조항 ↔ 약관규제법 유형·심결례·분쟁조정 사례 매칭, "유사 사례 n건" 생성
3. 쉬운 말 변환 — 시니어·초보자 대상 조항 해설 생성
4. 판별은 AI Hub 라벨 학습 분류기 + 별표15 diff(문서 비교)가 담당 — **"모델의 감"이 아닌 검증 가능한 근거** 구조. LLM 출력은 신뢰 스파인(출처 강제·가드레일·HITL)을 통과

**법적 컴플라이언스** ⚠️Stream 8 (자유 항목과 중복 시 요약만): 공시자료 대상 + 대법원 2021도1533 기준 준수 수집(robots 준수·차단 우회 금지·저부하) + 조항 인용은 제28조 요건(분석 主/원문 從/출처 표시) + 원본 재배포 없음 + 학습은 AI Hub 라이선스 데이터 한정.

## 6. 기대 효과 및 확장 가능성

- **소비자**: 가입 전 불리 조항 인지 → 불완전판매 예방. 구계약 재점검(금감원 약관 개편이 커버하지 못하는 기존 계약)
- **공급자·시장**: 보험사 약관 품질 경쟁 유도, 분쟁·민원 비용 절감
- **확장 로드맵** ⚠️Stream 6 — 경쟁 밀도 관점에서 진짜 빈 영역: **펀드 투자설명서·ELS/DLS 상품설명서·여신(대출) 약정서** (증권사 AI는 시황 요약뿐, 투자설명서 조항 검증 소비자 서비스 부재 확인). 데이터 우위(라벨·표준약관)가 보험에 있어 MVP는 보험, 확장은 펀드·여신 순
- **B2B 확장**: 보험사 약관 제·개정 시 사전 자가 심사 도구(은행연합회×업스테이지 사례가 방증), 금융보안원·감독기관 연계 가능성

## 7. 자유 항목 (어필 포인트)

1. **자체 레드팀 리포트 동봉** — 이미 구현된 신뢰 스파인(인젝션 가드레일·출처 강제 RAG·HITL·레이트리밋)의 레드팀 실행 결과를 부록 제출. 주최(금융보안원) 성격 정합
2. **법적 검토 선행** — 크롤링·저작권·AI 학습 쟁점을 판례 기준으로 검토하고 수칙을 파이프라인에 내장(Stream 8). DoNotPay FTC 제재를 반면교사로 한 표현 원칙("가능성+근거", 법률 자문 아님 고지)
3. **정량 평가 지표** — 필드 추출 EM/F1, 불리조항 분류 F1, diff 탐지 P/R을 골드셋 기준으로 공개. "심사 방어 가능한 숫자"
4. **9/7~9/11 무중단 설계** — 외부 실시간 API 의존 없음(프리로드 코퍼스), fake 모드 폴백, 레이트리밋
