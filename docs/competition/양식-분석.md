| 5* | MVP 검증 방법 | **심사자가 URL에서 기능을 확인하는 절차** — 테스트 계정, 샘플 입력값, 예상 결과, 브라우저 제한, MVP 제한사항 |

## 양식에서 읽히는 심사 포인트

1. **생성형 AI(LLM) 활용이 사실상 필수** — 기획서 5번이 "생성형 AI 모델 적용 방안"을 필수 항목으로 못 박음. 순수 전통 ML만으로는 항목을 못 채움.
2. **타깃 고객 세그먼트 + 채널을 명시적으로 좁혀야 함** — "금융소비자 특성과 서비스 채널을 고려한 맞춤형" 주제 문구와 기획서 3번이 일치. 막연한 "모두를 위한" 서비스는 감점 구조.
3. **기존 금융 앱 대비 차별성**을 직접 서술해야 함 → 기존 서비스 지형 리서치가 필수 (스트림 3).
4. **심사자는 직접 URL에 접속해 테스트함** — 테스트 계정·샘플 입력값·예상 결과를 준비해야 하고, 온보딩 없는 즉시 체험 흐름(데모 모드)이 유리.
5. 기능명세서는 "실제 동작하는 것만" — 과장 없이 좁고 완성도 있는 MVP가 유리.
