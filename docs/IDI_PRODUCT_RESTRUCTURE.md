## 작성 목적

[팩트] 사용자가 원하는 서비스는 많은 정보를 한 화면에 펼치는 실사 대시보드가 아니다. 신규 시장 참여자가 국내에서 청약·판매되는 조각투자 상품을 쉽게 찾고, 발행사와 기초자산의 과거 기록을 확인한 뒤, 짧은 검토 의견을 읽는 서비스다. 기존 투자자는 다음 상품을 빠르게 검토하는 용도로도 쓴다. 출처는 2026-08-10 인뎁스 인터뷰다.

[제품 결정] 제품의 중심을 `상품 검색 → 핵심 조건 비교 → 상품 검토 요약 → 근거 확인` 순서로 다시 잡는다. 정보량은 줄이되 근거를 없애지 않고, 상세 화면 안에서 단계적으로 공개한다.

## 해결하려는 문제

[팩트] 신규 사용자는 STO(Security Token Offering) 제도화 움직임에 관심을 느끼더라도 어떤 상품이 있는지, 최소 투자금액과 예상 기간은 얼마인지, 배당이 있는지, 제시 가격이 합리적인지 판단하기 어렵다. 기존 투자자도 상품마다 흩어진 공시와 웹 문서를 직접 모아야 한다. 출처는 2026-08-10 인뎁스 인터뷰다.

[추론입니다] 이 사용자의 첫 과제는 정밀한 투자 모델링이 아니라 탐색 비용과 기초 검토 비용을 줄이는 일이다. 따라서 첫 화면에서는 분석 항목의 완전성보다 검색 의도와 핵심 조건의 빠른 확인이 우선이다.

## 핵심 사용자와 이용 목적

### 신규 시장 참여자

- 국내 조각투자 상품이 무엇인지 처음 탐색한다.
- 소액으로 새로운 자산군을 경험하려 한다.
- 전문 용어보다 최소 투자금액, 예상 기간, 배당, 회수 구조를 먼저 본다.
- 상품의 장점뿐 아니라 가장 큰 위험과 추가 확인사항을 짧게 알고 싶어 한다.

### 기존 투자자

- 다음 청약 상품을 빠르게 찾는다.
- 현재 보유·경험 상품과 유사한 상품의 조건을 비교한다.
- 발행사와 기초자산의 과거 성과를 확인한다.
- 상세 화면에서 원문과 계산 근거까지 내려가 검증한다.

## 최종 제품 정의

[제품 결정] DAKER는 국내에서 청약·판매되는 조각투자 상품을 수집하고, 자연어 검색과 구조화된 핵심 정보, 발행사·기초자산 트랙레코드, 근거 기반 AI 코멘트를 제공하는 상품 검토 서비스다.

이 서비스가 답해야 할 질문은 다음과 같다.

- 지금 청약할 수 있거나 곧 나올 상품은 무엇인가
- 최소 투자금액, 목표 운용기간, 배당 조건은 무엇인가
- 발행사는 이전 상품을 어떻게 운용하고 회수했는가
- 부동산 지역, 미술품 작가, 항공기 엔진의 기초자산 기록은 어떠한가
- 제시 가격과 회수 가정에는 어떤 근거와 불확실성이 있는가
- 장점, 위험, 추가 확인사항은 무엇인가

## 범위와 비범위

### 포함 범위

- 국내에서 청약 또는 판매되는 상품
- 부동산, 미술품, 항공기 엔진
- 모집 예정, 청약 중, 운용 중, 완료 상품
- 자연어 상품 검색
- 발행사 트랙레코드
- 자산별 가격·수익·회수 근거
- 상품 전체에 대한 `검토 상태`
- 근거를 종합한 AI 코멘트
- 어디에서 청약하는지 알 수 있는 플랫폼명

### 포함하지 않는 범위

- 개인별 투자성향을 반영한 적합성 판정
- 매수·매도 추천
- 청약·주문 중개
- 청약 페이지로 바로 이동하는 링크
- 사용자 비교 기능의 현 단계 구현
- 사용자의 외부 상품 등록 요청 기능
- 비공개 계약서·송장·내부 운용자료에 대한 추정
- 연환산 수익률 표시

[팩트] 사용자는 동일한 상품 해석을 모든 사용자에게 우선 제공하고, 검색과 검토에 집중하며, 중개로 오해될 직접 청약 링크는 두지 않기로 답했다. 비교 기능은 아직 만들지 말라고 명시했다. 출처는 2026-08-10 인뎁스 인터뷰다.

## 핵심 사용자 흐름

```text
랜딩
  ↓ 자연어 검색 또는 자산 분류 선택
검색 결과
  ↓ 핵심 조건과 한 문장 코멘트 확인
상품 상세
  ↓ 상품 검토 요약·트랙레코드·그래픽 확인
근거 상세
  ↓ 원문·기준일·계산식·충돌 자료 확인
사용자가 직접 판단
```

[제품 결정] 서비스는 판단을 대신하지 않는다. 사용자가 판단에 필요한 조건, 기록, 불확실성을 짧은 화면에서 이해하고 필요할 때 원문까지 검증하게 한다.

## 정보 구조

### 랜딩 페이지

첫 화면은 다음 요소만 우선 노출한다.

- 서비스가 무엇을 하는지 설명하는 짧은 문장
- 문장으로 입력하는 큰 검색창
- 부동산, 미술품, 항공기 엔진을 고르는 시각적 자산 분류
- 현재 청약 가능 상품과 모집 예정 상품으로 바로 가는 진입점

검색 예시는 실제 검색 가능한 의도를 보여준다.

- `서울에 있는 최소 투자금액이 낮은 부동산 상품`
- `배당이 있고 예상 기간이 짧은 운용 중 상품`
- `최근 경매 기록이 있는 작가의 미술품 상품`
- `잔여 수명과 임대수익을 확인할 수 있는 항공기 엔진 상품`

### 검색 결과

모든 생애주기 상태를 결과에 포함한다. 사용자는 상태 필터로 모집 예정, 청약 중, 운용 중, 완료를 구분한다.

기본 정렬은 신규 순이다. 신규 기준일은 다음 날짜 중 가장 빠른 확인 가능 날짜로 정의한다.

- 플랫폼 등록일
- 모집 공고일
- 청약 시작일

[제품 결정] 셋 중 일부 날짜가 없으면 확인 가능한 날짜만 사용한다. 모든 날짜가 없으면 신규 순 계산에서 제외하고 `-`로 표시한다. 출처는 2026-08-10 인뎁스 인터뷰다.

결과 카드에는 다음 정보만 노출한다.

- 상품명과 자산 분류
- 지역 또는 핵심 기초자산 식별 정보
- 최소 투자금액
- 목표 운용기간
- 배당 여부와 제시 배당률
- 현재 생애주기 상태
- 검토 상태 : `양호`, `주의`, `-`
- AI 한 문장 코멘트
- 청약 플랫폼명

카드에서 제외하고 상세에만 두는 항목은 다음과 같다.

- 세부 가격 검증
- 유사 거래 목록
- 근거별 신뢰도와 출처 충돌
- 계산식
- 상세 수익·회수 기록
- 검토 상태의 항목별 산정 근거

### 상품 상세

상세 화면의 첫 구역은 `상품 검토 요약`이다.

- 현재 상품 조건 요약
- 장점
- 위험
- 추가 확인사항
- AI 코멘트 3∼4문장

`3∼4문장`은 2026-08-10 사용자 인터뷰에서 정한 상세 코멘트 길이다.

그 아래에는 다음 순서로 정보를 둔다.

- 핵심 조건
- 예상값과 실제값
- 회수·유동화 구조
- 자산별 가격 검토
- 발행사 트랙레코드
- 자산별 그래픽
- 검토 상태 세부 근거
- 출처, 확인일, 갱신 이력

자료가 없으면 빈칸이나 임의 추정값 대신 `-`를 표시한다. 상세에서는 `공개 자료에서 확인되지 않음`이라고 설명한다.

## 자연어 검색

[제품 결정] 사용자는 필터 문법을 배울 필요 없이 문장으로 질문한다. AI는 문장에서 구조화된 검색 조건을 추출한다.

우선 해석할 항목은 다음과 같다.

- 자산 분류
- 부동산 지역
- 최소 투자금액 범위
- 목표 운용기간
- 배당 여부와 배당률
- 상품 상태
- 발행사
- 작가 또는 기초자산명
- 검토 상태
- 등록·공고·청약 시점

AI가 문장을 확실히 해석하지 못하면 임의 조건을 적용하지 않는다. 인식한 조건을 검색창 아래에 태그로 보여주고, 나머지는 일반 키워드 검색으로 처리한다.

검색 결과가 없으면 `등록 상품 없음`을 표시한다. 현 단계에서는 외부 상품 등록 요청 기능을 제공하지 않는다.

## 상품 생애주기와 예상·실제 정보

### 모집 예정과 청약 중

- 발행사가 제시한 목표 운용기간을 표시한다.
- 예상 배당과 회수 계획을 표시한다.
- 실제값으로 오해되지 않도록 `예상`을 붙인다.

### 운용 중

- 발행사가 제시한 예상값을 유지한다.
- 실제 배당이나 운용 실적이 발생했다면 실제값을 우선 표시한다.
- 예상값은 별도 항목으로 남겨 둘을 비교하게 한다.

### 완료

- 실제 운용기간, 매각가격, 총수익을 표시한다.
- 회수가 목표일보다 늦어도 완료로 분류한다.
- 지연 완료 여부는 별도 상태로 표시한다.
- 연환산 수익률은 표시하지 않는다.
- 총수익 옆에 실제 보유·운용기간을 함께 표시한다.

[제품 결정] `완료`는 회수 여부를 뜻하고, `지연`은 일정 준수 여부를 뜻한다. 두 상태를 합쳐 손실이나 실패로 해석하지 않는다.

## 공통 데이터 모델

모든 상품은 최소한 다음 필드를 공유한다.

| 구분 | 필드 |
|---|---|
| 식별 | 상품명, 자산 분류, 발행사, 서비스 브랜드·운영사, 청약 플랫폼 |
| 일정 | 등록일, 공고일, 청약 시작·종료일, 목표 운용기간, 실제 운용기간 |
| 투자 조건 | 최소 투자금액, 모집금액, 배당 여부, 예상 배당, 실제 배당 |
| 상태 | 모집 예정, 청약 중, 운용 중, 완료, 지연 완료 |
| 회수 | 예상 회수 방식, 실제 매각가격, 총수익 |
| 검토 | 검토 상태, 항목별 근거, AI 코멘트, 검증 대기 여부 |
| 출처 | 원문 URL, 문서명, 발행 주체, 기준일, 수집일, 근거 등급 |

발행사와 서비스 브랜드·운영사는 같은 필드에 합치지 않는다. 트랙레코드 집계의 기본 단위는 공시·투자설명서에 적힌 법적 발행사다.

## 자산별 검토 항목

### 부동산

- 소재지와 권역
- 취득가격, 모집가격, 감정평가액
- 임대수익과 공실 관련 정보
- 주변 유사 거래
- 예상 매각가와 실제 매각가
- 회수 구조와 목표 기간

[제품 결정] 완전히 같은 조건의 비교 사례만 기다리지 않는다. 우선 인근 유사 거래를 사용하되 거리, 시점, 면적, 용도 차이를 함께 표시한다.

### 미술품

- 작가 경력과 시장 기록
- 동일 작품의 공개 거래 기록
- 같은 작가의 유사 작품 거래 기록
- 낙찰 수, 유찰·낙찰 비율, 반복 거래 여부
- 취득가격, 모집가격, 감정가의 차이
- 작품 이력(Provenance)
- 예상 매각 근거와 실제 매각가격

[제품 결정] `신인 작가를 포장해 비싸게 판매하는가`라는 사용자 우려는 작가명이나 홍보 문구로 판단하지 않는다. 공개 경매 수량, 낙찰 결과, 반복 거래, 동일·유사 작품 가격 분포, 취득가격과 모집가격의 차이로 검토한다.

### 항공기 엔진

- 엔진 모델과 공개된 경우 일련번호
- 임대수익
- 목표 매각가와 잔존가치 근거
- 엔진 잔여 수명
- 정비 이력과 다음 정비 시점
- 임차인과 계약 구조
- 회수 가정

[제품 결정] 항공기 엔진은 검색 분류와 상품 목록에는 포함한다. 다만 공개 자료만으로 필수 근거를 안정적으로 확보할 수 있는지 검증하기 전까지 검토 상태는 `-`로 둔다. 확인 가능한 사실과 자료 부족만 표시한다.

## 발행사 트랙레코드

[제품 결정] 트랙레코드의 기본 집계 단위는 법적 발행사다. 서울옥션, 소유, 갤럭시아머니트리처럼 사용자가 인식하는 서비스·회사명은 별도로 표시하되, 서로 다른 법적 발행사의 실적을 자동으로 합치지 않는다.

공개된 관계가 확인되면 운영사·플랫폼의 관련 이력을 참고 정보로 보여줄 수 있다. 이 정보는 발행사 검토 상태 점수에 자동 합산하지 않는다.

발행사 상세에는 다음을 표시한다.

- 출시 상품 수
- 운용 중 상품 수
- 완료 상품 수
- 수익, 손실, 확인 불가 상품 수
- 목표 기간 안에 완료한 상품과 지연 완료 상품
- 실제 매각가격
- 상품별 총수익과 실제 운용기간
- 배당 지급 상품 수와 전체 확인 대상 수
- 예상 배당 대비 실제 배당
- 상품별 실제 배당 기록

[제품 결정] 완료 이력이 없다는 사실은 손실이 아니며 `주의` 사유도 아니다. 이 경우 트랙레코드 항목을 `-` 또는 `자료 부족`으로 표시한다.

서울옥션의 작가·작품 거래 기록은 발행사 운용 성과가 아니라 미술품 가격 검토 근거로 분류한다.

## 검토 상태

### 명칭과 의미

화면 명칭은 `투자 등급`이나 `상대 검토 상태`가 아니라 `검토 상태`로 고정한다.

- `양호` : 필수 근거가 있고, 명시된 중대 주의 조건이 없으며, 고정 기준을 충족함
- `주의` : 필수 근거가 있고, 중대 주의 조건이 있거나 고정 기준을 충족하지 못함
- `-` : 필수 가격·현금흐름·회수 근거 또는 유효 비교 사례가 부족해 판정하지 않음

[제품 결정] 이 상태는 카탈로그 내 순위나 개인 투자 적합성을 뜻하지 않는다. 상품 조건을 자산군별 고정 기준에 대입한 결과다.

### 산정 원칙

- 자산군마다 기준, 가중치, 필수 근거, 중대 주의 조건, 경계값을 버전으로 관리한다.
- 동일한 근거 버전에는 항상 동일한 결과가 나와야 한다.
- AI가 상품마다 가중치를 임의 변경하지 않는다.
- 누락 항목의 가중치를 남은 항목에 재분배하지 않는다.
- AI는 근거를 항목에 연결하고 설명문을 작성한다.
- 최종 상태 계산은 고정된 규칙 코드가 수행한다.
- 상세 화면에 기준 버전, 비교 범위, 가중치, 항목별 결과, 중대 주의 조건, 핵심 사유를 공개한다.

[제품 결정] AI는 초기 기준안을 제안할 수 있다. 공개된 기준 버전이 정해진 뒤에는 상품별 동적 가중치를 사용하지 않는다.

### 공개 전 조건

[제품 결정] 표본 검토, 과거 자료 적용, 민감도 검토, 법률·규제·권리 검토가 끝나기 전에는 공개 검토 상태를 활성화하지 않는다. 그전에는 `-`와 근거 요약만 표시한다.

구체적인 점수 경계와 최소 표본 수는 아직 확정하지 않았다. 임의 숫자를 넣지 않고 기준 설계 단계에서 별도로 정한다.

## AI 코멘트

### 역할

AI는 수집된 근거와 고정된 검토 결과를 종합해 사용자가 먼저 읽을 문장을 작성한다. 매수·매도나 적합성 결론을 내리지 않는다.

결과 카드에는 한 문장만 표시한다. 상세에는 3∼4문장으로 다음 내용을 담는다.

- 확인된 강점
- 확인된 위험
- 가장 큰 미확인 사항
- 검토 상태가 있다면 그 핵심 근거

`한 문장`과 `3∼4문장`은 2026-08-10 사용자 인터뷰에서 정한 노출 길이다.

### 생성과 갱신

- 같은 근거 버전에는 같은 검토 결과를 사용한다.
- 새 자료가 들어오면 파싱과 계산을 다시 수행한다.
- 검증을 통과한 새 근거 버전으로 코멘트를 다시 생성한다.
- 이전 코멘트와 변경 근거를 기록한다.

### 문장 규칙

코멘트 안에서도 정보 성격을 구분한다.

- `[확인된 사실]` : 원문에서 직접 확인한 내용
- `[발행사 주장]` : 발행사·운영사가 제시한 전망이나 목표
- `[계산]` : 공개값으로 재계산한 결과
- `[AI 해석]` : 위 근거를 종합한 해석

자료가 없으면 그럴듯한 설명을 만들지 않고 `공개 자료에서 확인되지 않음`이라고 적는다.

## 자료 수집과 검증

[제품 결정] 운영사에서 자료를 제출받는 방식이 아니라 플랫폼이 공개된 자료를 찾아 수집하고 파싱한다. 대상은 공식 웹페이지, 공시, 투자설명서, PDF, 감정평가서, 공개 경매 기록, 공개 정비자료다.

[팩트] 비공개 계약서, 송장, 내부 장부는 공개 웹 수집만으로 확인할 수 없다. 그런 자료의 존재나 내용을 추정하지 않는다.

### 출처 우선순위

최신 자료를 우선하되, 출처 등급을 먼저 적용한다.

```text
공식 공시·법정 문서
  ↓
공공기관·공식 거래 데이터
  ↓
발행사·운영사 공식 자료
  ↓
신뢰 가능한 제삼자 자료
```

같은 출처 등급에서는 최신 자료를 우선한다. 서로 다른 등급이나 원문끼리 값이 충돌하면 하나를 임의 선택하지 않고 충돌 사실과 각 원문을 함께 표시한다.

### 신규 자료 반영

- 새 자료는 발견 즉시 근거 저장소에 추가한다.
- 비핵심 문구 변경은 스키마 검증 뒤 반영한다.
- 금액, 기간, 상태, 발행사, 검토 상태에 영향을 주는 변경은 자동 검증을 거친다.
- 자동 검증에는 단위, 날짜, 원문 위치, 출처 등급, 기존 값 충돌, 이상값 확인을 포함한다.
- 검증을 통과하면 새 버전을 공개한다.
- 실패하면 기존 공개값을 유지하고 `검증 대기`를 표시한다.
- 이전값, 새 값, 변경일, 근거를 기록한다.
- 초기 운영에서는 검토 상태가 바뀐 사례를 표본으로 재검토한다.
- 최소한의 오류 제보 수단을 둔다.

[제품 결정] `자료가 바뀌었다`는 사실 자체는 `주의` 사유가 아니다. 상품 조건에 불리한 변화가 확인될 때만 해당 검토 항목에 반영한다.

- 출처 버전, 충돌, 검증 대기, 변경 이력을 저장한다.
- 누락값 표기를 `-`로 통일한다.

### 검색 중심 화면

- 랜딩의 자연어 검색과 자산 분류를 만든다.
- 검색 의도를 구조화된 조건으로 변환한다.
- 카드 정보량을 줄이고 한 문장 AI 코멘트를 넣는다.
- 모집 예정, 청약 중, 운용 중, 완료 필터를 제공한다.
- 기본 신규 순 정렬을 적용한다.

### 상세 검토

- `상품 검토 요약`을 상세 첫 구역에 둔다.
- 자산별 가격·수익·회수 근거를 시각화한다.
- 발행사 트랙레코드와 상품별 원자료를 연결한다.
- 예상값과 실제값을 분리한다.

### 검토 상태와 자동 갱신

- 자산군별 고정 기준과 필수 근거를 설계한다.
- 표본 적용, 민감도, 법률·규제·권리 검토를 거친다.
- 검증 전에는 상태를 `-`로 유지한다.
- 검증된 기준 버전만 공개한다.
- 신규 자료 검증과 변경 이력을 운영한다.

## 확정된 결정

- 검색과 검토가 핵심 기능이다.
- 자연어 문장 검색을 기본으로 한다.
- 국내에서 청약·판매되는 상품을 다룬다.
- 부동산, 미술품, 항공기 엔진을 포함한다.
- 모집 예정부터 완료까지 계속 노출한다.
- 결과 카드에는 핵심 조건과 한 문장 코멘트만 둔다.
- 상세에는 3∼4문장 코멘트, 트랙레코드, 그래픽, 근거를 둔다.
- 청약 플랫폼명만 표시하고 직접 링크는 두지 않는다.
- 개인화된 적합성 판정과 매수·매도 판정은 하지 않는다.
- 검토 상태는 `양호`, `주의`, `-`로 표시한다.
- 자료 부족만으로 `주의`를 주지 않는다.
- 발행사 트랙레코드는 법적 발행사 기준으로 집계한다.
- 완료 상품에는 실제 매각가격과 총수익, 실제 기간을 표시한다.
- 운용 중 상품도 표시한다.
- 연환산 수익률은 제외한다.
- 새 근거가 검증되면 코멘트와 검토 결과를 갱신한다.
- 비교 기능은 현 단계에서 만들지 않는다.

## 완료 기준

재구조화 구현은 다음 조건을 모두 확인해야 완료로 본다.

- 사용자가 자연어로 자산 분류, 지역, 최소 투자금액, 기간, 배당 조건을 검색할 수 있음
- 결과 카드만 보고 상품의 핵심 조건과 가장 큰 확인사항을 이해할 수 있음
- 모집 예정, 청약 중, 운용 중, 완료 상품을 구분해 찾을 수 있음
- 상세 첫 화면에서 상품 검토 요약을 읽을 수 있음
- 발행사와 서비스 브랜드·플랫폼이 분리되어 있음
- 완료 상품의 실제 매각가격, 총수익, 실제 기간을 확인할 수 있음
- 미술품의 동일·유사 작품 근거 수준을 구분할 수 있음
- 항공기 엔진은 공개 근거가 부족할 때 검토 상태를 만들지 않음
- 모든 AI 문장이 사용한 원문과 근거 버전으로 연결됨
- 자료 부족이 `주의`나 손실로 오인되지 않음
- 새 자료가 핵심값을 바꿀 때 검증 대기와 변경 이력이 남음
- 검토 상태 기준과 결과가 같은 근거 버전에서 재현됨
- 직접 청약 링크, 매수·매도 추천, 개인화 적합성 판정이 없음

완료 여부는 실제 구현과 검증 결과로 판정한다. 이 문서 작성만으로 완료된 것으로 보지 않는다.
