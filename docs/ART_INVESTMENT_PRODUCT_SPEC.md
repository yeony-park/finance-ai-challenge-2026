# 미술품 조각투자 청약 전 AI 분석 서비스 제품 명세

- 문서 상태: **CURRENT · CANONICAL**
- 정본 경로: `docs/ART_INVESTMENT_PRODUCT_SPEC.md`
- 분석 기준 버전: `art-mvp-v1.0`
- 적용 우선순위: 본 문서와 연결된 6개 정본 문서가 기존 다중 자산 문서보다 우선한다.
- 참고 구조도: [`reference/ART_INVESTMENT_SERVICE_MAP.png`](./reference/ART_INVESTMENT_SERVICE_MAP.png)

## 1. 서비스 정의

이 서비스는 미술품 조각투자 상품의 판매·청약 중개 서비스가 아니다. 공개 자료를 수집·구조화하고 공모가격, 작가 경매 기록, 회수 가능성, 법적 발행사와 서비스 플랫폼의 이력을 함께 분석하여 **청약 전에 판단할 근거와 네 단계 최종 판단**을 제공하는 금융 분석 서비스다.

고정 핵심 문구:

> 그림 조각투자,<br>
> 청약 전에 AI 판단부터 확인하세요.

고정 보조 문구:

> 공모가, 작가 경매 기록, 유사 작품 가격,<br>
> 발행사 청산 이력을 AI가 함께 분석합니다.

AI는 자료 목록만 넘기지 않는다. 확인된 사실 → 비교 기준 → 숫자의 의미 → 청약 판단에 미치는 영향을 쉬운 한국어로 설명한다. 모든 핵심 판단은 원문 근거와 연결한다.

## 2. 핵심 사용자

주 사용자는 미술품, 투자계약증권, 경매시장에 익숙하지 않은 개인 투자자다. 증권신고서·투자설명서·경매 기록·플랫폼 공시를 직접 읽고 결합하기 어렵지만, 다음 네 질문에는 빠르게 답을 얻고 싶어 한다.

1. 이 상품은 왜 이 가격인가?
2. 이 작가는 실제로 지속적으로 거래되는가?
3. 플랫폼이 제시한 기간 안에 작품을 팔기 쉬운가?
4. 발행사와 플랫폼은 과거 상품을 제대로 끝냈는가?

부 사용자는 여러 상품을 빠르게 비교하고 원문까지 검증하려는 경험 투자자다. 개인 자산·투자성향에 따른 추천은 두 사용자 모두에게 제공하지 않는다.

## 3. 사용자 문제

- 취득가, 감정가, 공모금액, 각종 비용이 서로 다른 문서에 흩어져 있다.
- 공개 비용으로 설명되지 않는 차액을 사용자가 직접 계산해야 한다.
- 작가 전체 거래와 현재 작품에 가까운 시리즈·재료·크기 거래가 혼용된다.
- 가격 상승이 최고가 한 건에 의존하는지, 거래량을 동반하는지 알기 어렵다.
- `매각 완료`, `청산 완료`, `기간 내 청산`, `지연 청산`, `미매각`이 혼용된다.
- 플랫폼 브랜드, 운영사, 법적 발행사, 관리·매각 주체가 혼용된다.
- 자료 부족이나 원문 충돌이 숨겨지거나, 반대로 AI가 판단 자체를 회피한다.

## 4. 제품 원칙

1. **미술품 단일 범위**: 부동산, 항공기 엔진, 가축, 음악 저작권은 화면·필터·문구·데모에서 제외한다.
2. **탐색과 실제 상품의 결합**: `/`는 홍보 전용 랜딩이 아니라 검색과 청약 예정·진행 상품을 함께 제공한다.
3. **판단 우선, 근거 점진 공개**: 상세 상단에 결론을 두고 긴 내용은 탭, 토글, Accordion, Drawer에 둔다.
4. **정량과 정성의 분리**: 계산은 순수 함수, 의미 해석과 설명은 검증된 AI 출력이 담당한다.
5. **결측은 0이 아님**: 취득가가 없으면 감정가로 대체하지 않는다. 비공개를 위험으로 반영한다.
6. **충돌 보존**: 원문 값 충돌 시 평균을 내거나 하나를 버리지 않고 양쪽 값·기준일을 보존한다.
7. **주체 분리**: 플랫폼·운영사·법적 발행사·관리 주체·매각 주체를 별도 필드로 관리한다.
8. **근거 추적**: 핵심 값, 계산, 판단 이유는 `Evidence` ID와 외부 원문으로 추적 가능해야 한다.
9. **데모 오인 방지**: 데모 fixture에는 가상 엔티티만 사용하고 `데모 데이터` 배지를 항상 표시한다. 기존 DB 실데이터에는 별도의 `기존 DB` 배지를 표시한다.
10. **비권유**: 매수·매도, 수익 보장, 개인화 추천으로 표현하지 않는다.

## 5. 포함 범위

- 미술품 조각투자 상품 탐색과 청약 예정·진행 우선 노출
- 자연어 상품 검색, 조건 칩, URL 기반 검색·필터·정렬·페이지 상태
- 상품 목록, 상품/작가/플랫폼 상세, 최대 3개 상품 비교, 분석 기준
- 모든 상품의 `해볼 만함`, `조건부 해볼 만함`, `주의`, `위험` 중 하나의 AI 최종 판단
- 작품 취득가·감정가·총 공모금액·비용 구성·미설명 차액 비교
- 동일·유사 작품 거래, 작가 출품·낙찰·유찰·가격·거래량 분석
- 목표 보유기간과 회수 가능성, 매각 주체·방법·비용 분석
- 플랫폼 및 발행사 과거 배당·매각·청산·지연·미매각·손실 이력
- 상품별 AI 질문답변과 상품 비교 설명
- 계산식, 출처, 기준일, 변경 이력, 원문 충돌 공개
- 차트를 렌더링할 충분한 4개 가상 데모 상품
- 로딩·빈 상태·비공개·충돌·AI 실패·404·이미지 없음 처리
- 1440/1024/768/390px 반응형과 키보드·스크린리더 접근성

## 6. 제외 범위

- 부동산, 항공기 엔진, 가축, 음악 저작권, 기타 자산군
- 로그인·회원가입·결제·직접 청약·매수·매도 실행
- 개인 자산·투자성향 기반 추천, 커뮤니티, 포트폴리오, 실시간 거래, 알림
- 관리자 CMS, 복잡한 미래가격 예측, 수익 보장, 운영 자료 삭제
- 유료벽·로그인 제한 자료를 확인한 것처럼 표시하는 행위
- 숨은 신뢰도 점수, 확률, 별점, 100점 점수, `판정 불가`·`판단 보류`

## 7. 기능 요구사항

### 7.1 공통 구조

- URL은 `/`, `/products`, `/products/[productId]`, `/artists`, `/artists/[artistId]`, `/platforms`, `/platforms/[platformId]`, `/compare`, `/methodology`를 사용한다.
- 헤더는 로고, 청약 상품, 작가, 플랫폼, 상품 비교(개수), 분석 기준을 제공한다.
- 모바일 헤더는 햄버거/Drawer로 전환하고 키보드·ESC·focus trap을 지원한다.
- 푸터는 서비스 설명, 데이터 기준일, 분석 기준과 출처 정책 링크, 고정 면책문구를 간결하게 표시한다.
- 모든 상세 페이지는 Breadcrumb를 제공하며 내부·외부 링크의 의미와 클릭 영역을 분리한다.

### 7.2 홈과 상품 탐색

- Hero 문구와 자연어 검색을 첫 화면에 둔다. 제출하면 `/products`로 이동한다.
- 빠른 진입은 `청약 예정`, `청약 중`, 네 판단 단계만 제공한다.
- 청약 예정·진행 상품, AI가 보는 네 축, 과거 청산 완료 상품, 서비스 원칙을 순서대로 표시한다.
- `ProductCard`에는 이미지, 상태·기간, 상품·작가·플랫폼, 최소 투자금, 공모금액, 판단, 결론, 근거 2개, 상세/비교 행동을 표시한다.

### 7.3 자연어 검색과 목록

- AI가 자연어를 명시된 구조 조건으로 변환하고 적용 조건을 제거 가능한 칩으로 표시한다.
- 불명확한 표현은 임의 필터로 만들지 않고 키워드로 유지한다.
- `AI_MODE=demo`에서도 정의된 예시 질의 변환이 실제로 동작한다.
- 검색·필터·정렬·페이지는 query parameter에 저장되어 새로고침, 뒤로가기, URL 공유 후 복원된다.
- 필터는 상태, 판단, 작가, 플랫폼, 최소 투자금, 공모가 차이율을 지원한다.
- 정렬은 마감 임박, 최근 등록, AI 판단, 공모가 차이, 작가 거래량, 플랫폼 지연률을 지원한다.

### 7.4 상품 상세

상단 상품 헤더와 `AI 청약 판단` 뒤에 다음 탭을 둔다. 현재 탭은 `?tab=`에 저장하고 모바일에서 가로 스크롤한다.

- `summary`: 최종 판단, 한 문장 결론, 이유 3개, 3~5문장 설명, 네 축 요약, AI 질문
- `price`: 취득가·감정가·공모금액·공개 비용·미설명 차액 및 4개 가격 그래픽
- `comparables`: 유사성 기준, 낙찰/유찰 산점도와 거래표
- `artist`: 5년 거래량·중위가·낙찰률·분포·편중, 경력 토글
- `exit`: 거래 빈도·유찰률·보유기간·비용·매각/청산 타임라인
- `platform`: 상태 분포, 목표/실제기간, 배당·매각·청산 이력
- `evidence`: 기본 접힌 근거, 계산식, 비교 표본, 변경 이력, 충돌 자료

### 7.5 작가·플랫폼·비교·분석 기준

- 작가 목록은 이름 검색과 거래량·낙찰률·최근 거래일·관련 상품 수 정렬을 제공한다.
- 작가 상세는 시장 분석, 기간별 거래, 시리즈/재료/크기, 재거래, 경력, 관련 상품, 출처를 제공한다.
- 플랫폼 목록·상세는 브랜드/운영사/발행사를 분리하고 상태·기간·배당·지연·손실 이력을 제공한다.
- 비교는 URL의 `ids`로 2~3개를 저장하며 상품별 핵심 수치와 AI 상대 비교를 제공한다. `최고`, `무조건`, `수익 보장` 표현은 금지한다.
- 분석 기준은 네 축, 계산식, 기간·유사작·트랙레코드 집계, 네 판단 의미, 결측/충돌, 출처/갱신, 버전, 한계와 면책을 공개한다.

### 7.6 AI 질문답변

답변은 `직접 답변 → 근거 수치 → 의미 → 청약 판단 영향 → 근거 링크` 순서를 따른다. 저장 분석·근거를 우선 사용하고 최신성이 필요한 경우에만 서버 검색을 보강한다. 비공개 자료도 “직접 확인하라”로 끝내지 않고 어떤 검증이 불가능하며 어떤 위험에 반영됐는지 설명한다.

## 8. 계산과 표시 규칙

```text
공모가 차이 = 총 공모금액 - 작품 취득가
공모가 차이율 = (총 공모금액 - 작품 취득가) / 작품 취득가 × 100
설명되지 않는 차액 = 총 공모금액 - 작품 취득가 - 공개된 비용 합계
```

- 취득가가 `null`이면 위 취득가 기반 계산도 `null`이다.
- 낙찰률·유찰률의 분모와 제외 상태(`withdrawn`, `unknown`)를 분석 기준에 공개한다.
- 원화는 억·만원 읽기 형식과 원 단위 원값을 함께 관리하고 비율은 기본 소수점 한 자리로 표시한다.
- 표본이 없으면 빈 차트를 그리지 않고 텍스트 상태와 필요한 데이터 종류를 제공한다.
- 면적당 가격은 유사작 보조지표일 뿐 작품가치를 단정하는 기준으로 쓰지 않는다.

## 9. AI 판단 체계

### 고정 출력

| 값 | 화면 라벨 | 의미 |
|---|---|---|
| `worth_considering` | 해볼 만함 | 가격 설명력, 비교 거래, 시장성, 청산 이력이 전반적으로 양호하고 중대한 위험이 없음 |
| `conditional` | 조건부 해볼 만함 | 긍정 근거가 더 강하지만 표본·변동성·짧은 이력·일부 지연 등 약점이 있음 |
| `caution` | 주의 | 가격 또는 회수 구조 한 축에 의미 있는 위험이 있음 |
| `danger` | 위험 | 핵심 비공개·큰 미설명 차액·거래 부재·반복 지연 등 중대 위험이 하나 이상이거나 복합 위험이 있음 |

AI는 위험 개수 합산이나 단순 평균점수만으로 결론내리지 않는다. 순수 함수가 만든 정량 지표, 비교 가능성, 자료의 결측·충돌, 정성 위험을 함께 본다. 자료 부족이어도 네 단계 중 하나를 내리되 부족 자체를 위험에 반영하고 없는 숫자를 만들지 않는다.

### 금지 출력

`판정 불가`, `판단 보류`, `분석 신뢰도`, 신뢰도 점수·확률·별점·100점 점수, 매수·매도 추천은 사용자 화면에 표시하지 않는다.

### 코멘트 품질

각 핵심 분석은 실제 수치, 기간 비교, 유사작 비교, 전체/동일 시리즈 비교, 예상/실제 비교, 공개 비용/미설명 차액, 거래량/유찰률 등에서 최소 2개를 함께 사용한다. “추가 확인이 필요합니다”, “투자자가 직접 판단해야 합니다” 같은 책임 회피 문장으로 끝내지 않는다.

## 10. 비기능 요구사항

### 보안·프라이버시

- `OPENAI_API_KEY`는 Route Handler 등 서버 경계에서만 읽고 `NEXT_PUBLIC_` 변수·클라이언트 props·로그에 넣지 않는다.
- `OPENAI_MODEL`은 단일 서버 설정에서 읽고 여러 파일에 모델명을 하드코딩하지 않는다.
- 외부 URL은 허용 프로토콜, timeout, redirect, 크기와 schema를 검증하며 외부 링크에 `target="_blank" rel="noopener noreferrer"`를 적용한다.

### 성능·신뢰성

- 페이지 로드마다 전체 웹을 조사하지 않고 저장된 최신 분석을 렌더링한다.
- AI 실패는 저장 분석 → 규칙 기반 데모 분석 → 오류·재시도 순으로 degrade한다.
- Skeleton의 크기를 최종 레이아웃과 맞춰 CLS를 줄이고, 차트는 모바일에서 잘리지 않게 한다.
- 잘못된 ID는 Next.js `notFound()`/`not-found.tsx`, API는 구조화된 404를 반환한다.

### 접근성·반응형

- 1440, 1024, 768, 390px를 검증한다. 모바일은 단일열, 가로 스크롤 탭/표, 필터 Drawer, 최소 44px 터치 영역을 사용한다.
- 모든 이미지에 alt, 차트에 텍스트 요약, 상태에 텍스트+아이콘, interactive UI에 focus 표시와 적절한 ARIA를 제공한다.

### 유지보수성

- Next.js 16 App Router, React 19, TypeScript strict를 유지한다.
- 페이지는 기본적으로 Server Component로 데이터 조회하고 상호작용이 필요한 검색칩, Drawer, 탭, 비교함, 질문 패널만 작은 Client Component로 분리한다.
- fixture를 컴포넌트에서 직접 import하지 않고 Repository를 거친다.
- 계산은 `lib/domain/calculations` 같은 순수 함수 계층에 두고 테스트한다.

## 11. 데모 승인 기준

가상 `DEMO 작가`, `DEMO 작품`, `DEMO 플랫폼`만 사용한다. 최소 네 상품은 각각 `해볼 만함`, `조건부 해볼 만함`, `주의`, `위험`을 나타내며 요구된 취득가·공모금액·비용·미설명 차액·거래량·낙찰률·동일 시리즈·청산 이력을 정확히 반영한다. 각 작가는 5년 경매행, 각 플랫폼은 과거 상품 상태·목표/실제기간·배당·매각·청산 데이터를 포함한다.
